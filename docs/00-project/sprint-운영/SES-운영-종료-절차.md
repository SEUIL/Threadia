# SES 운영 종료 절차

## 목적·범위

본 문서는 프로젝트 완료와 권한을 가진 운영자의 명시적 종료 확인 이후 수행하는 SES sandbox 비밀번호 재설정 검증 운영의 종료 절차와 기록 양식을 정의한다. 현재 운영과 E2E 검증은 진행 중이므로, 본 문서는 정리 완료 증거나 실제 삭제 기록이 아니다.

대상은 sandbox에서 수행한 비밀번호 재설정 이메일 검증에 한정한다. production 접근, production 계정, production 수신자, production 설정의 조회·변경·삭제는 범위에 포함하지 않는다.

## 실행일·사전 조건

- [ ] 프로젝트가 완료되었고 권한을 가진 운영자가 운영 종료를 명시적으로 확인했는지 기록한다.
- [ ] 비밀번호 재설정 E2E 검증이 종료되었고 추가 발송이 없음을 확인한다.
- [ ] 대상이 sandbox 전용 리소스인지 별칭과 환경 구분값으로 확인한다. 계정 ID, 주소, ARN, credential은 기록하지 않는다.
- [ ] 종료 전 필요한 비밀값 없는 운영 증적의 보관 위치와 보존 책임자를 확인한다.

> 실제 삭제는 프로젝트 완료와 권한을 가진 운영자의 운영 종료 확인이 모두 충족된 뒤에만 수행한다.

## 순서형 제거 체크리스트

1. [ ] 발송·재설정 작업을 중지하고, 진행 중인 sandbox 비밀번호 재설정 요청이 없는지 확인한다.
2. [ ] 임시 IAM SMTP 사용자 1건의 별칭과 상태를 기록한 뒤 삭제한다. SMTP access key 1건은 키 식별 별칭과 삭제 상태만 기록한다.
3. [ ] MAIL·재설정 runtime SecureString 6건을 별칭으로 대조한 뒤 제거한다. 값, token, credential, parameter 경로 원문은 기록하지 않는다.
4. [ ] public host의 MAIL runtime 값은 항목 수와 상태만 기록한 뒤 제거한다. host 주소와 환경 변수 원문은 기록하지 않는다.
5. [ ] public backend를 재생성하고 health 확인을 수행한다. MAIL 설정 없이 정상 기동되는지와 비밀번호 재설정 발송이 차단되는지를 상태로 기록한다.
6. [ ] sandbox 수신자 identity를 별칭과 건수로 대조한 뒤 제거한다. 실제 수신자 이메일 주소는 기록하지 않는다.
7. [ ] 삭제 결과, health 확인 결과, 실행 시각, 승인자 역할을 비밀값 없는 closure evidence로 보관한다.

## 검증 체크리스트

| 검증 항목 | 기록할 식별 정보 | 기대 상태 | 결과 |
|---|---|---|---|
| 임시 IAM SMTP 사용자 | 사용자 별칭 1건 | 삭제됨 | [ ] |
| SMTP access key | 키 식별 별칭 1건 | 삭제됨 | [ ] |
| MAIL·재설정 SecureString | 항목 별칭 6건, 수량 6 | 삭제됨 | [ ] |
| public host MAIL runtime 값 | 항목 별칭, 수량 | 제거됨 | [ ] |
| public backend 재생성 | 배포 별칭, health 결과 | 정상, 메일 발송 차단 | [ ] |
| sandbox 수신자 identity | identity 별칭, 수량 | 삭제됨 | [ ] |
| closure evidence | 증적 위치 별칭 | 보관됨, 비밀값 없음 | [ ] |

검증 기록에는 실제 이메일 수신자, token, credential, host 주소, account ID, ARN을 쓰지 않는다. 실패 시 원문 값 대신 항목 별칭, 실패 단계, 오류 분류, 후속 조치만 기록한다.

## 롤백·incident 메모

삭제 전 단계에서 운영 종료 확인이 없거나 범위가 sandbox인지 확인할 수 없으면 작업을 중지하고 권한자에게 보고한다. 삭제 후 비밀번호 재설정 검증 재개가 필요하면 새 sandbox 리소스를 별도 승인 절차에 따라 생성한다. 삭제한 credential, SecureString 값, 수신자 주소를 복원하거나 기록하지 않는다.
