`docs/` 아래에서 문서를 작성하거나 수정할 때는 [문서-작성-규칙.md](./00-project/문서-작성-규칙.md)를 따른다.

## Docs 폴더 구조

Threadia 프로젝트 문서 보관 위치다. 기획주간에는 문서 제약을 강하게 두지 않고, 아래 폴더 기준으로 정리한다.

| Folder | Purpose |
|---|---|
| `00-project/` | 프로젝트 개요, README 초안, 팀 운영 메모 |
| `01-planning/` | 기획주간 작업물, 일정, 회의 전 준비 자료 |
| `02-requirements/` | 사용자 시나리오, 기능 분해표, 요구사항 |
| `03-design/` | 화면 정의서, 화면 흐름, UI/UX 참고 |
| `04-api/` | API 목록, API 명세 초안 |
| `05-architecture/` | ERD, 권한 정책, AWS architecture, 기술 결정 |
| `06-meetings/` | 회의록, 결정사항, 액션 아이템 |
| `07-decisions/` | 확정된 결정사항, 보류 기능, 변경 이력 |
| `assets/` | 문서에 첨부할 이미지, 다이어그램, 캡처 |

## Docs 운영 기준

- 기획주간에는 문서 형식을 강제하지 않는다.
- 확정된 내용과 초안은 파일명 또는 문서 상단에 구분한다.
- repo 이름, 배포 설정, 권한 정책처럼 팀 합의가 필요한 값은 임의로 확정하지 않는다.
- 개발주간부터는 API, ERD, branch, PR, issue 규칙을 별도 문서로 분리한다.

## 금지사항

- `01-planning/`의 기존 기획 자료는 읽기만 한다.
- 상태가 `확정`인 문서는 사용자 확인 없이 수정하지 않는다.
- `08-members/member-XX/` 문서는 해당 멤버 본인의 요청 없이 수정하지 않는다.
- 규칙에 없는 폴더를 임의로 만들지 않는다.
- 문서 내용 없이 폴더만 생성하지 않는다. 단, `.gitkeep`은 예외로 둔다.
- 한 문서에 여러 주제를 섞지 않는다.

## 작성 기준

- 새 문서는 정해진 `docs/` 폴더 구조에 저장한다.
- 파일명, 메타정보, 문체는 [문서-작성-규칙.md](./00-project/문서-작성-규칙.md)를 따른다.
- 기존 문서를 수정할 때는 필요한 최소 범위만 수정한다.
- 문서 생성 전 동일한 이름의 파일이 이미 존재하는지 확인한다.
- 확정 문서를 수정할 경우 `최종 수정` 날짜와 `버전` 갱신 필요 여부를 확인한다.
