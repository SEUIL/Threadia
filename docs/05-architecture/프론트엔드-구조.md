# 프론트엔드 구조

이 문서는 Threadia 프론트엔드의 폴더 구조, URL 라우팅, API 연동 방식을 정리한다. 백엔드 개발자가 CORS 설정, cookie 정책, API 계약을 맞출 때 참고한다.

---

## 1. 기술 스택

| 항목 | 선택 |
|---|---|
| 프레임워크 | Next.js 15 (App Router) |
| 언어 | TypeScript |
| 스타일 | Tailwind CSS |
| HTTP 클라이언트 | axios |
| 상태 관리 | Zustand |
| 폼 / 유효성 검사 | react-hook-form + zod |

## 4. API 연동 방식

### Base URL

```
개발: http://localhost:8080
운영: https://api.threadia.com
```

환경변수 `NEXT_PUBLIC_API_URL`로 관리한다.

### 인증 토큰 처리

| 토큰 | 저장 위치 | 설명 |
|---|---|---|
| access token | JS 메모리 (변수) | 30분 만료. `Authorization: Bearer <token>` 헤더로 전송 |
| refresh token | HttpOnly cookie | 14일 만료. 서버가 Set-Cookie로 내려줌 |

- access token은 페이지 새로고침 시 소멸한다. 소멸하면 axios interceptor가 자동으로 `POST /api/v1/auth/refresh`를 호출해 재발급한다.
- refresh token은 프론트에서 직접 읽거나 조작하지 않는다. cookie 전송은 axios `withCredentials: true`로 처리한다.

### CORS / Cookie 설정 (백엔드 필요 사항)

백엔드에서 아래 설정이 필요하다.

| 항목 | 값 |
|---|---|
| `Access-Control-Allow-Origin` | `http://localhost:3000` (개발), 운영 도메인 |
| `Access-Control-Allow-Credentials` | `true` |
| refresh token cookie `SameSite` | `Lax` |
| refresh token cookie `HttpOnly` | `true` |
| refresh token cookie `Secure` | HTTPS 환경에서만 `true` |

### axios interceptor 동작

1. 요청 전: `Authorization: Bearer <accessToken>` 헤더 자동 추가.
2. 응답 401 수신 시: `POST /api/v1/auth/refresh` 호출 → 새 access token 저장 → 원래 요청 재시도.
3. refresh도 실패하면: access token 초기화 → `/login`으로 redirect.

구현 위치: [`frontend/lib/axios.ts`](../../frontend/lib/axios.ts)

## 5. URL 파라미터 네이밍 규칙

백엔드 경로 변수와 프론트 URL 파라미터 이름을 통일한다.

| 프론트 URL 파라미터 | 백엔드 경로 변수 | 설명 |
|---|---|---|
| `companyId` | `{companyId}` | 회사 ID |
| `projectId` | `{projectId}` | 프로젝트 ID |
| `roomId` | `{roomId}` | DM 방 ID |
| `docId` | `{documentId}` | 문서 ID |
| `threadId` | `{threadId}` | 쓰레드 ID |

> `docId` ↔ `documentId` 차이가 있다. 프론트 URL은 짧게 `docId`를 쓰고, API 호출 시에는 `documentId`로 변환해서 전달한다.

## 6. 개발 서버 실행

```bash
cd frontend
npm run dev
# http://localhost:3000
```

환경변수는 `frontend/.env.local` 파일에 설정한다. `.env.example`을 참고한다.

```env
NEXT_PUBLIC_API_URL=http://localhost:8080
```
