# 백엔드 구조

이 문서는 Threadia 백엔드의 폴더 구조, Spring Boot 실행 구조, DB 연결 방식, 테스트 기준을 정리한다.  
프론트엔드 개발자가 API base URL, 인증 API 흐름, CORS·cookie 정책을 맞출 때 이 문서를 기준으로 삼는다.

## 2. 폴더 구조 및 역할

현재 Sprint 1.1.1~1.1.2 기준 백엔드 구조는 skeleton과 DB 연결 확인까지만 포함한다. Auth API 구현 전이므로 controller, service, repository, entity 계층은 아직 생성하지 않았다.

```text
backend/
├── build.gradle                         # Spring Boot, dependency, Java 17 toolchain
├── settings.gradle                      # Gradle project 이름
├── gradlew                              # macOS/Linux Gradle wrapper
├── gradlew.bat                          # Windows Gradle wrapper
├── src/
│   ├── main/
│   │   ├── java/
│   │   │   └── com/threadia/backend/
│   │   │       └── BackendApplication.java      # Spring Boot main entrypoint
│   │   └── resources/
│   │       └── application.properties           # application name, datasource 설정
│   └── test/
│       └── java/
│           └── com/threadia/backend/
│               ├── BackendApplicationTests.java # Spring context load 기본 테스트
│               └── MysqlConnectionTests.java   # MySQL 8.4 연결 검증 테스트
│
compose.mysql.yml                        # local MySQL 8.4 test DB 실행 구성
```

### 현재 포함된 dependency

```gradle
implementation 'org.springframework.boot:spring-boot-starter-actuator'
implementation 'org.springframework.boot:spring-boot-starter-jdbc'
implementation 'org.springframework.boot:spring-boot-starter-validation'
implementation 'org.springframework.boot:spring-boot-starter-web'
runtimeOnly 'com.mysql:mysql-connector-j'
testImplementation 'org.springframework.boot:spring-boot-starter-test'
```

## 3. Spring Boot application 구조

`BackendApplication`은 Threadia 백엔드의 main entrypoint다.

```text
com.threadia.backend.BackendApplication
```

현재 기본 package는 `com.threadia.backend`다. Spring Boot의 component scan은 이 package 아래를 기준으로 동작한다. 후속 Auth 구현 시 controller, service, repository, entity, config package는 이 하위에 생성한다.

예상 확장 구조는 다음과 같다.

```text
com.threadia.backend
├── auth/                 # login, logout, refresh, OAuth, password reset
├── user/                 # user 조회, me 응답, 사용자 상태
├── common/               # 공통 응답, error, exception handler
├── config/               # security, cors, cookie, jackson, timezone 설정
└── BackendApplication.java
```

> 위 구조는 구현 예정 기준이다. 실제 package는 Auth API 구현 PR에서 확정한다.

## 4. datasource / MySQL 연결 구조

백엔드는 `application.properties`에서 datasource를 설정한다.

```properties
spring.application.name=backend
spring.datasource.url=${THREADIA_DB_URL:jdbc:mysql://localhost:3307/threadia_test}
spring.datasource.username=${THREADIA_DB_USERNAME:threadia}
spring.datasource.password=${THREADIA_DB_PASSWORD:}
spring.datasource.hikari.initialization-fail-timeout=0
```

| 설정 | 의미 | 현재 기준 |
|---|---|---|
| `THREADIA_DB_URL` | JDBC URL | 없으면 local test DB 기본값 사용 |
| `THREADIA_DB_USERNAME` | DB 사용자 | 없으면 `threadia` 사용 |
| `THREADIA_DB_PASSWORD` | DB password | secret이므로 repository에 기록하지 않음 |
| `initialization-fail-timeout=0` | Hikari 초기화 동작 | 앱 시작만으로 DB 연결 성공을 단정하지 않음 |

DB name과 username의 기본값은 local test 편의를 위한 값이다. Password와 root password는 secret이므로 `.env` 또는 사용자 환경변수로만 주입한다.

## 5. MySQL 8.4 Docker 실행 구조

local test DB는 repository root의 `compose.mysql.yml`로 실행한다.

```yaml
services:
  mysql:
    image: mysql:8.4
    container_name: threadia-mysql84
    ports:
      - "3307:3306"
```

| 항목 | 값 | 설명 |
|---|---|---|
| Docker Compose project | `threadia` | repository 폴더명 기준으로 표시됨 |
| Service | `mysql` | compose service 이름 |
| Container | `threadia-mysql84` | 실제 container 이름 |
| Image | `mysql:8.4` | MySQL 8.4 고정 |
| Host port | `3307` | local host에서 접근하는 port |
| Container port | `3306` | MySQL 기본 port |

환경변수는 아래 기준으로 주입한다.

| Compose 변수 | 설명 | 기본값 |
|---|---|---|
| `THREADIA_DB_NAME` | 생성할 test DB 이름 | `threadia_test` |
| `THREADIA_DB_USERNAME` | 생성할 DB 사용자 | `threadia` |
| `THREADIA_DB_PASSWORD` | DB 사용자 password | 필수 |
| `THREADIA_DB_ROOT_PASSWORD` | root password | 필수 |

`THREADIA_DB_PASSWORD`, `THREADIA_DB_ROOT_PASSWORD`가 없으면 compose 실행이 실패하도록 구성했다. Secret 값을 repository에 commit하지 않기 위한 기준이다.

## 6. 테스트 구조

### 6.1 Spring context load 테스트

`BackendApplicationTests`는 Spring Boot application context가 정상 로드되는지 확인하는 기본 테스트다.

```text
backend/src/test/java/com/threadia/backend/BackendApplicationTests.java
```

이 테스트는 skeleton 생성 직후 backend가 최소한의 Spring context를 구성할 수 있는지 확인한다.

### 6.2 MySQL 연결 검증 테스트

`MysqlConnectionTests`는 Sprint 1.1.2의 `test DB 연결 성공` 기준을 검증한다.

```text
backend/src/test/java/com/threadia/backend/MysqlConnectionTests.java
```

테스트 내용은 다음과 같다.

| 검증 | 설명 |
|---|---|
| `JdbcTemplate` 주입 | Spring datasource가 구성됐는지 확인 |
| `SELECT 1` | DB에 실제 query를 실행할 수 있는지 확인 |
| `SELECT VERSION()` | 연결된 DB version 확인 |
| `8.4.x` 검증 | MySQL 8.4 container에 연결됐는지 확인 |

`MysqlConnectionTests`는 아래 조건이 있을 때만 실행된다.

```java
@EnabledIfEnvironmentVariable(named = "THREADIA_DB_PASSWORD", matches = ".+")
```

따라서 단순히 `./gradlew test`가 성공했다는 사실만으로 MySQL 연결 성공을 단정하지 않는다. DB 연결 확인 시에는 `.env` 또는 shell 환경변수로 `THREADIA_DB_PASSWORD`를 주입한 뒤 테스트가 skip되지 않았는지 확인한다.

## 7. API 구현 예정 구조

Threadia API는 `/api/v1/...` 경로를 기준으로 구현한다. Sprint 1에서 백엔드가 우선 구현할 범위는 Auth API다.

| Method | Endpoint | 설명 | 구현 Sprint |
|---|---|---|---|
| `POST` | `/api/v1/auth/signup` | 이메일 회원가입 | Sprint 1 |
| `POST` | `/api/v1/auth/login` | 이메일 로그인 | Sprint 1 |
| `POST` | `/api/v1/auth/logout` | 로그아웃, refresh token revoke | Sprint 1 |
| `POST` | `/api/v1/auth/refresh` | access token 재발급 | Sprint 1 |
| `GET` | `/api/v1/auth/me` | 현재 사용자 조회 | Sprint 1 |
| `GET` | `/oauth2/authorization/google` | Google OAuth 시작 | Sprint 1 |
| `GET` | `/api/v1/auth/oauth2/callback/google` | Google OAuth callback | Sprint 1 |
| `POST` | `/api/v1/auth/password-reset/request` | 비밀번호 재설정 요청 | Sprint 1 |
| `POST` | `/api/v1/auth/password-reset/confirm` | 비밀번호 재설정 확정 | Sprint 1 |

Sprint 2 이후의 project, issue, document, chat, thread, notification API는 현재 백엔드 skeleton 범위에 포함하지 않는다.

## 8. 인증/Auth 구현 시 백엔드 기준

Sprint 1 Auth 구현은 canonical 문서의 hardening 기준을 따른다.

| 항목 | 기준 |
|---|---|
| Email normalization | signup, login, password reset, OAuth, invitation lookup에서 `trim + lowercase` |
| OAuth account link | 이메일만 같다는 이유로 blind auto-link 금지 |
| Refresh token | DB 저장, logout 시 revoke, password reset confirm 시 전체 revoke |
| Active user check | login, OAuth callback, refresh, `/auth/me`는 `users.status = ACTIVE` 기준 |
| Token time | 서버 생성·만료 시각은 UTC 저장, API 응답은 ISO-8601 UTC `Z` |
| Refresh cookie | `HttpOnly`, `SameSite=Lax`, 운영 환경 `Secure=true` |

프론트엔드는 access token을 JS memory에 저장하고 refresh token은 HttpOnly cookie로 받는 구조를 기준으로 한다. 따라서 백엔드는 CORS와 cookie 정책을 프론트엔드 구조 문서와 맞춰야 한다.

## 9. 환경변수

local backend 실행과 MySQL 연결 확인에는 아래 환경변수를 사용한다.

| 변수명 | 예시 값 | 설명 |
|---|---|---|

| `THREADIA_DB_USERNAME` | `threadia` | local test DB 사용자 |
| `THREADIA_DB_PASSWORD` | `<local-db-password>` | local test DB password |
| `THREADIA_DB_ROOT_PASSWORD` | `<local-root-password>` | local MySQL root password |

`.env` 파일은 repository root에 둘 수 있지만 git에 commit하지 않는다. 실제 password, root password, token, OAuth client secret은 문서와 PR 본문에도 노출하지 않는다.

## 10. 개발 서버 실행

### 10.1 MySQL 8.4 실행

```bash
docker compose --env-file .env -f compose.mysql.yml up -d mysql
```

MySQL 자체 연결 확인은 다음 명령으로 수행한다.

```bash
set -a
source .env
set +a

docker exec -e MYSQL_PWD="$THREADIA_DB_PASSWORD" threadia-mysql84 \
  mysql -u"$THREADIA_DB_USERNAME" "$THREADIA_DB_NAME" \
  -e "SELECT VERSION(); SELECT 1;"
```

성공 기준은 `SELECT VERSION()` 결과가 `8.4.x`이고, `SELECT 1` 결과가 `1`인 것이다.

### 10.2 Spring Boot 테스트

```bash
cd backend

set -a
source ../.env
set +a

./gradlew test --rerun-tasks
```

성공 기준은 다음과 같다.

```text
MysqlConnectionTests가 skip되지 않고 실행됨
JdbcTemplate으로 SELECT 1 성공
JdbcTemplate으로 SELECT VERSION() 성공
VERSION() 결과가 8.4.x
BUILD SUCCESSFUL
```

### 10.3 Spring Boot 실행

```bash
cd backend
./gradlew bootRun
```

기본 실행 port는 `8080`이다. Actuator health endpoint는 다음 주소로 확인한다.

```text
http://localhost:8080/actuator/health
```

## 11. 현재 한계와 후속 작업

| 항목 | 현재 상태 | 후속 기준 |
|---|---|---|
| `db/schema.sql` | 아직 없음 | Auth table 생성 기준 추가 후 검증 |
| JPA Entity | 아직 없음 | Entity 구현 시 `ddl-auto=update` 사용 금지 기준 확인 |
| Auth controller/service | 아직 없음 | Sprint 1 Auth API 구현 PR에서 추가 |
| Security config | 아직 없음 | JWT, CORS, cookie 정책 구현 시 추가 |
| UTC/timezone | 명시 설정 전 | token 만료, password reset 구현 전 확정 |
| CI DB test | 아직 없음 | CI에서 MySQL service container 또는 test profile 결정 |

현재 백엔드 구조는 skeleton과 DB 연결 확인을 완료한 상태다. Auth table 생성, Entity mapping, JWT 발급·검증, OAuth callback, password reset은 후속 Sprint 1 작업에서 구현한다.
