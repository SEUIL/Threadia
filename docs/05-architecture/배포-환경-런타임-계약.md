# 배포 환경 및 런타임 계약

## 1. 목적과 적용 범위

이 문서는 현재 repository의 코드, 예시 설정, CI workflow, deploy script를 기준으로 배포 시 주입할 환경 변수의 계약을 정의한다. 실제 환경 변수 값, secret, host, domain, account 식별자는 기록하지 않는다.

이 문서의 대상은 backend Spring Boot process, frontend build, CI test와 `ecr-compose-nonprod` Compose deployment다. 실제 AWS resource 생성, GitHub Secrets 또는 Environment 설정, 그리고 workflow 실행에 따른 배포 실행은 범위에 포함하지 않는다.

코드가 환경 변수를 읽거나 script가 소비하는 경우만 현재 동작으로 분류한다. 예시 파일과 기존 AWS 문서는 보조 근거이며, 이 문서와 code path가 충돌할 때 code path를 우선한다.

## 2. 설정 출처와 우선순위

### 2.1 Backend Spring Boot

`backend/src/main/resources/application.properties`는 root `.env`와 `backend/.env`를 선택적으로 import한다. 두 파일은 local 개발 편의를 위한 fallback이며, repository에 commit하지 않는다.

동일 backend property의 현재 우선순위는 다음과 같다.

1. Spring Boot command-line argument와 Java system property
2. process environment variable
3. `backend/.env` import
4. root `.env` import
5. `application.properties`의 placeholder default

같은 키를 여러 출처에 중복 정의하지 않는다. 배포 runtime은 process environment variable을 표준 전달 경로로 사용한다. `.env` import는 현재 코드가 지원하는 local fallback일 뿐, production secret 전달 경로로 확정하지 않는다.

### 2.2 Frontend Next.js

Frontend code는 `NEXT_PUBLIC_API_URL`을 build process environment에서 읽고, 없으면 source code fallback을 사용한다. `NEXT_PUBLIC_` 값은 browser bundle에 포함되므로 secret을 넣지 않는다. build 이후 process environment를 바꾸어도 이미 생성된 browser bundle의 값은 바뀌지 않는다.

`frontend/.env.example`은 예시 파일이고 자동 주입 출처가 아니다. production build를 만드는 주체가 build 직전에 public API URL을 process environment로 제공해야 한다.

### 2.3 Local Compose와 test script

`compose.mysql.yml`은 root 환경에서 local MySQL container를 만들 때만 DB 이름, 사용자, password와 root password를 읽는다. `backend/scripts/auth-e2e-preflight.sh`의 `THREADIA_E2E_*` 키는 E2E preflight 실행에만 사용한다. 이 두 경로는 production application runtime의 설정 출처가 아니다.

## 3. 현재 runtime 필수 키

아래 키는 code default가 있더라도 production deployment에서 명시적으로 주입해야 하는 계약이다. default는 local 개발 편의를 위한 것이며 production 안전값이 아니다.

| 키 | 소비 위치 | 분류 | 주입 이유 | 기본 동작 |
|---|---|---|---|---|
| `THREADIA_DB_URL` | backend datasource | Compose가 주입 | `mysql` service를 향한 내부 JDBC URL | local datasource fallback |
| `THREADIA_DB_USERNAME` | backend datasource | 필수 | production DB 계정 | local username fallback |
| `THREADIA_DB_PASSWORD` | backend datasource | 필수, secret | DB 인증 | 빈 값 |
| `THREADIA_JWT_SECRET` | JWT signer 및 verifier | 필수, secret | access token 서명과 검증 | 빈 값, token 처리 시 설정 오류 |
| `THREADIA_COOKIE_SECURE` | refresh token cookie | 필수 | HTTPS deployment에서 Secure cookie 활성화 | 비활성 |
| `THREADIA_CORS_ALLOWED_ORIGIN` | `CorsConfig` | 필수 | credential 포함 API 요청의 허용 origin | local frontend origin |
| `THREADIA_PLATFORM_ADMIN_BOOTSTRAP_EMAIL` | `PlatformAdminBootstrapService` | restricted SSM host 필수, secret-adjacent | 비어 있는 `platform_admins`를 bootstrap할 valid ACTIVE user 식별 | 없음 |
| `NEXT_PUBLIC_API_URL` | frontend API client와 OAuth 시작 URL | 필수, public build config | browser가 호출할 API base URL | local backend URL fallback |

`SPRING_PROFILES_ACTIVE`는 Spring Boot가 인식하는 선택 키지만, 현재 repository에는 profile별 application config가 없다. profile을 도입하는 별도 결정 전에는 runtime 필수 키로 간주하지 않는다.

restricted SSM host는 위 bootstrap email key를 exact Parameter Store SecureString으로 materialize한다. 이 key는 persistent DB의 Platform foundation one-time additive migration 후 첫 bootstrap에 필요하며, actual email value는 repository, 문서, CI log, PR evidence에 기록하지 않는다. ECR Compose Fresh DB path의 `.env` 계약 또는 `db/schema.sql` 실행 권한을 확장하지 않는다.

## 4. 조건부 필수 키

### 4.1 Google OAuth를 활성화할 때

`GoogleOAuthClientConfig`는 `GOOGLE_CLIENT_ID`와 `GOOGLE_CLIENT_SECRET`가 모두 비어 있지 않을 때만 client registration을 만든다. 둘 중 하나라도 없으면 OAuth login flow는 활성화되지 않는다.

| 키 | 분류 | 조건 | 기본 동작 |
|---|---|---|---|
| `GOOGLE_CLIENT_ID` | 조건부 필수, secret-adjacent | Google OAuth 활성화 | 빈 값 |
| `GOOGLE_CLIENT_SECRET` | 조건부 필수, secret | Google OAuth 활성화 | 빈 값 |
| `GOOGLE_REDIRECT_URI` | 조건부 필수, config | Google OAuth 활성화 | framework callback template |
| `THREADIA_OAUTH_SUCCESS_REDIRECT_URL` | 조건부 필수, config | Google OAuth 성공 redirect 사용 | local frontend success path |
| `THREADIA_OAUTH_FAILURE_REDIRECT_URL` | 조건부 필수, config | Google OAuth 실패 redirect 사용 | local frontend failure path |

OAuth key를 주입하기 전에 provider console의 callback 등록값, frontend origin, CORS origin, cookie policy가 같은 확정 domain 정책을 참조해야 한다.

### 4.2 Password reset email을 실제 발송할 때

Password reset API의 email delivery를 production에서 제공하면 아래 키를 같은 환경 계약으로 검토한다. credential 또는 domain 관련 값은 log와 문서에 출력하지 않는다.

| 키 | 분류 | 조건 | 기본 동작 |
|---|---|---|---|
| `MAIL_HOST` | 조건부 필수, config | SMTP provider를 사용한 실제 발송 | code default SMTP host |
| `MAIL_PORT` | 조건부 필수, config | SMTP provider를 사용한 실제 발송 | code default SMTP port |
| `MAIL_USERNAME` | 조건부 필수, secret-adjacent | SMTP 인증 | 빈 값 |
| `MAIL_PASSWORD` | 조건부 필수, secret | SMTP 인증 | 빈 값 |
| `NOTIFICATION_FROM_EMAIL` | 조건부 필수, config | provider 발신자와 SMTP username이 다를 때 | `MAIL_USERNAME` fallback |
| `THREADIA_PASSWORD_RESET_URL_PREFIX` | 조건부 필수, public config | reset link가 frontend production URL을 가리켜야 할 때 | local frontend reset path |

## 6. CI 전용 test 값

`.github/workflows/backend-ci.yml`과 `.github/workflows/pre-deploy-readiness.yml`은 backend test를 위해 `THREADIA_DB_URL`, `THREADIA_DB_USERNAME`, `THREADIA_DB_PASSWORD`, `THREADIA_JWT_SECRET`, `THREADIA_COOKIE_SECURE`, `THREADIA_CORS_ALLOWED_ORIGIN`을 job environment에 둔다. `frontend-ci.yml`과 readiness workflow는 frontend build를 위해 `NEXT_PUBLIC_API_URL`을 job environment에 둔다.

이 workflow의 값은 test fixture다. 특히 CI의 JWT secret은 production secret이 아니며, production secret store 또는 runtime environment에 복사하지 않는다. CI job에 없는 OAuth와 SMTP key는 현재 CI가 실제 OAuth login 또는 email delivery를 검증하지 않는다는 뜻이다.

## 7. ECR Compose deployment

`.github/workflows/ecr-compose-nonprod.yml`은 `workflow_dispatch`로만 실행하며, `main` branch에서만 수동 실행할 수 있다. 이 workflow는 backend와 frontend image를 ECR에 publish한 뒤 기존 `THREADIA_COMPOSE_SSH_KEY`, `THREADIA_COMPOSE_SSH_KNOWN_HOSTS` secret으로 public Compose host에 접속하여 `compose.ecr-nonprod.yml`과 `db/schema.sql`을 먼저 동기화한다. `restricted-ssm-release`는 별도 승인된 cutover 전까지 `main`의 자동 release 소유자로 유지한다.

host의 ignored `.env`는 DB credential, JWT와 조건부 OAuth·SMTP key를 제공한다. workflow와 compose는 secret 값을 저장하거나 전달하지 않는다. Compose는 backend의 datasource URL을 `mysql` service로 고정하고 나머지 DB credential을 runtime `.env`에서 주입한다.

Compose host는 host 자체의 AWS identity로 ECR에 인증해야 한다. workflow는 GitHub runner의 AWS credential을 host로 전달하지 않으며, public region·registry·repository·image tag만 deployment input으로 제공한다. host에서는 ECR 인증과 `docker compose pull`이 성공한 뒤에만 `docker compose ... down --volumes --remove-orphans`를 실행하고 서비스를 다시 만든다. 따라서 pull 또는 인증 실패는 실행 중인 stack을 유지한다.

매 release의 Fresh DB 정책에 따라 Compose가 관리하는 MySQL container와 data volume은 의도적으로 삭제된다. 새 MySQL 8.4 container는 `db/schema.sql`을 한 번 실행하고 canonical schema 존재 query healthcheck를 통과한 뒤 backend를 시작한다. 이후 workflow는 backend image의 `curl`로 Compose network 내부 `http://backend:8080/actuator/health`를 제한된 횟수로 확인하며, 성공하지 않으면 release를 실패 처리한다. 이 경로는 persistent data를 보존하는 production DB model이 아니다.

## 8. 향후 AWS 및 deploy placeholder

다음 키는 `.env.example`, `scripts/deploy/check-env.sh`, `scripts/deploy/deploy-backend-ec2.example.sh` 또는 AWS proposal에서 보이지만 현재 application runtime과 deploy workflow가 소비하지 않는다. 값의 존재 여부 확인이나 dry-run skeleton을 실제 deployment 구현으로 해석하지 않는다.

| 키 묶음 | 키 | 현재 상태 |
|---|---|---|
| Domain과 certificate | `THREADIA_DOMAIN_NAME`, `THREADIA_APP_DOMAIN`, `THREADIA_API_DOMAIN`, `THREADIA_DOCS_DOMAIN`, `THREADIA_ROUTE53_HOSTED_ZONE_ID`, `THREADIA_ACM_CERTIFICATE_ARN` | 미래 AWS 또는 hosting placeholder |
| GitHub Actions AWS OIDC | `AWS_REGION`, `AWS_ROLE_TO_ASSUME` | 미래 deploy job placeholder |
| EC2 backend skeleton | `THREADIA_DEPLOY_TARGET_HOST`, `THREADIA_DEPLOY_TARGET_USER`, `THREADIA_DEPLOY_SSH_KEY_PATH`, `THREADIA_DEPLOY_REMOTE_DIR`, `THREADIA_DEPLOY_ARTIFACT`, `THREADIA_DEPLOY_RESTART_COMMAND`, `THREADIA_DEPLOY_EXECUTE` | local dry-run script용 placeholder |

`THREADIA_DEPLOY_EXECUTE`는 명시적으로 활성화되지 않으면 remote action을 수행하지 않는다. 이 계약은 해당 활성화나 원격 배포를 승인하지 않는다.

## 9. Secret 주입 소유권

| 환경 | secret 주입 담당 | 허용 경로 | repository 책임 |
|---|---|---|---|
| Local 개발 | 실행 개발자 | ignored local `.env` 또는 local process environment | `.env.example`에 key와 placeholder만 유지 |
| CI test | workflow 작성자 | workflow의 test fixture environment | production secret을 넣지 않음 |
| ECR Compose runtime | 승인된 platform 또는 deployment 담당자 | host의 ignored runtime `.env`에서 Compose container로 주입 | key 소비와 누락 시 동작만 유지, secret 값 저장 금지 |
| Future AWS deploy | 미정 | 미정 | OIDC와 secret store 방식은 deployment 설계 확정 후 결정 |

application code, `.env.example`, docs, CI log, PR evidence는 secret 값을 소유하거나 출력하지 않는다. production injection 경로가 확정되기 전에는 secret을 GitHub workflow, repository variable, Dockerfile, image layer에 옮기지 않는다.

## 10. 미해결 결정과 비권위 정보

### 9.1 배포 전 확정할 결정

| 결정 | 현재 상태 | 영향 |
|---|---|---|
| Canonical domain과 subdomain 정책 | 미확정 | CORS, OAuth callback, reset link, frontend build config, TLS 설정 |
| Backend runtime 형태와 config 전달 방식 | 미확정 | process environment, container definition, local `.env` fallback의 운영 사용 여부 |
| Production secret store와 injection 주체 | 미확정 | DB, JWT, OAuth, SMTP secret의 전달 경로 |
| Frontend hosting과 build 실행 주체 | 미확정 | `NEXT_PUBLIC_API_URL`의 build-time 주입 책임 |
| Docs site hosting | 미확정 | `THREADIA_DOCS_DOMAIN` placeholder의 필요 여부 |
| TLS termination 위치 | 미확정 | certificate 관리와 HTTPS cookie 검증 |

위 항목에는 값이 없다. 확정 전에는 domain을 정규화하거나 placeholder를 실제 설정으로 바꾸지 않는다.

### 9.2 기존 문서와 placeholder의 해석

[`AWS-운영-환경변수-목록.md`](./AWS-운영-환경변수-목록.md)는 inventory 초안이며 runtime source of truth가 아니다. [`AWS-배포-아키텍처-v1.md`](./AWS-배포-아키텍처-v1.md)와 [`Route53-커스텀-도메인-가이드.md`](./Route53-커스텀-도메인-가이드.md)의 domain 및 AWS 예시는 proposal 또는 guide로만 해석한다.

기존 문서에 남아 있는 과거 domain 표기, AWS region, Route 53, ACM, OIDC, EC2 관련 키와 값은 이 계약의 runtime 설정을 확정하지 않는다. 특히 `THREADIA_DOCS_DOMAIN`은 현재 consumer가 없는 placeholder다. 관련 문서는 기록 보존을 위해 수정하거나 삭제하지 않는다.
