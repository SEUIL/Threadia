## 2026-07-02 백엔드 schema 검증 기준 보강

> 변경이력 묶음 ID: 백엔드 schema 검증 기준 보강 ^change-2026-07-02-backend-schema-validation

### 1. 목적

Sprint 1 Auth DB 검증 기준을 단순 MySQL 연결 확인에서 `db/schema.sql` 적용 검증까지 확장하고, 최신 `dev` 기준의 Auth JPA Entity mapping 현황을 백엔드 구조 문서에 반영한다.

### 2. 변경 원칙

- Sprint 1 구현·검증 직접 대상은 Auth 4개 table로 유지한다.
- `db/schema.sql` 적용 검증은 기존 `threadia_test`가 아니라 임시 DB `threadia_schema_validation`에서 수행한다.
- schema 적용 테스트는 SQL 적용 자체를 검증하므로 Spring context 시작 시점의 JPA schema validation은 비활성화한다.
- JPA Entity와 실제 schema의 정합성은 별도 JPA schema validation gate에서 확인한다.
- API, 요구사항, ERD DDL 자체는 이번 변경에서 수정하지 않는다.

### 3. 변경 문서

| 문서 | 변경 내용 |
|---|---|
| `backend/src/test/java/com/threadia/backend/MysqlSchemaValidationTests.java` | `db/schema.sql` 적용 전 JPA validation이 먼저 실행되지 않도록 test context의 `ddl-auto`를 `none`으로 고정 |
| `docs/05-architecture/백엔드-구조.md` | schema.sql 적용 검증 테스트, Auth JPA Entity mapping 현황, JPA/schema 검증 역할 분리 기준 반영 |
| `docs/08-members/member-여도현/기술-연구/sprint-1-mysql-연결-검증-피드백.md` | 임시 DB 기반 schema.sql 적용 검증 절차와 후속 작업 기준 정리 |
| `docs/07-decisions/기획문서-변경이력.md` | canonical 백엔드 구조 문서 변경 묶음 추가 |

### 4. 영향 범위

## 2026-07-01 ERD 기준 schema.sql 최초 생성

> 변경이력 묶음 ID: ERD 기준 schema.sql 최초 생성 ^change-2026-07-01-schema-sql-initial-ddl

### 1. 목적

`docs/03-design/ERD.md` 개발주간 ERD 상세화 v1.2를 기준으로 MySQL 8.4용 `db/schema.sql`을 생성해 backend Entity와 로컬 DB 생성의 기준 산출물을 고정한다.

### 2. 변경 원칙

- Sprint 1 구현·검증 직접 대상은 Auth 4개 table로 유지한다.
- 전체 MVP 27개 table은 reference DDL 스켈레톤으로 포함한다.
- `messages.thread_id`, `issues.issue_key VARCHAR(40)`, 채팅/DM/알림 조회용 복합 index, archive/trash/date/source CHECK를 ERD v1.2 기준으로 반영한다.
- tenant/project/다형성 정합성처럼 FK와 CHECK만으로 표현하기 어려운 규칙은 service policy와 테스트 검증 대상으로 분리한다.
- SQL 파일에는 실행 DDL만 남기고, 설명과 근거는 ERD, 근거표, 변경이력 문서에 기록한다.

### 3. 변경 문서

| 문서 | 변경 내용 |
|---|---|
| `db/schema.sql` | 전체 MVP 27개 table DDL 최초 생성. Auth 4개 table과 후속 MVP reference table의 PK, FK, unique/index, CHECK constraint 반영 |
| `docs/07-decisions/DB-schema-변경이력.md` | `db/schema.sql` 최초 생성 이력 추가, metadata를 v1.1로 갱신 |
| `docs/07-decisions/기획문서-변경이력.md` | ERD 기준 schema 생성 변경 묶음 추가 |

### 4. 영향 범위

| 구분 | 영향 |
|---|---|
| 요구사항 | 요구사항 범위 변경 없음. Sprint 1 Auth-only와 Sprint 1.5 invitation 분리 유지 |
| API | API 계약 변경 없음. API와 충돌하던 `messages.thread_id` 누락 가능성을 DDL에서 보정 |
| ERD/DB | ERD v1.2를 실행 가능한 MySQL 8.4 DDL로 반영. 전체 MVP table은 reference skeleton이며 Sprint 1 검증 범위는 Auth 4개 table 중심 |

## 2026-07-01 ERD MVP reference table 상세화

> 변경이력 묶음 ID: ERD MVP reference table 상세화 ^change-2026-07-01-erd-mvp-reference-detail

### 1. 목적

`db/schema.sql` 작성 전에 `docs/03-design/ERD.md`의 MVP reference table을 table별 column, FK, unique/index 후보, service policy 경계까지 확인 가능한 수준으로 상세화한다. 또한 오후 27개 table schema 초안을 canonical API/ERD와 대조해 그대로 수용할 항목과 수정 전 blocker를 분리한다.

### 2. 변경 원칙

- Sprint 1 구현 범위는 Auth-only로 유지한다.
- Auth 4개 table과 invitation/조건부 table의 기존 상세 정의는 유지한다.
- 근거가 약한 column 결정은 TBD 또는 service policy로 낮춰 과잉 확정을 피한다.
- 전체 MVP 27개 table 스켈레톤은 `schema.sql`에 둘 수 있으나, Sprint 1 구현·검증은 Auth 4개 table 중심으로 유지한다.
- `activity_events`, `project_dashboard_summaries`는 전체 MVP DDL 스켈레톤 포함은 허용하되 실제 활성화는 조건부 확장으로 분리한다.
- API와 충돌하는 schema 초안 항목은 canonical 반영 전 blocker로 표시한다.

### 3. 변경 문서

| 문서 | 변경 내용 |
|---|---|
| `docs/03-design/ERD.md` | `companies`부터 `notification_preferences`까지 MVP reference table 상세 column/FK/unique/index 후보 추가, `oauth_accounts`에 provider별 사용자 중복 연결 방지 unique 추가, `projects.status`·`sprints.status`·`documents.document_type`을 API enum과 정합화, `messages.thread_id`와 notification 표시 컬럼 blocker를 명시, metadata를 ERD 상세화 v1.2로 갱신 |
| `docs/03-design/ERD-상세화-근거표.md` | table별 근거표를 v0.3으로 갱신하고, 오후 schema 초안 리뷰 결과와 추가 수정필요사항을 수용/수정 전 blocker/보류 항목으로 기록 |
| `docs/07-decisions/기획문서-변경이력.md` | canonical ERD 변경 묶음 추가 |

## 2026-06-27 DB schema 관리 방식 변경

> 변경이력 묶음 ID: DB schema 관리 방식 변경 ^change-2026-06-27-db-schema-policy

### 1. 목적

멘토 피드백에 따라 Sprint 1 개발 단계의 DB schema 관리 방식을 Flyway/Liquibase migration tool 기반 versioned migration에서 ERD 기반 `db/schema.sql`과 문서 변경이력 관리 방식으로 변경한다.

- Sprint 1에서는 Flyway/Liquibase migration tool을 구성하지 않는다.

- 이 수정본은 기획 문서 정합성 보정본이다. 실제 schema migration, Backend 구현, Frontend 구현은 포함하지 않는다.
