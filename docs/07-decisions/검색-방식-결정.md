## 1. 결정 개요

| 항목 | 결정 |
|---|---|
| 결정 ID | `SEARCH-01` |
| WBS | `4.9.2.1` |
| 상태 | Backend 결정 완료 |
| 적용 범위 | Sprint 3 baseline |

WBS `4.9.2`는 진행 중 50% conceptual parent다. 완료된 MySQL `LIKE` Backend 결정은 `4.9.2.1`에서, 계획/0% Frontend 결정은 Owner 정철진의 `4.9.2.2`에서 추적한다. 구현은 진행 중 50% conceptual parent `4.9.4` 아래 완료된 Backend `4.9.4.1`과 계획/0% Frontend `4.9.4.2`로 분리한다.

## 2. 확정 결정

제품 통합 검색은 프로젝트 범위 안에서 Issue, Document, Thread, Project Message를 검색한다.

초기 구현은 MySQL `LIKE`를 사용한다. 검색 query에 프로젝트 범위를 적용하고, 기존 프로젝트 authorization policy로 접근을 제한한다. Sprint 3 baseline에는 외부 검색 서비스, 검색 index, 동기화 pipeline을 포함하지 않는다.

이 결정은 API request/response field를 만들지 않는다. 해당 field는 구현 slice에서 확정할 계약이다.

## 3. 품질 범위와 제외

초기 검색은 한국어 형태소 분석, 초성 검색, 오타 허용, 동의어, fuzzy 검색, autocomplete를 보장하지 않는다.

## 4. 전환 판단 기준

| 후보 | 검토 조건 |
|---|---|
| MySQL FULLTEXT | 측정한 `LIKE` 동작이 합의된 relevance 또는 performance 요구를 충족하지 못할 때 검토한다. |
| 외부 검색 엔진 | MySQL baseline과 FULLTEXT가 모두 합의된 quality 또는 performance 요구를 충족하지 못하거나, 제품에 오타 허용, faceted search, 한국어 linguistic analysis 같은 역량이 필요할 때 검토한다. |

수치 SLO는 이 결정에서 정하지 않는다. Korean FULLTEXT를 검토할 때는 ngram 적용 필요성을 별도로 판단하며, 형태소 분석이나 stemming을 보장하는 것으로 해석하지 않는다.

## 5. 검증 기준

- 권한이 있는 프로젝트에서 일반 검색 결과가 반환된다.
- 일치하는 항목이 없으면 빈 결과를 반환한다.
- 다른 프로젝트 또는 권한 없는 항목은 검색 결과에 노출하지 않는다.
- 특수문자 입력을 안전하게 처리한다.
- 중복 없는 결과를 deterministic pagination으로 반환한다.

## 6. 영향과 비범위

- 기존 project-leading B-tree index를 전제로 하며, FULLTEXT index를 추가하지 않는다.
- DB table, column, FK, index, 외부 검색 인프라, 동기화 pipeline은 변경하지 않는다.
- Typesense와 Meilisearch는 명시적으로 보류한다.
