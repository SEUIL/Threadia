# Threadia 발표 시연 시나리오와 대본

## 1. 목적과 운영 원칙

이 문서는 배포 완료된 Threadia를 15분 이내에 시연하기 위한 화면 순서와 발표 대본이다. 시연의 중심 메시지는 다음과 같다.

> Threadia는 사용자 협업, 회사 관리, 프로젝트 실행, 플랫폼 운영을 하나의 맥락으로 연결하는 통합 협업 플랫폼이다.

시연 중 변경하는 데이터는 사전에 준비한 항목으로 한정한다. DM 메시지 전송, 회사 초대 거절, 부서 추가·구성원 부서 배정, 선택한 이슈의 칸반 상태 이동, 쓰레드 댓글, 문서 파일 추가, Sprint 백로그 배정·해제, 문의 답변, 테스트 회사 비활성화만 수행한다. 그 외 이슈 생성·삭제, 일반 문서 수정, 권한 변경, 시스템 설정 변경은 수행하지 않는다.

## 4. 상세 대본

### 4.1 3D 허브와 사용자 공통 기능 (0:00~1:45)

#### 4.1.1 3D 허브

**화면**: `/hub`

**대본**

> Threadia는 Jira, Slack, Confluence처럼 분리된 협업 도구에서 업무 맥락이 끊기는 문제를 해결하기 위한 통합 협업 플랫폼입니다.
>
> 첫 화면은 3D 허브입니다. 회사 구성원이 하나의 협업 공간에서 프로젝트, 채팅·DM, 초대, 알림, 문의, 회사 관리로 이동하는 공통 진입점으로 구성했습니다.

**시연 포인트**

- 3D 오피스와 좌측 레일을 20~30초만 보여준다.
- 카메라 조작은 최소화한다.

#### 4.1.2 DM, 받은 초대, 알림, 문의하기

**화면**: `/6/dm` → `/invitations` → `/6/notifications` → `/support`

**대본**

> 먼저 채팅·DM입니다. 프로젝트 채팅과 별도로 같은 회사 구성원 사이의 1:1 소통을 지원합니다. 여기서 DM 메시지를 전송해 개인 협업 흐름을 보여드리겠습니다.
>
> 다음은 받은 초대입니다. 다른 회사에서 보낸 초대를 수락하거나 거절할 수 있고, 이번에는 미리 준비한 테스트 회사 초대를 거절하겠습니다. 초대 상태가 회사 소속과 권한 흐름에 연결됩니다.
>
> 알림 화면에서는 사용자에게 도착한 알림을 모아 보고 읽음 상태를 관리할 수 있습니다.
>
> 마지막으로 문의하기입니다. 사용자는 서비스 이용 중 발생한 문의를 등록하고 자신의 문의 내역을 확인할 수 있습니다. 여기 있는 문의는 뒤에서 플랫폼 관리자가 답변하는 흐름으로 이어집니다.

**시연 포인트**

- DM에서 준비한 문구를 한 번 전송한다.
- 받은 초대에서 사전 준비한 테스트 회사 초대만 `거절`한다.
- 알림은 목록·읽지 않은 수만 소개하고 상태는 변경하지 않는다.
- 문의하기에서 미리 등록한 문의 제목과 상태를 보여준다.

### 4.2 회사 관리와 프로젝트 선택 (1:45~4:30)

#### 4.2.1 회사 관리·구성원 관리

**화면**: `/6/settings` → `/6/members`

**대본**

> 회사 관리 화면에서는 회사 정보와 전체 프로젝트, 구성원, 부서, 진행 중 프로젝트 현황을 한 화면에서 확인할 수 있습니다.
>
> 회사 관리자는 조직 구조를 직접 운영할 수 있습니다. 지금 `인프라/클라우드 팀` 부서를 추가하고, 구성원 관리 화면에서 아직 부서가 배정되지 않은 구성원에게 해당 부서를 할당하겠습니다.
>
> 이처럼 Threadia는 프로젝트 업무 관리 이전에 조직과 구성원을 함께 관리할 수 있도록 구성했습니다.

**시연 포인트**

- 회사 현황 카드와 기존 부서 목록을 먼저 소개한다.
- `인프라/클라우드 팀`을 추가한다.
- `구성원 관리로 이동`을 눌러 구성원 목록, 역할·상태·부서 정보를 소개한다.
- 미배정 구성원 한 명에게만 새 부서를 배정한다.

#### 4.2.2 프로젝트 목록과 프로젝트 홈

**화면**: `/6/projects` → `/6/9/dashboard`

**대본**

> 회사에는 여러 프로젝트가 존재하며, 기획중·진행중·일시중지·완료·보관됨 상태로 분류해 조회할 수 있습니다. 상태 필터를 통해 회사 전체의 프로젝트 포트폴리오를 빠르게 파악할 수 있습니다.
>
> 이제 기획중인 `TAI · AI 업무 인사이트 및 프로젝트 리포트`를 선택하겠습니다.
>
> 프로젝트 홈에서는 이슈 진행률과 최근 이슈, 최근 문서를 요약해 보여줍니다. 관리자는 여러 화면을 오가지 않고도 프로젝트의 현재 상태를 빠르게 파악할 수 있습니다.

**시연 포인트**

- 프로젝트 목록과 다섯 상태 필터를 조회만 한다.
- `TAI · AI 업무 인사이트 및 프로젝트 리포트`를 클릭해 프로젝트 9로 진입한다.
- 프로젝트 홈의 이슈 진행률, 최근 이슈·문서 목록을 짚는다.

### 4.3 프로젝트 채팅: 대화에서 이슈 후보 확인 (4:30~5:30)

**화면**: `/6/9/messages`

**대본**

> 프로젝트 채팅은 프로젝트 구성원이 업무 맥락을 공유하는 공간입니다. 실무에서는 업무 요청과 결정이 채팅에서 먼저 발생하지만, 채팅만으로 관리하면 중요한 논의가 묻히게 됩니다.
>
> 이 메시지인 “AI 리포트에서 보여줄 핵심 지표 후보를 정리해보겠습니다. 우선 프로젝트 진행률과 이슈 상태를 기준으로 잡겠습니다.”를 이슈 후보로 전환할 수 있습니다. `이슈로 만들기`를 눌러 이슈 제목과 내용을 확인하되, 이번 시연에서는 실제 생성하지 않습니다.
>
> 생성하지 않고 모달을 닫은 뒤, 두 번째 채팅에 연결된 `→ [SEED:TAI:ISSUE:02]`를 클릭해 칸반 보드로 이동하겠습니다. 이후 이슈는 칸반 보드에서 상태와 담당 업무로 관리하고, 필요하면 쓰레드로 세부 논의를 이어갈 수 있습니다.

**시연 포인트**

- 프로젝트 채팅과 구성원 영역을 소개한다.
- 첫 메시지의 `이슈로 만들기`를 눌러 모달의 입력 항목을 보여주고 취소한다.
- 두 번째 채팅의 `→ [SEED:TAI:ISSUE:02]` 링크를 클릭해 칸반 보드로 이동한다.
- 메시지 전송이나 이슈 생성은 하지 않는다.

### 4.4 칸반, 이슈 상세, 쓰레드 (5:30~7:20)

**화면**: `/6/9/messages`의 `→ [SEED:TAI:ISSUE:02]` → `/6/9/board` → 이슈 상세 → 쓰레드

**대본**

> 채팅에서 확인한 업무 후보는 칸반 보드에서 실행 단위로 관리합니다. 이슈는 백로그에서 시작해 할 일, 진행 중, 검토 중, 완료 단계로 이동하며 업무 상태를 명확히 보여줍니다. 지금 이슈 하나를 백로그에서 완료까지 단계별로 이동해 보겠습니다.
>
> 여기서 `TAI-1 프로젝트 리포트 핵심 지표 정의` 이슈를 선택하고 상세를 열겠습니다. 상세 화면에서는 이슈의 설명, 상태, 담당·기한 같은 업무 정보와 연결된 문서·쓰레드를 확인할 수 있습니다.
>
> 이제 쓰레드를 열어 이슈에 대한 논의를 이어가겠습니다. 쓰레드는 이슈·문서·메시지에 연결되는 대표 토론 공간으로, 업무 결정의 이유를 해당 대상과 함께 보존합니다.

**시연 포인트**

- 선택한 이슈 하나를 백로그에서 할 일, 진행 중, 검토 중, 완료로 순서대로 이동한다.
- 백로그부터 완료까지의 상태 컬럼을 차례로 소개한다.
- `TAI-1`을 클릭하고 `상세 열기`를 눌러 이슈 상세 항목을 소개한다.
- `쓰레드 열기`를 눌러 댓글 입력란에 아래 문구를 작성·등록한다.

```text
첫 번째 지표에 작업량의 난이도도 추가해야 될 것 같습니다.
```

### 4.5 그래프와 문서: 업무 맥락의 추적 (7:20~8:50)

#### 4.5.1 그래프

**화면**: `/6/9/graph`

**대본**

> 이슈만으로는 기획 배경, 회의 결정, 작업 기록을 충분히 보존하기 어렵습니다. Threadia는 이슈와 문서를 연결하고, 그래프 화면에서 관계를 노드로 보여줍니다.
>
> 따라서 Threadia는 단순히 할 일을 관리하는 도구가 아니라 업무가 왜 시작됐고 어떤 산출물과 연결되는지를 보존하는 도구입니다.

**시연 포인트**

- 문서·이슈 노드와 자동 정렬 기능을 보여준다.
- 문서 노드 하나를 클릭하고 `문서 열기`를 선택한다.

#### 4.5.2 문서와 첨부 파일

**화면**: `/6/9/docs` → 문서 상세

**대본**

> 문서 페이지에서는 기획, 작업 기록, 회의 내용처럼 프로젝트의 산출물을 관리합니다. 문서 자체와 연결 이슈를 함께 보존해, 업무의 결과와 근거를 분리하지 않습니다.
>
> 또한 문서에는 필요한 파일을 첨부할 수 있습니다. 지금 준비한 파일을 추가해 문서 중심 협업에서 파일까지 함께 관리할 수 있음을 보여드리겠습니다.

**시연 포인트**

- 문서 목록과 문서 상세 내용을 소개한다.
- 준비한 첨부 파일만 추가한다. 기존 파일과 문서 본문은 수정·삭제하지 않는다.

### 4.6 Sprint와 백로그 운영 (8:50~9:50)

**화면**: `/6/9/backlog`

**대본**

> 백로그와 Sprint 화면에서는 이슈를 계획 단위로 운영합니다. `Sprint-01 기획`은 종료된 이력을 통해 계획 단위의 완료 흐름을 보여주고, 현재 `Sprint-02 설계`에서는 백로그 이슈를 선택해 배정할 수 있습니다.
>
> 이번에는 이슈 하나를 Sprint-02에 배정한 뒤, 다시 백로그로 되돌리겠습니다. 이를 통해 계획 변경 시 이슈가 Sprint에 고정되지 않고 유연하게 관리되는 흐름을 보여드리겠습니다.

**시연 포인트**

- 종료된 `Sprint-01 기획`과 `Sprint-02 설계`를 먼저 소개한다.
- 준비한 이슈 하나를 Sprint-02에 배정한다.
- 같은 이슈를 백로그로 다시 이동한다.

### 4.7 통합 검색: 흩어진 업무 맥락을 다시 찾기 (9:50~10:30)

**화면**: `/6/9/search`

**대본**

> 앞에서 채팅, 이슈, 쓰레드, 문서가 연결되는 흐름을 보여드렸습니다. 실제 업무에서는 필요한 맥락을 다시 빠르게 찾는 것도 중요합니다.
>
> Threadia의 통합 검색은 현재 프로젝트 범위 안에서 이슈, 문서, 쓰레드, 채팅 메시지를 함께 찾습니다. 여기서 `로그인`을 검색하면 같은 주제의 이슈·문서·쓰레드·채팅 결과를 하나의 검색 흐름에서 확인할 수 있습니다.

**시연 포인트**

- 검색어로 `로그인`을 입력하고 이슈·문서·쓰레드·채팅 결과 범주를 보여준다.
- 검색 결과는 조회만 하고, 결과 상세를 여러 개 열지 않는다.

### 4.8 프로젝트 설정: 역할 기반 권한 (10:30~11:00)

**화면**: `/6/9/settings`

**대본**

> 프로젝트 설정에서는 프로젝트 정보와 멤버를 관리합니다. 특히 프로젝트 관리자와 일반 멤버 역할을 구분해, 프로젝트 관리 권한이 필요한 기능과 일반 협업 기능의 범위를 분리했습니다.
>
> 같은 회사 구성원만 프로젝트에 초대할 수 있도록 제한해, 프로젝트 경계와 회사 경계를 함께 보호합니다.

**시연 포인트**

- 프로젝트 정보와 멤버 역할 목록을 보여준다.
- 초대 가능 범위와 역할 구분을 설명한다.
- 멤버 역할 변경·제거·초대는 수행하지 않는다.

### 4.9 플랫폼 관리자: 서비스 운영과 감사 (11:00~14:00)

**계정 전환**: 플랫폼 관리자 계정

**화면**: `/platform/support-cases` → `/platform/companies` → `/platform/admins` → `/platform/settings` → `/platform/audits`

**대본**

> 지금까지는 회사와 프로젝트 내부의 협업 흐름을 보여드렸습니다. 마지막으로 서비스 운영자 관점의 기능을 소개하겠습니다.
>
> 먼저 앞에서 기본 계정으로 확인했던 문의를 플랫폼 관리자 콘솔에서 열겠습니다. 관리자는 문의 상태를 관리하고, 사용자에게 노출되는 공개 답변과 관리자 전용 내부 메모를 구분할 수 있습니다. 이번에는 미리 준비한 문의에 공개 답변을 등록하겠습니다.
>
> 회사 관리에서는 전체 회사의 상태를 조회하고 운영할 수 있습니다. 여기서는 테스트를 위해 만든 덤프 회사만 비활성화해, 플랫폼 차원의 회사 생명주기 관리 기능을 보여드리겠습니다.
>
> 관리자 화면에서는 사용자 ID와 부여 사유를 입력하고 `PLATFORM_ADMIN` 또는 `SUPER_ADMIN` 역할을 부여할 수 있습니다. `PLATFORM_ADMIN`은 운영 기능을 수행하고, `SUPER_ADMIN`은 관리자 관리까지 수행할 수 있는 최상위 역할입니다. 배포 과정에서는 초기 운영 계정에 `SUPER_ADMIN`을 bootstrap 방식으로 할당해 첫 관리자 계정을 확보합니다.
>
> 시스템 설정에서는 공지 배너, 제재 기준, 답변 템플릿, 고객센터 정책을 관리합니다. 운영 로그에서는 문의 처리, 회사 상태 변경, 설정과 권한 관련 관리자 행위를 추적할 수 있습니다.

**시연 포인트**

- 문의 상세에서 사전 준비한 문의를 열고 공개 답변을 등록한다. 내부 메모는 조회만 한다.
- `회사`에서 테스트 덤프 회사만 비활성화한다. 실제 사용 회사는 변경하지 않는다.
- `관리자`에서 사용자 ID, 부여 사유, `PLATFORM_ADMIN`·`SUPER_ADMIN` role 선택 UI와 배포 시 `SUPER_ADMIN` bootstrap 방식을 설명한다. role 부여는 수행하지 않는다.
- 시스템 설정의 정책 항목·버전과 운영 로그의 action 필터는 조회만 한다.

### 4.10 마무리 (14:00~15:00)

**대본**

> Threadia는 개인 DM과 회사 초대에서 시작해 조직과 구성원을 관리하고, 프로젝트 안에서는 채팅·이슈·쓰레드·문서·Sprint를 하나의 흐름으로 연결합니다.
>
> 여기에 프로젝트 역할 기반 권한과 플랫폼 관리자 운영 기능까지 제공해, 팀 협업과 서비스 운영을 하나의 플랫폼으로 연결했습니다. 감사합니다.

## 5. 발표 중 유의사항

| 상황 | 대응 |
|---|---|
| 3D 허브 WebGL 실패 | 레일에서 DM 또는 프로젝트 화면으로 즉시 이동하고, 3D 허브는 지원 환경에서 제공되는 보조 진입점이라고 짧게 설명한다. |
| 데이터 변경 직전 | 변경 대상이 사전에 준비한 DM·초대·부서·구성원·칸반 이슈·댓글·첨부·Sprint·문의·덤프 회사인지 화면에서 다시 확인한다. |
| 네트워크 지연 | 새로고침을 반복하지 말고 미리 준비한 다음 화면 탭으로 이동한다. |
| 플랫폼 관리자 계정 전환 지연 | 프로젝트 설정까지 먼저 진행하고, 별도 탭에서 준비한 플랫폼 콘솔을 연다. |
| 시간이 부족 | 그래프 또는 검색을 짧게 소개한 뒤 플랫폼 관리자와 결론으로 이동한다. |

## 6. 핵심 한 문장

> Threadia는 사용자 협업, 조직 관리, 프로젝트 실행, 플랫폼 운영 데이터를 연결해 업무의 실행과 맥락이 분리되지 않도록 만든 통합 협업 플랫폼이다.
