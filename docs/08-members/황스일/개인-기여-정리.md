# Threadia 개인 기여 정리

## 1. 기여 요약

프로젝트 전 기간 동안 WBS 실행 기준을 정비하고, Spring Boot 기반 Backend 기능 구현, 배포·CI/CD 경로 구성, QA 및 PR review를 수행했다. 특히 기능 구현 시 API·DB·권한·테스트·운영 문서를 함께 정리해 기능 단위의 추적성과 배포 준비도를 높였다.

| 구분 | 주요 기여 |
|---|---|
| Backend | 프로필, 프로젝트 초대, Issue/Sprint, 문서 그래프, 프로젝트 채팅, DM, Thread, 알림, 검색, Dashboard, 활동 피드, 플랫폼 관리자, 첨부파일 기능을 구현했다. |
| Infra·CI/CD | SSM 기반 release, ECR Compose, dual-image 배포, runtime contract, 배포 smoke와 storage migration 검증 경로를 구성했다. |
| WBS·문서 | WBS와 Sprint 계획을 동기화하고, API·ERD·Architecture·운영 Runbook·변경 이력을 지속적으로 정리했다. |
| QA·Review | Company Frontend 브라우저 QA, WBS gate 검토, 기능 PR review를 수행해 권한·회귀·배포 관점의 보완 사항을 반영했다. |

## 3. 배포 및 운영 기여

- SSM 기반 restricted release와 EC2 bootstrap·immutable artifact·수동 release 절차를 구성했다. ([#105](https://github.com/SEUIL/Threadia/pull/105))
- ECR Compose 배포, digest rollback, dual-image SSR release, public runtime 전달 계약을 구현·문서화했다. ([#128](https://github.com/SEUIL/Threadia/pull/128), [#129](https://github.com/SEUIL/Threadia/pull/129), [#130](https://github.com/SEUIL/Threadia/pull/130), [#132](https://github.com/SEUIL/Threadia/pull/132))
- CI에 frontend smoke, pre-deploy readiness, S3 runtime fixture를 추가해 배포 전 회귀 검증 경로를 보완했다. ([#85](https://github.com/SEUIL/Threadia/pull/85), [#88](https://github.com/SEUIL/Threadia/pull/88), [#227](https://github.com/SEUIL/Threadia/pull/227))

## 5. 핵심 문제 해결 경험

| 주제 | 해결 방식 | 결과 |
|---|---|---|
| 멀티테넌트 권한 | 회사·프로젝트 membership과 역할을 서비스 계층에서 재확인하고, 다른 회사·프로젝트 데이터 접근을 차단했다. | 채팅, DM, Issue, 문서, 알림, attachment 기능의 권한 경계를 일관되게 유지했다. |
| 동시성·페이지네이션 | DM room 생성, 읽음 포인터, 채팅·검색 cursor에 lock·keyset·signed cursor 방식을 적용했다. | 중복 생성, 읽음 수 불일치, offset 기반 조회의 불안정성을 줄였다. |
| 배포 안정성 | build artifact, runtime env, SSM, ECR Compose, readiness smoke를 분리하고 release 전 검증 게이트를 추가했다. | 배포 실패 원인을 source·runtime·infra 계층으로 분리해 점검할 수 있게 했다. |
| 파일 보안 | private S3 object storage와 target access 정책, additive migration 재실행 검증을 구성했다. | 파일 metadata와 실제 object 접근을 권한 정책 및 운영 gate 아래에서 관리할 수 있게 했다. |
