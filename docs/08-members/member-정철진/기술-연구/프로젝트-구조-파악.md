# 프로젝트 구조 파악

> 개인 학습 노트다. Threadia `docs/` canonical 문서를 정독하고 파악한 전체 구조를 정리한다.
> 공식 기준은 각 canonical 문서이며, 이 노트는 빠른 참조용 요약이다.

---

## 1. 프로젝트 개요

Threadia는 Jira(이슈)·Slack(채팅)·Confluence(문서)를 하나로 합친 협업 도구다. 핵심 차별점은 이슈, 문서, 메시지를 쓰레드와 그래프 뷰로 서로 연결하는 것이다.

- 팀: 6명 (황스일, 여도현, 정철진, 김민정, 김민경, 김태준)
- 부팀장: 정철진 (`cjfwls39`), `dev` PR review 조건 bypass 가능
- 진행 단계: 기획주간 6일차 종료 후 Sprint 1 진입

핵심 사용 흐름은 다음과 같다.

```text
S11 알림 → S05 이슈/칸반 → S10 쓰레드 → S09 채팅/1:1 DM
→ S08 문서 → S07 그래프 뷰 → 다시 S11 알림으로 회수
```

## 2. 기술 스택

| 영역 | 결정 |
|---|---|
| Backend | Spring Boot 3.x, Java 17, REST API |
| DB | MySQL 8.4 |
| Frontend | React + Next.js, TypeScript, Tailwind CSS, npm |
| 인증 | JWT Bearer Token (access 30분 memory, refresh 14일 `HttpOnly`/`SameSite=Lax` cookie) |
| 외부 연동 | Google OAuth, Google SMTP(비밀번호 재설정) |
| AWS | EC2/RDS/S3 사용 방향은 확정, 실제 배포와 S3 파일 저장 구현은 Sprint 1 이후 |
| 협업 | GitHub Issue, branch, PR, review, merge, CI |

## 3. Sprint 범위 구조 (가장 중요)

ERD와 API 명세서에는 전체 MVP가 모두 정의되어 있지만, 대부분은 `후속 sprint reference`다. 실제 Sprint 1 구현은 인증뿐이다.

| 단계 | 범위 |
|---|---|
| Sprint 1 | Auth-only. signup/login/logout/me/Google OAuth/비밀번호 재설정 + Spring Boot·Frontend skeleton + CI/PR baseline |
| Sprint 1.5 | 등록 사용자 대상 회사 invitation (app-internal only). accept 시 company membership 생성 |
| Sprint 2 이후 | company/project/issue/document/chat/DM/thread/notification, project invitation 등 나머지 MVP 전체 |

Sprint 1 DB는 인증 4개 table만 포함한다.

- `users`
- `oauth_accounts`
- `password_reset_tokens`
- `refresh_tokens`

## 4. 6일차 수정본 v2 공통 불변식

모든 canonical 문서에 반복 명시된 Auth hardening 기준이다.

1. email은 모든 진입점에서 `trim + lowercase`로 정규화한다. (signup, login, password reset, OAuth, invitation lookup 공통)
2. OAuth는 이메일만 같다는 이유로 기존 계정에 blind auto-link하지 않는다.
3. `password-reset/confirm` 성공 시 해당 사용자의 모든 기존 `refresh_tokens`를 revoke한다.
4. login, OAuth callback, token refresh, `/auth/me`는 `users.status = ACTIVE`인 사용자만 성공 처리한다.
5. 서버 생성·만료 시각은 UTC로 저장하고 API 응답은 ISO-8601 UTC `Z` 형식으로 반환한다.
6. `users.role` 필드는 만들지 않는다. 권한은 `company_members.role`과 `project_members.role`로 판정한다.
7. `activity_events`(활동 원장)와 `notification_events`(알림 사건 원본)는 통합하지 않고 분리 운영한다.

| 코드 | 역할 | company_members.role | project_members.role |

| A | 일반 사용자 | MEMBER | MEMBER |

권한은 계정에 고정하지 않고 회사·프로젝트 소속 관계로 판정한다.

## 7. Sprint 1 작업 일정 요약

Sprint 1 = Week 2, 5영업일. 인증 Backend는 여도현·김태준·김민경, Frontend는 정철진 단독, 협업/지원은 황스일·김민정이 맡는다.

| Day | 핵심 작업 |
|---|---|
| Day 1 | Spring Boot/Frontend/MySQL skeleton, CI·문서 규칙 확정, Google OAuth 앱 등록 |
| Day 2 | 인증 JPA Entity 구현, 로그인/회원가입 화면 레이아웃, JWT 정책 결정 회의 |
| Day 3 | 이메일 로그인 API + Google OAuth API, 화면 마무리 |
| Day 4 | 비밀번호 재설정 API (Google SMTP), 화면 API 연동, Postman 정리 |
| Day 5 | 인증 흐름 E2E 테스트, 버그 수정/버퍼, 6일차 보고 정리 |

정철진(본인)은 Frontend 전담이다. React + Next 구조 생성, App Router/Pages Router 결정, 로그인·회원가입·비밀번호 재설정 화면과 Auth API 연동이 Sprint 1 담당 범위다.

## 8. docs 폴더 운영 기준

| 폴더 | 용도 |
|---|---|
| `00-project/` | 공통 규칙, 운영 기준, `sprint-운영/` |
| `01-planning/` | 기획주간 raw archive (수정 금지) |
| `02-requirements/` | 사용자 시나리오, 기능 분해표, 추적표 |
| `03-design/` | 화면정의서, ERD |
| `04-api/` | API 명세서 |
| `05-architecture/` | Architecture, 기술 연구 |
| `06-meetings/` | 실제 회의록 |
| `07-decisions/` | ADR, 확정 결정, 보류 기능, 변경 이력 |
| `08-members/` | 팀원별 개인 작업 기록 (이 노트의 위치) |
| `assets/` | 이미지, PDF, PPTX 등 첨부 |

핵심 규칙은 다음과 같다.

- `01-planning/` 원본은 명시 요청 없이 수정하지 않는다.
- 상태가 `확정`인 문서는 사용자 확인 없이 수정하지 않는다.
- 최종본 승격은 이동이 아니라 canonical 폴더로 복사한다.
- 본인 폴더 외 타인의 `08-members/member-XX/` 문서는 수정하지 않는다.
