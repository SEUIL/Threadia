# 문서 그래프뷰 설계 메모

> docs-site(`threadia-kappa.vercel.app`)에 문서 간 연관관계를 그래프/시냅스 형태로 보여주는 기능을 붙이기 전, 어떤 방식으로 연관관계 데이터를 만들지 검토한 메모다. 구현 전 단계이며, 나중에 실제 작업할 때 참고용으로 정리했다.

---

## 1. 문제

지금 docs-site는 파일 검색만 있고, 문서가 서로 어떻게 연결돼 있는지 보여주는 기능이 없다. WBS&요구사항추적표 같은 새 문서가 늘어나면서 문서 간 관계를 시각적으로 보여주고 싶다는 요구가 나왔다.

`docs.ts`는 현재 frontmatter/blockquote에서 제목·작성자·상태·태그만 추출하고, 문서 간 연결 정보는 전혀 만들지 않는다. 실제 문서들도 서로 마크다운 링크로 연결된 경우가 거의 없고(`05-architecture/배포-호스팅-아키텍처-연구.md` 정도), 대부분은 표나 본문에 다른 문서 이름을 텍스트로만 언급한다(예: 요구사항추적표의 "기준 문서" 칸).

## 2. 검토한 방식과 기각 이유

| 방식 | 내용 | 기각/보류 이유 |
|---|---|---|
| 태그 공유 기반 그래프 | 같은 태그를 가진 문서끼리 연결 | 구현은 쉽지만 같은 태그면 다 연결돼서 노이즈가 많고 의미가 약함 |
| 문서 제목 텍스트 mention 파싱 | 본문에 다른 문서 제목이 텍스트로 등장하면 정규식으로 찾아 edge 생성 | fuzzy 매칭이라 약어/축약 표기에서 오탐·누락 발생, "정확한 규칙"을 원하는 목적에 안 맞음 |
| 본문 어디든 인라인 마크다운 링크 허용(`[text](path.md)`) | 사람이 본문에 링크를 직접 박으면 그걸 파싱 | 강제할 방법이 없음 — 빠뜨려도 검증할 수 없고, 빠뜨린 걸 잡으려면 결국 제목 텍스트 mention 파싱(위 방식)을 다시 끌어와야 함. 문서 이동/리네임 시 링크가 여러 문서 본문 곳곳에 흩어져 있어 일괄 수정도 어려움 |
| 전용 메타 필드 `관련 문서` (사람이 직접 채움) | 메타정보 블록에 다른 문서로의 링크 목록을 명시 | 검증은 쉽지만(필드 하나만 확인하면 됨), 사람이 매번 연관 문서를 찾아 적어야 해서 부담이 그대로 남음 |

## 3. 최종 방향 — AI가 작성 시점에 메타 필드를 채운다

사람이 직접 연관 문서를 찾아 적는 부담을 줄이기 위해, **AI가 문서를 작성/수정할 때 본문을 분석해 연관 문서를 찾고, 그 결과를 전용 메타 필드 `관련 문서`에 채워 넣는다**는 규칙으로 정리했다.

- 결과를 담는 위치를 메타 필드로 못박아서, AI의 탐색 과정은 fuzzy(semantic)하더라도 결과물은 항상 같은 자리에서 검증 가능하게 만든다.
- 빌드 스크립트는 `관련 문서` 필드에 적힌 상대경로가 실제로 존재하는지만 확인하면 된다 — 본문 전체를 다시 훑는 fuzzy 검증은 필요 없다.
- 역방향(backlink)은 사람이 양쪽에 다 적을 필요 없이, `docs.ts`가 전체 문서의 `관련 문서` 필드를 모아 빌드 시점에 자동 계산한다.

### 남은 약점 (인지하고 넘어가는 부분)

- AI 도움 없이 사람이 직접 문서를 쓰면 이 규칙이 적용되지 않는다. 100% 강제는 안 되고 "기본값"으로 받아들인다.
- 기존(레거시) 문서는 이 필드가 비어 있다. 나중에 한 번 전체 문서를 AI로 재스캔해서 `관련 문서`를 보강하는 일회성 backfill 작업이 필요하다.
- 이번 검토한 WBS&요구사항추적표 PDF처럼 `docs/` 바깥에 있는 자료는, 그래프에 넣기 전에 먼저 canonical `.md`로 옮겨 메타정보를 갖춰야 그래프 대상이 된다.

## 4. 나중에 구현할 때 할 일 (개략)

1. `문서-작성-규칙.md`에 "문서 간 참조 규칙" 섹션 추가 — `관련 문서` 메타 필드 정의, AI가 작성/수정 시 채워야 한다는 규칙, 필드 형식(`[표시텍스트](상대경로.md)` 목록) 명시.
2. `docs-site/src/lib/docs.ts`에서 `관련 문서` 필드 파싱 추가, 경로 존재 여부 검증(빌드 경고).
3. 전체 문서의 forward link를 모아 backlink map 계산.
4. 그래프 렌더링 — 새 라우트(예: `/graph`)에 force-directed graph 라이브러리(`react-force-graph` 또는 `d3-force`)로 node(문서)/edge(관련 문서) 시각화.
5. 레거시 문서 backfill — 기존 문서 전체를 AI로 재스캔해 `관련 문서` 채우는 일회성 작업.
6. WBS&요구사항추적표 PDF를 canonical `.md`로 이전(메타정보 포함)한 뒤 그래프 대상에 포함.

이 메모는 팀 합의 전 개인 설계 검토 단계이며, 실제 규칙 변경(`문서-작성-규칙.md` 수정)과 구현은 별도로 진행한다.
