# 2026-07-10 작업 기록 — WBS 3.4 Project Frontend 구현 (S04/S12) + PR #68/#70 리뷰

> 개인 작업 노트다. `feature/wbs-3.4-project-frontend` 브랜치에서 WBS
> 3.4.1~3.4.3(S04 프로젝트 목록, 생성 entry, S12 프로젝트 설정)을 실 API
> 연동했고, 같은 브랜치에서 이어서 WBS 3.3.4(Project Member API) 머지 후
> S12 멤버 관리(역할변경/제거)까지 마저 실 연동했다. 중간에 팀원 PR
> 2건(#68, #70)도 리뷰했다.

---

## 1. 배경 — WBS 3.2 이후 다음 범위 확정

WBS 3.2(회사 프론트) 완료 후 다음 범위를 WBS 시트와 `sprint-2-backlog.md`
대조로 확인했다. 3.4(Project Frontend)가 Owner 정철진으로 지정돼 있었고,
당시 진척률이 50%(mock 골격만 존재)였다. PR #61(목록/생성)과 PR #65(상세/
수정/archive)가 이미 머지돼 있어 실 연동이 가능한 상태였다.

## 2. Phase 1~6 — S04/S12 1차 실 연동

- `project.types.ts`/`project.service.ts`를 PR #61/#65 계약 기준으로
  신규 작성했다. `update()`는 `status`가 `@NotNull`인 full-replace라
  타입 시그니처에도 `Exclude<ProjectStatus, "ARCHIVED">`로 강제해뒀다.
- **S04(`projects/page.tsx`)**: 목록/생성 실 연동. 화면정의서 "주요
  데이터"에 명시된 멤버 수/이슈 수/PM은 `ProjectResponse`에 없어서
  카드에서 뺐다 — WBS 요구사항과 실제 API 사이 gap이라 화면정의서에
  인용구로 남겼다.
- **S12(`[projectId]/settings/page.tsx`)**: 정보 조회/수정/archive 실
  연동. `GET /projects/{projectId}`가 내려주는 `viewer.canManageProject`로
  실제 프로젝트 레벨 RBAC를 처음 썼다(그 전엔 `useCurrentCompanyRole()`의
  회사 role 근사치만 있었음). 멤버 관리 섹션은 WBS 3.3.4/4.3이 둘 다
  미착수라 인터랙션을 다 걷어내고 "준비 중" 안내로 대체했다 — 서버에
  반영 안 되는데 동작하는 것처럼 보이는 mock을 남기지 않기 위한
  판단이었다.
- COMPANY_ADMIN/MEMBER/비멤버(403) 4가지 role 시나리오를 실 DB 대조로
  검증하고 커밋(`b9e09ae`)했다.

## 3. gap의 원인을 문서로 추적 — sprint-2-backlog 서술 불일치

S04/S12에서 빠진 필드·액션이 단순 프론트 스코프 판단이 아니라 실제
문서 간 불일치에서 비롯됐다는 걸 확인했다. `sprint-2-backlog.md`의
"3.3 Project Backend" 작업 범위표는 프로젝트 멤버 API를 "권한 분리를
준비한다" 정도로만 서술하고 명시적 항목으로 다루지 않는데, "3.4 Project
Frontend" 작업 범위표는 화면정의서 문구를 그대로 인용해서 3.3이 실제로
약속하지 않은 백엔드 산출물을 프론트 요구사항으로 전제하고 있었다.
다만 3.4 완료조건 자체에 "API 미완료면 mock 범위와 전환 조건을 기록한다"는
탈출구가 이미 있어서, 이 gap을 화면정의서 인용구 + `기획문서-변경이력.md`로
정식 기록하는 것으로 처리했다(Phase 5, `#change-2026-07-09-project-frontend-member-stats-gap`).

## 4. PR #68 리뷰 — Department API 존재확인/권한확인 순서

팀원 PR(`fix/department-api-qa`, WBS 3.1.3 QA)을 리뷰했다. `DepartmentService.
list()/create()`에서 권한 확인이 존재 확인보다 먼저 실행되던 걸 "인증 →
존재 확인 → 권한 확인"으로 통일하는 2줄짜리 순서 교체였다. 격리된 git
worktree에서 `DepartmentServiceTest`를 직접 돌려 `BUILD SUCCESSFUL`
확인 후 approve. Company API(PR #66)에는 이미 적용된 패턴인데 Project
API(PR #61 list/create)는 아직 반대 순서로 남아있다는 점도 코멘트로
남겼다.

## 5. WBS 3.3.4(Project Member API) 머지 확인 — PR #70 딥 리뷰

`dev`를 최신화하다가 PR #70(Project Member API, WBS 3.3.4)이 머지된 걸
발견했다. `ProjectMemberController`(list/update/remove), `ProjectMemberService`,
관련 DTO/예외/repository를 전부 읽고 검증했다.

- API: `GET /projects/{projectId}/project-members`, `PATCH/DELETE
  /project-members/{projectMemberId}`. update는 `role`/`status` 둘 다
  `@NotNull` full-replace(company-member와 동일 패턴).
- 비즈니스 규칙: 마지막 활성 PROJECT_ADMIN 강등/제거 차단(비관적 락으로
  race condition도 방지), REMOVED 멤버 재활성화·승격 시 대상자가 여전히
  활성 회사 구성원인지 검증(자체 리뷰로 추가된 후속 커밋).
- **멤버 추가(POST) endpoint 자체가 없다** — WBS 4.3(Project Invitation,
  Sprint 3)과의 경계가 코드로 확인됨.
- 격리된 worktree에서 `ProjectMemberServiceTest`/`ProjectMemberControllerTest`
  직접 실행해 `BUILD SUCCESSFUL` 확인.

다음 세션에서 사용자가 "WBS 3.3.4가 완료로 표시돼 있는데 다시 확인해보자"고
해서, WBS 원문 완료조건("회사 구성원만 프로젝트 멤버가 되고 PROJECT_ADMIN
최소 1명 유지") 두 가지를 코드로 재대조했고 — 특히 "멤버 추가 endpoint가
없다"는 게 결함이 아니라 4.3과의 의도된 경계라는 걸 재확인 — 정확히
일치함을 확인했다.

## 6. Phase 7~9 — S12 멤버 관리 실 연동 (역할변경/제거)

3.3.4가 풀렸으니 S12의 "준비 중" placeholder를 실 연동으로 교체했다.

- `project-member.types.ts`/`project-member.service.ts` 신규 작성.
- S12 멤버 섹션: `viewer.canManageProject`인 사용자만 역할 select/제거
  버튼을 보게 게이트(서버 `requireProjectManage`와 동일 조건이라 UI에서
  숨긴 액션은 서버도 막음). `status=ACTIVE` 필터로 목록 조회, 제거된
  멤버는 목록에서 사라짐(복원 UI 없음). 멤버 추가는 여전히 "준비 중"
  안내로 남김.
- 브라우저 검증: 관리자 2명 시드해서 승격→성공, 마지막 관리자 강등
  시도→409("마지막 활성 프로젝트 관리자는 변경할 수 없습니다.") 정상
  차단, 정상 제거→DB에 `status=REMOVED`로 soft delete 확인, 비관리자
  (MEMBER) 뷰는 멤버 목록은 보이되 관리 컨트롤 전부 숨김.
- 화면정의서 S04/S12 인용구에 "2026-07-10 갱신" 내용 추가, 변경이력에
  새 항목(`#change-2026-07-10-project-member-frontend-integration`) 기록.

## 7. 통합점검 + 커밋

사용자 요청으로 전체 범위(3.4.1~3.4.3 + 오늘 추가분)를 한 번에 재검증했다.

- `npx tsc --noEmit`/`npx eslint`(변경 파일 전체) 클린.
- 실제 사용자 진입 경로 그대로 end-to-end 확인: `/projects` 빈 목록 →
  생성 → 카드 클릭(`/graph` 진입 확인) → 프로젝트 탭 "설정" 클릭 →
  정보/멤버/아카이빙 섹션 확인 → 아카이빙 → "← 프로젝트 목록"으로 복귀
  → 카드가 "보관됨" 상태로 정상 표시. 콘솔 에러 없음.
- 커밋 2개로 나눠 반영: `b9e09ae`(Phase 1~6, S04/S12 1차 연동),
  `2618a1d`(Phase 7~9, 멤버 관리 실 연동). 그 사이 `dev` 두 차례
  merge(`5a59ede`) — 화면정의서/변경이력 문서 충돌만 발생, 코드 충돌은
  없었다(같은 날 다른 팀원의 "Project detail viewer 응답 계약" 문서
  PR과 삽입 위치만 겹침).

  가능해졌지만 프로젝트마다 별도 호출이 필요해 N+1 문제가 있다 — 별도
  설계 필요, 이번엔 손대지 않음.

  제외.

  여전히 제외.
