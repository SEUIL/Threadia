### 1.1 테두리 과사용 정리

`border-border`가 15개 파일에서 67회 쓰이며 리스트 행마다 개별 박스를 두르는
"네모 상자 우리(cage of rectangles)" 패턴이 있었다(리서치 근거는 기술연구
문서 참고). 화면별로 다음 두 패턴으로 정리했다.

- **반복 리스트**(백로그 이슈, 문서 목록, 구성원, 알림, DM 목록, 부서 등):
  행마다 있던 `rounded-lg border border-border`를 없애고, 리스트 전체를
  `divide-y divide-border`로 감싸는 방식으로 바꿨다.
- **독립 카드형 엔티티**(프로젝트 카드, 칸반 이슈 카드, 문서 목록 행):
  `border` + `shadow-sm` 중복을 없애고 `shadow-sm`(hover 시 `shadow-md`)만
  남겨 "떠 있는 카드" 느낌으로 통일했다.
- **섹션 컨테이너**(프로젝트 정보, 부서 목록 등 단일 카드): `border`만 남기고
  중복이던 `shadow-sm`을 뺐다.

### 1.2 Aurora 정체성 확장 (B안 확정)

디자인이 "어디서 본 것 같은 AI스러운 느낌"이 든다는 문제의식에서 출발해
레퍼런스를 찾아본 뒤, 로고/버튼/배지 모양을 3가지 방향(구조적·Aurora강화·
에디토리얼)으로 만들어 비교했다. 사용자가 **B안(Aurora 정체성 강화)**을
확정했고, 그라디언트는 `teal 0% → violet 100%` 선형(v1)으로 정했다(중간에
violet이 정점을 찍는 v2 버전도 만들어 나란히 비교했으나 v1이 더 낫다는
판단).

적용 범위는 사용자가 명시적으로 좁혔다 — **로고 + 주요(primary) CTA 버튼까지만**.
배지·아바타 채우기·채팅 말풍선은 노이즈가 커질 수 있어 제외했다(배지는
끝까지 그대로 뒀고, 아바타는 아래 1.3에서 별도로 "채우기 대신 링"으로
절제해서 반영).

`globals.css`에 `@layer components`로 두 클래스를 추가했다.

```css
.text-gradient-brand { /* 로고 워드마크 전용 */ }
.btn-gradient { /* 주요 CTA 버튼 전용, hover는 filter: brightness */ }
```

`(auth)/layout.tsx`의 로고 워드마크, `HubOverlay`의 상단바 로고(+ 아이콘 마크
추가로 auth 화면과 통일), 그리고 `bg-primary` + `hover:bg-primary-hover`
조합으로 쓰이던 주요 버튼 14곳(로그인/회원가입 제출, 새 프로젝트/스프린트/
문서 생성, 저장, 초대 등)을 `btn-gradient`로 교체했다.

### 1.3 타이틀 자간 + 아바타 그라디언트 링

- `h1` 전체에 `-0.02em` 자간을 공통 적용했다(레퍼런스: Linear 디자인 시스템의
  display 타이포 음수 자간). 화면마다 각각 안 고치고 `globals.css` base
  레이어 한 줄로 전체 반영했다.
- 아바타(허브 상단바, DM 목록/채팅방, 구성원 목록 4곳)를 `bg-primary` 통 채우기
  대신 `avatar-ring`(흰 배경 + 얇은 teal→violet 그라디언트 테두리)으로
  바꿨다. 아바타·배지처럼 반복되는 소형 요소는 채우기보다 테두리 쪽이
  노이즈가 덜하다는 판단을 버튼/로고 작업과 같은 기준으로 적용했다.
- 그라디언트 버튼의 `disabled:opacity-70` 상태도 점검했다 — opacity가
  그라디언트 전체에 균일하게 걸려서 색이 깨지지 않고 자연스럽게 흐려지는 것을
  확인했다(코드 수정 불필요).

### 1.4 지속 사이드바+상단바 (AppShell) — 이번 세션에서 가장 큰 작업

기존에는 허브(3D 화면)에만 `HubOverlay`(사이드바+탑바)가 있고, 그 밖의 모든
화면(`/projects`, `/board`, `/backlog`, `/docs`, `/dm`, `/settings`,
`/members`, `/notifications` 등)은 "← 뒤로가기" 텍스트 링크 하나뿐인 독립
페이지였다. 예를 들어 칸반 보드를 보다가 DM을 확인하려면 반드시 허브로
돌아갔다가 다시 들어가야 했다 — Slack/Notion/Linear류 B2B SaaS의 "항상
보이는 좌측 사이드바" 관습에서 크게 벗어난 구조였다.

`components/app-shell/AppShell.tsx`를 새로 만들어 이 공백을 메웠다.

- **사이드바**: 로고, 프로젝트/채팅·DM/알림/회사 관리 내비게이션. 현재
  경로 기준 active 상태 표시. `md:` 이상에서만 노출(모바일은 숨김 — 반응형
  햄버거 메뉴는 이번 범위 밖으로 남겨뒀다).
- **상단바**: 회사명, 알림·DM 아이콘 바로가기(뱃지), 사용자 아바타
  (`avatar-ring` 재사용), 로그아웃.
- Next.js 라우트 구조상 `app/(app)/[companyId]/layout.tsx`(원래 있던 빈
  패스스루 stub)에서 `AppShell`로 `children`을 감싸는 방식으로 적용했다.
  `hub`, `invitations`는 `[companyId]` 경로 밖에 있어 영향받지 않고, 허브는
  기존 3D 오버레이를 그대로 유지한다.

## 2. 발생한 문제와 해결

### 2.1 새 Tailwind 유틸리티 클래스가 반영 안 됨 (Turbopack 재스캔 캐시)

`divide-y`, `divide-border`를 처음 도입했을 때 브라우저에서 `border-bottom-width: 0px`로
확인돼 전혀 적용이 안 된 것처럼 보였다. `preview_inspect`로 실제 stylesheet에
`divide-y` 관련 규칙 자체가 생성 안 된 걸 확인했다 — 이전 세션에서 이미
기록된 "새로 등장하는 유틸 클래스는 Turbopack이 재스캔을 안 한다"는 문제와
동일했다. 서버 중지 → `.next` 삭제 → 재시작으로 해결했다. `avatar-ring`,
`btn-gradient` 같은 새 클래스를 추가할 때마다 같은 절차를 반복했다.

### 2.2 스크린샷 도구가 실제 레이아웃을 왜곡해서 보여줌

리서치 단계에서 스크린샷만 보고 "컨테이너 폭이 너무 좁고 왼쪽에 쏠려있다",
"칸반 컬럼이 좁다", "배지 색이 톤온톤이다"라고 진단했는데, `preview_inspect`로
실제 DOM의 `boundingBox`/`computedStyle`을 직접 재보니 전부 정상이었다(1440px
화면에서 좌우 336px씩 정확히 중앙 정렬, 칸반 컬럼은 1392px를 5등분해서
262px씩, 배지 색도 회색/보라/주황/빨강으로 이미 잘 구분됨). 스크린샷 도구가
실제 브라우저 렌더링과 다른 축소 렌더링을 보여준 것으로 보인다. **스크린샷은
"눈으로 훑어보는 용도"로만 쓰고, 폭/정렬/색 같은 정확한 수치 판단은 반드시
`preview_inspect`나 `getComputedStyle`로 재검증**해야 한다는 교훈을 얻었다.
이 삽질 덕분에 진짜 문제(테두리 과사용)만 남기고 잘못된 진단(컨테이너 폭,
배지 색)은 사용자에게 정정해서 알렸다.

### 2.3 `sed` 일괄 치환이 주석 문구까지 건드림

`bg-primary` + `hover:bg-primary-hover` 조합을 `btn-gradient`로 일괄
치환할 때 `sed`로 파일 14개를 한 번에 처리했는데, `globals.css`의 주석
문장("주요 CTA 버튼 전용 — bg-primary + hover:bg-primary-hover 대체")도
같은 패턴에 걸려 "btn-gradient + 대체"로 깨졌다. 다음 커밋에서 발견해
바로잡았다. **문자열 치환을 코드 전용이 아니라 파일 전체에 걸 때는 주석도
같이 걸린다는 걸 항상 염두에 둬야 한다.**

### 2.4 preview 도구의 세션 유지 불안정 (기존에 알려진 문제 재확인)

`window.location.href`로 중첩 라우트에 반복 이동하다 보면 실제로는 계정이
정상 인증된 상태(`POST /auth/refresh → 200` 확인)인데도 화면이 `/login`으로
튕기는 현상이 여러 번 있었다. 실제 로그인 API를 fetch로 직접 호출해 세션
쿠키가 정상 세팅되는 것도 확인했고, 이후 클릭 기반 네비게이션으로 전환하니
문제없이 재현됐다 — 이전 세션에 기록된 "preview_eval로 중첩 라우트에 직접
이동할 때 가끔 튀는" 도구 결함과 동일한 것으로 판단하고, 실제 앱 버그로
보지 않았다.
