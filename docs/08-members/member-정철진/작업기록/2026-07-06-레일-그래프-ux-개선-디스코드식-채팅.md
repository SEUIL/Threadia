## 1. 오전 — AppShell → RailShell 교체 + 그래프 뷰 승격 (PR #38)

### 1.1 배경과 전제 확인

전날 `frontend/design-sample`에서 만든 D안(레일+플라이아웃 + 상단바 제거 +
하단 플로팅 커맨드바 + 이슈/문서/채팅 통합 그래프)이 마음에 들어서, 조심스러운
파일럿 방식이 아니라 **전면 적용**으로 진행하기로 했다. 시작 전 확인한
전제 두 가지:

- 이슈/문서/채팅은 Sprint 1 기준 전부 mock(컴포넌트 로컬 state)이고 실 API가
  없다(Sprint 1 = Auth only). 그래서 이 작업은 **백엔드 연결 상태와 완전히
  무관한 순수 프론트 구조 변경**이었다 — 오히려 API가 붙기 전인 지금 하는 게
  나중에 갈아엎는 것보다 리스크가 낮다고 판단했다.
- 실제 코드를 조사해보니 `docs/page.tsx`(S07)에 이미 문서+이슈 SVG 그래프
  뷰(2종, 원형 노드, 2열 고정 좌표, pan/zoom 없음) + 우측 디테일 패널이
  구현돼 있었다 — 이걸 확장하는 쪽이 새로 만드는 것보다 합리적이라고 봤다.

확정된 범위(사용자 확인 완료): 사이드바 교체는 **전면적**(모든 (app) 화면에
동일 적용), 칸반보드/채팅은 **독립 화면으로 유지**하되 그 데이터가 통합
그래프 뷰에도 함께 보인다.

### 1.2 작업 단위별 진행

1. **RailShell 구현**: `components/app-shell/AppShell.tsx`를 삭제하고
   `RailShell.tsx`(hover 시 펼쳐지는 아이콘 레일 + 상단바 제거 + 하단 플로팅
   커맨드바)로 교체. `app/(app)/[companyId]/layout.tsx` 한 곳만 바꿔서
   board/backlog/docs/messages/members/settings 등 모든 화면에 전면
   적용했다.
2. **통합 그래프 데이터 모델**: `docs/page.tsx`의 `GraphNode`(`kind: "doc" | "issue"`)를
   `kind: "issue" | "doc" | "chat"`로 확장. `messages/page.tsx`의 mock과는
   별개로 그래프 전용 채팅 노드 mock(`MOCK_CHATS`)을 추가했다.
3. **타입 필터 + 검색**: 색상 매칭 필터 칩(문서=teal/이슈=violet/채팅=aqua,
   기존 이 화면의 원색 관례를 그대로 따름) + 제목 검색을 AND 조건으로
   연동했다.
4. **좌표 자동배치**: `layoutColumn()` 헬퍼로 종류별 열 배치, 노드가 많아지면
   서브열로 줄바꿈해서 캔버스 높이가 무너지지 않게 했다.
5. **디테일 패널 3분기**: 우측 서랍 패널이 문서/이슈/채팅 각각 다른 내용을
   보여주게 확장했다.
6. **전체 화면 chrome 교체 검증**: 실제로 로그인해서 board/docs/backlog/
   messages/dm/members/settings/notifications 9개 화면을 순회 확인. 이
   과정에서 버그 2개를 발견해서 같이 고쳤다:
   - 새 theme 토큰(`--color-chrome*`)을 처음 쓸 때 Turbopack이 캐시를 안
     갈아치워서 이미 고친 코드인데 옛날 에러가 계속 남 → `.next` 삭제 후
     재시작으로 해결(env-tooling-notes에 이미 있던 패턴).
   - `messages/page.tsx`, `dm/[roomId]/page.tsx`가 `h-screen`으로 자체
     전체높이를 잡고 있어서 새 하단 플로팅 커맨드바와 메시지 입력창이
     겹침 → `h-full`로 교체해 부모 `<main>`의 예약 공간을 존중하게 했다.
7. **프로젝트 진입점 공백 발견/수정**: 검증 도중 사용자가 "일부 화면이
   진입점 자체가 없다"고 지적했다. 조사해보니 프로젝트 카드가 `/board`로만
   연결되고 그 안에서 backlog/docs/messages/settings로 갈 방법이 화면
   자체엔 없었다(원래부터 있던 공백이지 이번 회귀가 아니었다). 빈 통과
   래퍼였던 `[projectId]/layout.tsx`에 sticky 탭 내비게이션(보드/백로그/
   문서/채팅/설정)을 추가해서 해결했다.
8. **그래프 뷰를 프로젝트 메인 화면으로 승격**: 여기서 사용자가 "그래프
   뷰를 메인화면 느낌으로 박으면 임팩트가 좋겠다"고 요청. `docs/page.tsx`
   안 탭이었던 그래프 뷰를 `graph/page.tsx`로 독립시키고, 프로젝트 카드
   링크를 `/board` → `/graph`로 바꿔서 프로젝트 진입 시 기본으로 보이는
   화면으로 만들었다. 탭 순서도 그래프를 맨 앞으로. 공유 목업 데이터/타입은
   `graph/mockGraphData.ts`로 분리해서 `docs/page.tsx`(이제 목록만 남음)와
   함께 쓴다.
9. **노드를 카드형으로 재디자인**: 사용자가 실제 스크린샷(배지+제목이 있는
   둥근 카드, 점선 연결, 점 그리드 배경)을 레퍼런스로 줌 — "원형 노드는
   조잡하다"는 피드백. SVG `<circle>`을 절대위치 HTML 카드(배지 pill + 제목)
   로 교체하고, 카드 폭에 맞춰 `CARD_WIDTH`/`COLUMN_BASE_X`/`ROW_HEIGHT`
   등 배치 상수를 재조정했다.
10. **화면정의서/프론트엔드 구조 문서 갱신**: `docs/03-design/화면정의서.md`는
    상태가 "확정"인 팀 공유 문서라, 표 내용을 직접 덮어쓰지 않고 인용구
    메모로 실제 구현과의 차이를 표시했다 — 특히 **S04(프로젝트 목록)의
    진입점이 팀 확정 스펙("S04→S05 칸반 보드로 바로 진입")과 다르게
    구현됐다는 점**(S04→그래프)을 명시적으로 플래그해뒀다. 팀 규칙에 따라
    `docs/07-decisions/기획문서-변경이력.md`에 변경 묶음도 추가했다.
    `docs/05-architecture/프론트엔드-구조.md`(본인 작성, "작성 중" 상태)는
    확정 문서가 아니라 바로 갱신했다.
11. **커밋 + PR + 머지**: 위 내용을 커밋 하나로 묶어 PR #38을 올렸고,
    본인이 부팀장 bypass 권한으로 직접 머지했다. 이후 `dev` fast-forward
    pull, 브랜치 로컬/원격 삭제, 메모리(`threadia-현재-작업-상태`) 갱신까지
    마쳤다.

### 1.3 그 밖에 오전에 짚었던 것 — 알림 화면 분리 여부

작업 중 "프로젝트 단위 알림 화면도 있는데 나눠놓을 이유가 없지 않냐"는
질문이 나왔다. 확인해보니 `[companyId]/notifications/page.tsx`(실제 구현)
쪽 주석에 이미 답이 있었다 — 화면정의서 S11이 "MVP는 GLOBAL scope만 허용,
PROJECT scope는 보류"로 확정해둬서, `[projectId]/notifications`는 내용
없는 스텁으로 **의도적으로** 남겨진 자리였다. 실제로 알림 진입은 레일의
"알림" 링크(`/{companyId}/notifications`) 하나로 이미 잘 되고 있었고
(스크린샷으로 직접 확인), 프로젝트 탭 바에도 이 스텁을 넣지 않았으니
결론은 "이미 의도한 대로 되어 있음 — 코드 변경 불필요"였다. 파일 자체는
PROJECT scope가 나중에 열릴 때를 대비해 그대로 뒀다.

## 2. 오후 — 플로팅 커맨드바 제거 → 레일 하단으로 이동

하단에 떠 있던 플로팅 커맨드바(알림/DM/아바타/로그아웃)가 화면마다 콘텐츠와
겹치는 문제가 계속 나왔다. 원인을 보니 알림/DM 아이콘은 레일 nav에도 이미
있던 중복이었다 — 그래서 커맨드바 자체를 없애고 아바타+로그아웃만 레일
하단(`mt-auto`)으로 옮겼다. 레일은 항상 고정된 좁은 컬럼이라 콘텐츠와 겹칠
여지가 구조적으로 없어져서, 화면마다 일일이 여백을 맞출 필요가 없어졌다.
`<main>`의 `pb-24`(커맨드바 공간용 여백)도 같이 정리했다.

## 3. 그래프 뷰 UX 개선

1. **스크롤바 → 드래그 팬**: 캔버스에 스크롤바가 생기던 걸 없애고
   (`overflow-auto` → `overflow-hidden`), 빈 캔버스 영역을 마우스로 눌러
   드래그하면 `transform: translate()`로 캔버스 전체가 이동하게 바꿨다.
2. **휠 확대/축소**: 마우스 커서가 가리키는 지점을 고정한 채(`onWheel`에서
   커서 좌표 기준으로 pan을 같이 보정) 0.4x~2x 범위로 확대/축소되게 했다.
3. **노드 드래그 이동**: 카드형 노드를 각각 마우스로 드래그해서 옮길 수 있게
   했다. `layoutColumn()` 계산 위치를 기본값으로 두고, 드래그하면
   `positions` state에 override로 저장한다. 실제로 3px 이상 움직였는지로
   "드래그"와 "클릭 선택"을 구분해서, 드래그 후에는 선택(우측 패널 오픈)이
   안 되고 순수 클릭만 선택되게 했다.
4. **자동 정렬 버튼**: 드래그로 흐트러진 위치와 pan/zoom을 한 번에 초기
   `layoutColumn()` 배치로 되돌리는 버튼을 필터/검색 줄에 추가했다.

세 기능 모두 노드 위에서 mousedown이 시작됐는지(`e.target === canvasSurfaceRef.current`
체크)로 pan과 노드 드래그를 구분해서 서로 안 부딪히게 했다.

## 4. 채팅/DM 레이아웃을 디스코드 참조로 리뉴얼

사용자가 실제 디스코드 스크린샷을 캡처해서 레퍼런스로 줬다 — "이미 검증된
방식으로 가자"는 게 이유였다. 기존 말풍선 스타일 채팅은 조잡하다고 판단해서
전면 교체했다.

### 4.1 프로젝트 채팅 (`messages/page.tsx`)

- 좌측에 가짜 단일 채널 목록("# 프로젝트 채팅" 항목 1개) + 하단 유저 미니바.
  Threadia는 아직 프로젝트당 채팅 채널이 1개뿐이라(멀티 채널 개념 없음)
  실제 여러 채널을 담을 수는 없지만, 디스코드와 시각적으로 맞추기 위해
  형태만 가짜로 만들었다 — 멀티채널 API가 생기면 그때 목록을 채운다.
- 메시지 목록을 말풍선 대신 아바타+이름+시각 헤더 뒤에 본문이 이어지는
  flat 스타일로 바꾸고, 연속된 같은 작성자 메시지는 헤더를 생략(그룹핑)했다.
  hover 시 "+ 이슈로 만들기" 액션이 노출된다.
- 우측에 온라인/오프라인 멤버 목록(mock)을 추가했다.
- 컴포저도 rounded pill 형태로 다시 잡았다.

### 4.2 1:1 DM

메시지 리스트 스타일은 프로젝트 채팅과 동일하게 맞추되, 채널목록/멤버목록은
빼고(DM은 1:1이라 그 역할이 필요 없음), 대신 **DM 목록 화면(`/dm`) 자체를
없앴다**. 원래는 "직사각형 방 목록 클릭 → 채팅방 이동"의 2단계 구조였는데,
디스코드의 서버 아이콘 목록을 참고해서:

- `dm/layout.tsx`에 대화 상대 아바타를 디스코드 서버 아이콘처럼 세로로
  나열하는 레일을 추가하고, 아이콘 클릭 한 번으로 대화가 바로 전환되게 했다
  (Next.js 클라이언트 사이드 전환이라 페이지 전체가 다시 로드되지 않는다).
- `/{companyId}/dm`(인덱스)은 이제 목록을 보여주는 대신 첫 번째 대화방으로
  즉시 리다이렉트한다.
- 방 목업 데이터(`dm/mockRooms.ts`)를 레일과 방 화면이 공유하도록 분리했고,
  겸사겸사 본인(정철진)이 DM 대상 목록에 끼어있던 것도 제외했다.

## 5. 공용 페이지 전환 애니메이션

라우트가 바뀔 때마다 콘텐츠가 페이드인 되는 연출을 공용으로 추가했다.
`components/app-shell/PageTransition.tsx`를 새로 만들었는데, 새 애니메이션을
발명하지 않고 `globals.css`에 이미 있던 `animate-enter`(카드 진입 등에 쓰던
fade + translateY 0.75rem, 300ms ease-out)를 그대로 재사용했다.
`usePathname()`으로 `key`를 걸어서 라우트가 바뀔 때마다 강제로 리마운트해
매번 재생되게 했고, RailShell의 `<main>` 안에 적용해서 허브를 제외한 모든
화면에 자동 적용된다. `h-full`을 유지해서 messages/dm처럼 내부 flex-col
레이아웃에 의존하는 화면들이 안 깨지게 했다.

## 6. 허브(3D 화면) chrome도 레일 스타일로 통일

RailShell로 다른 화면은 다 바꿨는데, 허브의 `HubOverlay`(3D Canvas 위에 얹는
HTML 오버레이)는 옛 AppShell 스타일(상단바 + 좌측 박스 메뉴) 그대로 남아있던
마지막 자리였다. 그래서 이것도 레일 스타일로 다시 스킨했다.

`<RailShell>`을 그대로 씌우지는 않았다 — RailShell은 실제 flex 레이아웃이라
씌우면 Canvas 폭이 레일 너비만큼 줄어서 카메라 구도가 틀어진다. 대신 오버레이
구조(Canvas는 항상 풀스크린, HTML은 `position: absolute`로 위에 얹는 방식)는
그대로 두고, 내용물(로직/스타일)만 RailShell의 Rail과 동일하게 맞춘
`HubRail` 컴포넌트로 새로 짰다. 배경색(navy)은 나중에 다시 다듬을 예정이라
지금은 RailShell과 같은 값을 그대로 가져다 썼다.

## 7. 검증

전부 실제 로그인해서 브라우저로 확인했다:
- 그래프: 드래그 팬(마우스 좌표 델타만큼 정확히 이동 확인), 휠 줌(scale 값
  변화 확인), 노드 드래그(드래그 후 위치 변경 + 선택 안 됨, 순수 클릭 시
  선택 확인), 자동 정렬(초기 위치/pan/scale로 정확히 복귀 확인).
- 채팅: 메시지 그룹핑, 전송, hover 액션 노출 확인.
- DM: 아이콘 클릭 시 URL과 대화 내용이 즉시 바뀌는 것 확인.
- 페이지 전환: `animate-enter` 클래스와 실제 computed animation-name/duration
  확인, `h-full` 체인이 깨지지 않는지(메시지 컴포저 위치) 확인.
- 허브: Canvas가 여전히 풀스크린(1440x900)인지, 레일 배경색/링크/로그아웃
  버튼이 정상 동작하는지 확인.

이 과정에서 이 컴퓨터 환경의 알려진 도구 이슈(세션이 이유 없이 `/login`으로
튕김, `preview_screenshot` 타임아웃, `preview_resize` 후 viewport가 0x0으로
깨짐)를 여러 번 다시 만났다 — 전부 [[env-tooling-notes]]에 이미 기록된
것들이라 재로그인/리사이즈로 우회했다. 새로 배운 건 없어서 메모리에 추가로
남기지 않았다.
