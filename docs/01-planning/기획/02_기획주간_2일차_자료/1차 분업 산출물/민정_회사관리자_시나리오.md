> **기준 문서:** 화면정의서 S01 ~ S14

| 구분 | 이름 | 플랫폼 역할(코드) | 담당 |
|------|------|-----------------|------|
| 대표 | 황스일 | 회사 관리자 (C) | 회사 전체 관리, 프로젝트 생성, PM 지정 |

> └─ 여도현 (P) → 김태준 (A)

## 배경 — 기존 Jira + Confluence + Slack 조합에서 대표 관점의 문제

```
기존 상황
│
├─ 현황 파악에 앱 순례 필요
│     └─ 프로젝트 A 보드(Jira) → 프로젝트 B 보드(Jira) → 문서 공간(Confluence)
│         → 슬랙 채널(Slack) → 어드민 패널 3개
│         → 대표가 하루 업무 시작 전 도구 5개를 순서대로 열어야 함
│
├─ 신규 팀원 온보딩에 3중 설정 필요
│     └─ Jira 어드민 권한 설정
│         + Confluence 공간 접근 권한 설정
│         + Slack 채널 초대
│         → 동일 인물에게 동일 작업 3번 반복
│
├─ 프로젝트 간 맥락 단절
│     └─ 프론트엔드팀의 기술 결정이 백엔드팀에 영향을 주어도
│         대표는 각 Slack 채널을 개별적으로 팔로우해야 인지 가능
│
└─ 의사결정 맥락 소실
      └─ Slack에서 나눈 중요한 결정이 Jira 이슈에 귀속되지 않음
          → "왜 이 결정이 났나요?" → Slack 대화 수백 개를 뒤져야 함
```

## 2단계 — 구성원 관리 (회사 레벨)

> ⚠️ **구성원 관리 두 단계 구분**
>
> | 단계 | 화면 | 목적 |
> |------|------|------|
> | ① 회사 구성원 등록 | S13 → S14 | 팀원을 회사 플랫폼 계정에 추가하고 전사 역할 부여 |
> | ② 프로젝트 멤버 초대 | S12 | 등록된 회사 구성원을 특정 프로젝트에 배정 |
>
> 이 단계는 ① 회사 구성원 등록이며, 프로젝트 배정(②)은 3단계에서 진행.

```
│     └─ 좌측 관리 메뉴 → '구성원' 클릭 → S14로 이동

├─ [S14 구성원·권한 관리] ── 팀원 초대
│     ├─ '+ 구성원 초대' 클릭 → 이메일 초대 모달

│     │     ├─ 여도현 (yeo@techflow.com) 초대 발송
│     │     ├─ 김민정 (minjung@techflow.com) 초대 발송
│     │     ├─ 김민경 (minkyung@techflow.com) 초대 발송

      ├─ "프로젝트 관리자" 탭: 정철진 · 여도현 (2명)
      └─ "일반 사용자" 탭: 김민정 · 김민경 · 김태준 (3명)
            ※ 일반 사용자는 프로젝트 생성 권한 없음
               프로젝트 생성은 회사 관리자(C) · 프로젝트 관리자(P)만 가능
```

## 4단계 — PM 인수 후 팀 운영 흐름 (위임 이후 배경 흐름)

> 황스일 대표는 이 단계에 직접 개입하지 않음.  
> 아래는 PM과 팀원이 수행하는 흐름으로, 대표가 다음 단계(모니터링)에서 결과를 조회.

```
PM 인수 후 팀 운영
│
├─ [S06 백로그/스프린트] ── 정철진 / 여도현 PM 수행
│     ├─ 스프린트 생성 (P/C 전용)
│     ├─ 백로그에 이슈 추가 후 스프린트에 배정
│     └─ '스프린트 시작' 클릭 → 팀원 전체에게 알림 자동 발송 (S11)
│
├─ [S05 칸반 보드] ── 팀원(A) 이슈 처리
│     ├─ 이슈 카드를 To Do → In Progress → Done 으로 이동
│     └─ 카드 내 '쓰레드 버튼' 클릭 → S10 이슈별 토론
│
├─ [S10 쓰레드] ── 이슈 단위 맥락 보존
│     ├─ 상위 컨텍스트 배너: 연결된 이슈 제목 · 담당자 · 상태 표시
│     └─ 이슈마다 논의가 귀속되어 나중에도 맥락 추적 가능
│
└─ [S09 채팅 (DM)] ── 팀 내 빠른 소통
      └─ 쓰레드 → 채팅 전환 시 쓰레드 요약 배너 자동 표시
            → 이전 논의 맥락을 잃지 않고 대화 이어감
```

## 5단계 — 황스일 대표의 진행 현황 모니터링

```
프로젝트 진행 모니터링 (대표 관점)
│
├─ [S11 알림] ── 매일 아침 진입점
│     ├─ 유형별 탭 필터: 전체 / @멘션 / 이슈 / 채팅 / 시스템
│     ├─ 읽지 않은 알림 강조 표시로 이상 신호 선별
│     │     ├─ "정철진이 Sprint 1을 시작했습니다"
│     │     ├─ "여도현이 'DB 스키마 설계' 이슈를 Done으로 이동"
│     │     └─ "@황스일 대표님 — 프론트엔드 팀 외부 API 연동 블로커 발생"
│     └─ 알림 클릭 → 해당 프로젝트의 이슈·쓰레드로 직접 이동
│           ※ 기존: Jira 알림 + Slack 알림 + Confluence 알림 앱 3개 교차 확인
│              현재: S11 탭 하나에서 두 프로젝트 이벤트 통합 수신
│
├─ [S04 프로젝트 목록] ── 전체 프로젝트 현황 조망
│     ├─ "CoWork 프론트엔드 개발" 카드
│     │     └─ 상태 뱃지: 진행중 | 멤버: 3명 | 이슈: 14개
│     ├─ "CoWork 백엔드 API 개발" 카드
│     │     └─ 상태 뱃지: 진행중 | 멤버: 2명 | 이슈: 9개
│     └─ 두 카드가 같은 화면에 나란히 표시
│           → 프로젝트 간 현황을 즉시 비교 가능
│           ※ 기존: Jira 프로젝트 보드 A → 뒤로 → 보드 B → 현황 수동 합산
│              현재: 카드 목록 한 화면에서 전체 포트폴리오 조감 가능
│
├─ [S05 칸반 보드] ── 프론트엔드 팀 이슈 현황 열람 (관찰자 모드)
│     ├─ "CoWork 프론트엔드 개발" 카드 클릭 → S05 진입
│     ├─ To Do / In Progress / Done 컬럼 분포 확인
│     │     └─ In Progress 컬럼에 카드 집중 → 병목 가능성 인지
│     └─ 이슈 카드 → '쓰레드 버튼' 클릭 → S10 쓰레드
│           ├─ 상위 컨텍스트 배너로 이슈 상황 즉시 파악
│           └─ 팀의 토론 맥락을 읽으며 현황 파악 (직접 수정 없음)
│
└─ [S06 백로그/스프린트] ── 백엔드 팀 스프린트 현황 열람
      ├─ "CoWork 백엔드 API 개발" → S06 진입
      ├─ 스프린트 섹션: Sprint 1 이슈 목록 · 상태 뱃지 · 기간 확인
      └─ 백로그 섹션: 미배정 이슈 잔량 확인
            → 다음 스프린트 업무량 과부하 여부 선제 파악
```

## 6단계 — 이슈 발생 시 대표의 개입 방식

```
이슈 대응 (대표 관점)
│
├─ [S11 알림]
│     └─ "@황스일 대표님 — 외부 OAuth API 계약 필요, 결정 요청"
│         알림 클릭 → S05 칸반 보드 해당 카드로 이동
│
├─ [S10 쓰레드] ── 맥락 파악 및 의사결정
│     ├─ 상위 컨텍스트 배너: "소셜 로그인 구현 | 담당: 김민정 | In Progress"
│     ├─ 이슈 쓰레드에 쌓인 정철진·김민정의 논의 내용 열람
│     │     → 이전 맥락을 단번에 파악
│     └─ 황스일 대표 → 쓰레드에 코멘트 입력
│           "외부 OAuth 계약이 필요하면 구매팀에 공유하겠습니다.
│            이번 주 안으로 확인 후 진행 여부 알릴게요."
│           ★ 대표의 결정이 이슈 맥락에 귀속
│              나중에 "왜 이 결정이 났나요?" → 쓰레드 하나로 답변 가능
│              ※ 기존: Slack 메시지로 전달 → Jira 이슈에 기록 없음
│                       → 의사결정 맥락이 Slack 대화 속에 소실
│
└─ [S09 채팅 (DM)]
      └─ 황스일 → 정철진에게 DM
            "소셜 로그인 이슈 쓰레드에 방향 코멘트 남겼어요.
             확인하고 팀원들한테 공유해주세요."
            └─ 쓰레드 요약 배너가 채팅 상단에 자동 표시
                → DM에서도 이전 이슈 맥락을 잃지 않고 대화 이어감
```

```
회사 전체 현황 관리
│
├─ [S13 회사 관리] ── 주기적 현황 점검

│     │     ├─ 총 구성원: 6명
│     │     ├─ 부서 수: 2개
│     │     └─ 프로젝트 수: 2개 (진행중)
│     ├─ 부서 목록 테이블
│     │     ├─ 프론트엔드 팀: 인원 3명 (정철진 · 김민정 · 김민경)

│     │     └─ 김민정 → 드롭다운 → "프로젝트 관리자"로 격상 (3번째 PM)

│           "프로젝트 관리자" 탭: 정철진 · 여도현 (· 김민정 격상 후 3명)
│
└─ [S04 프로젝트 목록] ── 포트폴리오 관리
      ├─ 스프린트 종료 후: 프로젝트 카드 상태 뱃지 변화 확인
      ├─ 신규 프로젝트 필요 시: '+ 새 프로젝트' 클릭
      └─ 전체 카드: 진행중 · 완료 · 준비중 뱃지로
            회사 전체 포트폴리오 현황을 한 화면에서 파악
```

## [별도 정리] 설계 보완 필요 및 미구현 기능

### A. 화면설계 보완이 필요한 항목 (구현 검토 권장)

| 항목 | 현재 상태 | 보완 방향 |
|------|----------|----------|
| 회사 정보 등록 화면 | S13에 조회 카드만 있음 | 회사명 · 대표명 · 로고 · 업종 등을 등록·수정하는 전용 폼 화면 필요 |
| 프로젝트 생성 모달 — 기간 | S04/S12에 기간 필드 미정의 | 시작일~종료일 입력 필드 추가 설계 필요 |
| 프로젝트 생성 시 멤버 초대 | 현재 생성 후 S12에서 별도 초대 | 생성 모달 단계에서 바로 멤버 초대할지 여부 설계 결정 필요 |

### B. 화면정의서(S01~S14)에 정의되지 않은 기능

| 기능 | 역할 정의 · 기획서 언급 | 제외 사유 |
|------|----------------------|----------|
| 통합 검색 | 플랫폼 주요 기능 | 별도 검색 화면 미정의 |
| 통합 활동 피드 | 플랫폼 주요 기능 | 별도 피드 화면 미정의 (S11 알림과 구분) |
| 프로젝트별 진행률(%) 조회 | 회사 관리자 기능 | S04 카드에 상태 뱃지만 있고 % 수치 미정의 |
| 구성원 활동 모니터링 | 회사 관리자 기능 | 별도 모니터링 화면 미정의 |
| 회사 전체 활동 기록 조회 | 회사 관리자 기능 | S13 통계는 집계 수치만 제공, 활동 로그 미정의 |
| 메시지 → 이슈 원클릭 전환 | 핵심 차별 기능 | S09 · S10 화면 정의에 해당 UI 없음 |
| 이슈 ↔ 문서 양방향 연결 | 핵심 차별 기능 | S05 · S08 화면 정의에 연결 UI 없음 |
| 문서 내 `/task` 명령어 | 핵심 차별 기능 | S08 편집기 정의에 슬래시 커맨드 없음 |

> **특히 주목:** 회사 관리자 역할의 핵심 가치인  
> **프로젝트별 진행률 조회**와 **구성원 활동 모니터링**이 현재 화면정의서에 없음.  
> 이 두 기능이 없으면 대표 입장에서 CoWork의 모니터링 기능이  
> "알림(S11) + 카드 상태 뱃지(S04) 수준"에 머물게 됨.  
> → 별도 **관리자 대시보드 화면 설계**를 검토하길 권장.
