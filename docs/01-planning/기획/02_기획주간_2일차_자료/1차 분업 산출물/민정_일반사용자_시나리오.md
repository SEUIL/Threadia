## 배경 — 기존 Jira + Confluence + Slack 조합에서 팀원 관점의 문제

```
기존 상황 (일반 팀원 관점)
│
├─ 문제 1. 업무 시작 전 도구 순례
│     └─ 아침 출근 → 오늘 내 업무 확인 루틴:
│         Jira 열어 담당 이슈 확인
│         → Slack 열어 팀 공지·멘션 확인
│         → Confluence 열어 관련 문서 확인
│         → 다시 Jira로 돌아와 작업 시작
│         → 하루에 3개 앱을 수십 번 오가며 맥락을 스스로 조합
│
├─ 문제 2. 이슈 논의가 흩어짐
│     └─ Jira 이슈에서 발생한 기술적 논의를
│         → Slack 채널에서 이어서 나눔
│         → 결론은 다시 Jira 코멘트에 붙여넣기
│         → "이 결정이 왜 났나요?" → Slack 수백 개 뒤지거나 Jira 코멘트 확인
│         → 맥락이 두 군데에 쪼개져 추적 불가
│
├─ 문제 3. 문서와 이슈의 단절
│     └─ 이슈 해결 후 Confluence에 문서화
│         → Jira 이슈에 링크를 붙여도 문서 수정 시 링크는 낡은 버전
│         → "최신 설계 문서가 어디 있나요?" → 매번 물어봐야 함
│
└─ 문제 4. 알림 파편화
      └─ Jira 알림은 이메일 / Slack 알림은 앱 / Confluence 알림은 별도
          → 중요한 멘션을 놓치거나 알림 피로로 무시하게 됨
```

## 1단계 — 플랫폼 첫 진입

```
회원가입 및 로그인
│
├─ [로그인 · /] → [회원가입 · /signup] ── 자체 계정 생성
│     ├─ 로그인(/) 화면에서 '회원가입' 링크 클릭 → /signup 이동
│     │     ※ 초대 없이 누구나 직접 CoWork 계정 생성 가능
│     │       회원가입과 회사 스페이스 합류는 별개의 단계
│     ├─ 입력 항목
│     │     ├─ 이름: 김민정
│     │     ├─ 이메일: minjung@techflow.com
│     │     ├─ 비밀번호 입력
│     │     └─ 비밀번호 확인
│     └─ '가입하기' 클릭 → 계정 생성 완료 → 로그인(/) 이동
│
├─ [로그인 · /]
│     ├─ 이메일 + 비밀번호 입력
│     └─ '로그인' 클릭 → 인증 성공 → 3D 사무실(/hub)로 이동
│
└─ [3D 사무실 · /hub] ★ 첫 진입
      ├─ "사무실 로딩 중..." → Three.js 3D 사무실 공간 렌더링
      ├─ 상단바: 알림(🔔) · 채팅(💬) · 프로필(👤)
      ├─ 좌측 사이드바 (편집자 기준)
      │     ├─ 📋 프로젝트
      │     ├─ 📄 문서
      │     ├─ 📊 칸반
      │     └─ 🏃 스프린트
      │     ※ '🏢 회사관리' 없음 (오너 전용 — 김민정에게 표시되지 않음)
      └─ 상단바 알림(🔔) 아이콘에 뱃지 표시
            → 황스일 대표가 /company/members에서 발송한
               TechFlow Inc. 회사 스페이스 초대 알림 도착
            ※ 현재 상태: CoWork 계정은 있지만 아직 어느 회사 스페이스에도 미속
```

## 2단계 — 회사 스페이스 합류 및 프로젝트 참여

```
회사 스페이스 초대 수락 → 프로젝트 초대 수락
│
├─ [알림 · /notifications] ── 1. 회사 스페이스 초대 수락
│     ├─ 상단바 알림(🔔) 아이콘 클릭 → /notifications 진입
│     ├─ "읽지 않은 알림 N개" 표시
│     ├─ 필터 탭: 전체 / 읽지않음 / 멘션 / 태스크 / 문서
│     └─ 읽지 않은 알림 (강조 표시)
│           └─ ⚙ 시스템: "TechFlow Inc.에서 회사 스페이스에 초대했습니다"
│               초대 수락 → TechFlow Inc. 회사 구성원으로 합류 완료
│               ※ 회원가입(계정 생성)과 회사 합류(스페이스 참여)는 별개
│                  초대 수락 전까지는 회사 데이터에 접근 불가
│
├─ [알림 · /notifications] ── 2. 프로젝트 초대 수락
│     └─ ⚙ 시스템: "정철진님이 'CoWork 프론트엔드 개발' 프로젝트에 초대했습니다"
│         초대 수락 → 프로젝트 합류 완료
│
└─ [프로젝트 목록 · /projects]
      ├─ "CoWork 프론트엔드 개발" 카드 확인
      │     └─ 상태: 진행중 | 진행률: N% | 팀원: 3명
      └─ ※ '+ 새 프로젝트' 버튼이 화면에 없음
            (편집자는 프로젝트 생성 권한 없음 — 관리자·오너 전용)
```

## 3단계 — 스프린트 시작 알림 수신 및 업무 파악

```
스프린트 시작 및 업무 확인
│
├─ [알림 · /notifications] ── 다음 날 아침 진입점
│     ├─ 필터 탭 '태스크' 클릭
│     │     └─ ✓ 태스크: "정철진님이 Sprint 1을 시작했습니다"

│           ※ 기존: Slack 공지 채널에서 PM의 스프린트 시작 메시지를 찾아야 함
│              현재: /notifications에서 자동 수신, 클릭 한 번으로 해당 화면 이동
│
├─ [칸반 보드 · /kanban] ── 전체 이슈 현황 파악
│     ├─ 상단 프로젝트 탭: "CoWork 프론트엔드 개발" 선택
│     ├─ "총 N개 · 완료 N개" 진행 현황 표시
│     └─ 5개 컬럼 분포 확인
│           ├─ 백로그: 미배정 이슈
│           ├─ 할일: 배정되었으나 미착수 이슈
│           ├─ 진행중: 작업 중인 이슈
│           ├─ 검토중: PM 리뷰 대기 이슈
│           └─ 완료: 리뷰 완료 이슈
│
└─ [스프린트 · /sprint] ── 스프린트 전체 일정 파악
      ├─ 헤더 정보
      │     ├─ 스프린트명: Sprint 1
      │     ├─ 상태: 진행중
      │     ├─ 기간: 2026.06.11 ~ 2026.06.24
      │     └─ 프로젝트: CoWork 프론트엔드 개발
      ├─ 통계 대시보드
      │     ├─ 전체 태스크 N개 / 완료 N개 / 진행중 N개
      │     ├─ 스토리 포인트: N/N 완료 (N% 진행률)
      │     └─ 남은 일수 / 마감일
      ├─ 탭: 🏃 현재 스프린트 / 📦 백로그
      └─ 테이블: 태스크명 / 태그(카테고리) / 우선순위 / 상태 / SP / 담당자
            └─ "3D 사무실 Three.js 렌더링 구현" | 프론트 | 높음 | 할일 | 5SP | 김민정
            ※ 스프린트 시작·종료·생성 버튼 없음 (관리자·오너 전용)

```

│     │     ├─ 우선순위: 높음
│     │     └─ 생성 완료 → 할일 컬럼에 새 카드 추가
│     │           ※ 기존: Jira에서 이슈 생성 → Slack으로 팀에게 별도 공지

## 핵심 흐름 요약 — 일반 사용자 맥락 사슬

```
┌──────────────────────────────────────────────────────────┐
│               Context Switching 비교 (팀원 관점)          │
├─────────────────────────┬────────────────────────────────┤
│ 기존 (Jira+Slack+Confluence)│ 현재 (CoWork)               │
├─────────────────────────┼────────────────────────────────┤
│ 업무 시작: 앱 3개 순서대로  │ /notifications → 1클릭 이동  │
│ 이슈 논의: Slack + Jira 분리│ 이슈 쓰레드에 모두 귀속      │
│ 채팅 전환: 맥락 처음 재설명 │ 요약 배너 자동 표시 맥락 유지 │
│ 문서 연결: 링크 후 단절     │ 프로젝트 내 문서 항상 최신   │
│ 알림: 앱마다 별도 확인      │ /notifications 단일 통합 관리 │
└─────────────────────────┴────────────────────────────────┘

  [일반 사용자 업무 흐름 — 한 플랫폼에서 완결되는 사슬]

  /notifications
    │ ✓ 태스크: 이슈 배정·스프린트 시작 수신
    ↓
  /kanban (칸반 보드)
    │ 5컬럼: 백로그→할일→진행중→검토중→완료
    │ 이슈 생성·상태 변경(드래그&드롭)
    ↓
  이슈 쓰레드 (카드 내 패널)
    │ 이슈 단위 토론·결정·블로커 기록
    │ ※ 상위 컨텍스트 배너: 이슈 정보 항상 표시
    ↓
  /chat (채팅)
    │ 채널(# 개발 등) or DM으로 빠른 소통
    │ ※ 쓰레드 요약 배너: 직전 맥락 자동 전달
    ↓
  /docs/editor (문서 편집기)
    │ 해결 내용·기술 결정 .md 문서화
    │ 필터: 문서·회의록·기획서·가이드
    ↓
  /kanban → 검토중 → 완료
    └─ /notifications로 팀에 자동 공지
```

## [별도 정리] 설계 보완 필요 및 미구현 기능

### A. 데모 구현과 화면정의서 간 차이 (데모 기준 적용)

| 항목 | 화면정의서 | 실제 데모 구현 |
|------|-----------|--------------|
| 역할명 | 일반 사용자·프로젝트 관리자·회사 관리자 | 편집자·관리자·오너 |
| 칸반 컬럼 | To Do · In Progress · Done (3개) | 백로그·할일·진행중·검토중·완료 (5개) |
| 채팅 구조 | DM 전용 | 채널(#일반/#개발/#디자인/#공지) + DM |
| 알림 필터 탭 | 전체/@멘션/이슈/채팅/시스템 | 전체/읽지않음/멘션/태스크/문서 |
| 알림 시간 그룹 | 정의 없음 | 오늘/어제/이전으로 구분 |
| 문서 카테고리 | 정의 없음 | 문서·회의록·기획서·가이드 |
| 문서 그래프 보기 | 정의 없음 | 🕸️ 그래프 보기 구현됨 |
| 스프린트 통계 | 정의 없음 | 스토리 포인트·진행률%·남은 일수 |

### B. 데모에서 확인되지 않은 미구현 기능

| 기능 | 기획서 언급 | 비고 |
|------|------------|------|
| 이슈 쓰레드 전용 화면 | 핵심 기능 (S10) | 칸반 카드 내 패널 형태로 추정, 별도 URL 없음 |
| 쓰레드 → 채팅 전환 요약 배너 | 핵심 차별 기능 | 채팅(/chat) 화면에서 미확인 |
| 메시지 → 이슈 원클릭 전환 | 핵심 차별 기능 | 채팅 화면에 해당 UI 미확인 |
| 이슈 ↔ 문서 양방향 연결 | 핵심 차별 기능 | 칸반·문서 화면 간 연결 UI 미확인 |
| 문서 내 `/task` 명령어 | 핵심 차별 기능 | 문서 편집기에 슬래시 커맨드 미확인 |

> **일반 사용자 관점 핵심 메시지:**  
> 기존 Jira+Confluence+Slack 조합에서 팀원은 하루에 3개 앱을 수십 번 오가며  
> 맥락을 **스스로 조합**해야 했다.  
> CoWork에서는 **/notifications → /kanban → 이슈 쓰레드 → /chat → /docs**  
> 흐름이 한 플랫폼 안에서 끊기지 않고 이어지며,  
> 특히 **5컬럼 칸반(검토중 단계 포함)**과 **채널 기반 채팅**이  
> 데모에서 확인 가능한 핵심 차별 요소다.
