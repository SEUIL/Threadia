# 정돈형 역할별 기능분해 계층 다이어그램

> 프로젝트: Jira + Confluence + Slack 경량 애자일 협업 플랫폼  
> 목적: 전체 기능, 회사 관리자 기능, 프로젝트 관리자 기능, 일반 사용자 기능을 상하 계층과 좌우 업무 흐름으로 정리한다.  
> 기준: 화면정의서, 기능분해표, 사용자유형별 필수기능 문서 검수 결과 반영

---

# 1. 다이어그램 개요

이 다이어그램은 단순히 기능을 나열하는 표가 아니라, 역할별 권한 구조와 실제 업무 흐름을 함께 보여주기 위한 기능분해 다이어그램이다.

구조는 다음 기준으로 정리했다.

```text
상하 관계: 전체 공통 기반 → 회사 관리자 → 프로젝트 관리자 → 일반 사용자
좌우 흐름: 프로젝트 홈 → 이슈·칸반 → 채팅·쓰레드 → 문서·회의록 → 알림/활동 피드
범위 통제: MVP 보류 기능은 오른쪽 별도 영역으로 분리
```

---

# 2. 전체 계층 구조

```text
경량 애자일 협업 플랫폼
│
├─ 전체 공통 기반 기능
│  ├─ 로그인 / 회원가입
│  ├─ 로그아웃 / 내 정보
│  ├─ 역할 기반 접근 제어
│  ├─ C / P / A 권한 분리
│  ├─ 3D 메인 허브
│  ├─ 회사 / 프로젝트 선택
│  ├─ .md 문서 원칙
│  └─ 하나의 주제 하나의 쓰레드
│
├─ C. 회사 관리자
│  ├─ 회사 관리
│  ├─ 구성원 / 권한 관리
│  ├─ 회사 프로젝트 관리
│  └─ 회사 대시보드
│
├─ P. 프로젝트 관리자
│  ├─ 프로젝트 관리
│  ├─ 이슈 관리
│  ├─ 스프린트 관리
│  └─ 프로젝트 설정
│
└─ A. 일반 사용자
   ├─ 프로젝트 홈
   ├─ 이슈·칸반
   ├─ 채팅·쓰레드
   ├─ 문서·회의록
   └─ 알림 / 활동 피드
```

---

# 3. 권한 포함 관계

```text
C. 회사 관리자
└─ P. 프로젝트 관리자 기능 사용 가능
   └─ A. 일반 사용자 기능 사용 가능
```

즉, 역할별 권한 관계는 다음과 같다.

| 역할 | 포함 기능 |
|---|---|
| A 일반 사용자 | 일반 사용자 기능만 사용 |
| P 프로젝트 관리자 | 일반 사용자 기능 + 프로젝트 관리자 기능 |
| C 회사 관리자 | 일반 사용자 기능 + 프로젝트 관리자 기능 + 회사 관리자 기능 |

# 4. 전체 공통 기반 기능

전체 공통 기반 기능은 A, P, C가 모두 사용하는 서비스 기반 기능이다.

## 4.1 인증 / 계정

- 로그인
- 회원가입
- 로그아웃
- 내 정보 조회

## 4.2 권한 / 접근 제어

- 역할 기반 접근 제어
- 회사 관리자 C 권한 분리
- 프로젝트 관리자 P 권한 분리
- 일반 사용자 A 권한 분리

## 4.3 공통 진입 구조

- 3D 메인 허브
- 회사 선택
- 프로젝트 선택
- 글로벌 사이드바
- 상단바: 알림 / 채팅 / 프로필

## 4.4 공통 제약사항

- 모든 문서는 `.md` 형식으로 관리
- 하나의 주제는 하나의 쓰레드로 관리
- 이슈, 문서, 채팅, 알림은 서로 연결되는 구조로 설계

---

# 5. 회사 관리자 기능 C

회사 관리자는 회사 또는 워크스페이스 단위의 조직과 권한을 관리한다.

## 5.1 회사 관리

- 회사 / 워크스페이스 생성
- 회사 정보 조회
- 회사 정보 수정

## 5.2 구성원 / 권한 관리

- 회사 구성원 목록 조회
- 구성원 초대
- 초대 상태 확인
- 구성원 역할 변경
- 프로젝트 관리자 지정
- 구성원 비활성화

## 5.3 회사 프로젝트 관리

- 회사 전체 프로젝트 목록 조회
- 프로젝트 상태 확인
- 회사 단위 프로젝트 생성
- 프로젝트별 PM 지정

## 5.4 회사 대시보드

- 사용자 수 확인
- 부서 수 확인
- 프로젝트 수 확인
- 최근 활동 확인

---

# 6. 프로젝트 관리자 기능 P

프로젝트 관리자는 일반 사용자 기능을 포함하며, 프로젝트 운영과 업무 계획을 담당한다.

## 6.1 프로젝트 관리

- 프로젝트 생성
- 프로젝트 정보 수정
- 프로젝트 멤버 조회
- 프로젝트 멤버 초대
- 프로젝트 멤버 제거

## 6.2 이슈 관리

- 이슈 전체 수정
- 담당자 지정
- 우선순위 지정
- 마감일 지정
- 이슈 삭제 또는 보관

## 6.3 스프린트 관리

- 백로그 관리
- 백로그 이슈를 스프린트에 배정
- 스프린트 생성
- 스프린트 시작
- 스프린트 종료

## 6.4 프로젝트 설정

- 프로젝트 권한 설정
- 프로젝트 알림 설정
- 문서 삭제 또는 보관
- 회의록 템플릿 관리
- 프로젝트 보관

---

# 7. 일반 사용자 기능 A

일반 사용자는 프로젝트 안에서 실제 업무를 수행한다.

## 7.1 프로젝트 홈

프로젝트 홈은 사용자가 프로젝트에 들어왔을 때 가장 먼저 확인하는 요약 화면이다.

- 내 프로젝트 확인
- 내 업무 확인
- 프로젝트 공지 확인
- 최근 활동 확인

## 7.2 이슈·칸반

Jira 역할에 해당하는 업무 관리 기능이다.

- 이슈 목록 조회
- 이슈 상세 조회
- 이슈 생성
- 내 업무 상태 변경
- 칸반 보드 조회
- 담당 카드 이동

## 7.3 채팅·쓰레드

Slack 역할에 해당하는 커뮤니케이션 기능이다.

- 프로젝트 채팅방 조회
- 메시지 작성
- 쓰레드 조회
- 쓰레드 댓글 작성
- 메시지에서 이슈 생성

## 7.4 문서·회의록

Confluence 역할에 해당하는 지식 관리 기능이다.

- `.md` 문서 조회
- `.md` 문서 작성
- `.md` 문서 수정
- 마크다운 미리보기
- 문서와 이슈 연결
- 문서 댓글
- 파일 첨부

## 7.5 알림 / 활동 피드

업무 변경 사항을 다시 프로젝트 홈으로 모으는 기능이다.

- 알림 목록 조회
- 읽지 않은 알림 표시
- 알림 읽음 처리
- 멘션 알림
- 업무 할당 알림
- 댓글 알림
- 문서 변경 알림
- 이슈 상태 변경 알림
- 프로젝트 활동 피드 확인

---

# 8. 일반 사용자 기준 업무 흐름

일반 사용자의 실제 업무 흐름은 다음과 같다.

```text
프로젝트 홈
→ 이슈·칸반
→ 채팅·쓰레드
→ 문서·회의록
→ 알림 / 활동 피드
→ 프로젝트 홈으로 다시 회수
```

각 단계의 의미는 다음과 같다.

| 단계 | 의미 |
|---|---|
| 프로젝트 홈 | 내 업무, 공지, 최근 활동 확인 |
| 이슈·칸반 | 업무 생성, 상태 변경, 진행 상황 확인 |
| 채팅·쓰레드 | 업무 관련 논의 진행 |
| 문서·회의록 | 논의 내용과 결정사항 정리 |
| 알림 / 활동 피드 | 변경사항을 다시 사용자에게 전달 |

# 11. 발표용 설명

> 이 기능분해 다이어그램은 역할의 상하 관계와 실제 업무 흐름을 기준으로 정리했습니다.  
> 가장 위에는 모든 사용자가 공통으로 사용하는 로그인, 권한, 메인 허브 같은 기반 기능을 두었고, 그 아래에는 회사 관리자, 프로젝트 관리자, 일반 사용자 순서로 권한 계층을 배치했습니다.  
> 일반 사용자 영역에서는 실제 협업 흐름이 보이도록 프로젝트 홈에서 시작해 이슈·칸반, 채팅·쓰레드, 문서·회의록, 알림/활동 피드로 이어지게 구성했습니다.  
> 프로젝트 관리자는 이 흐름을 운영하기 위해 멤버, 이슈, 스프린트, 프로젝트 설정을 관리하고, 회사 관리자는 구성원, 권한, PM 지정, 회사 전체 프로젝트를 관리합니다.  
> MVP에서 제외할 기능은 보류 영역으로 분리해 개발 범위를 명확히 했습니다.
