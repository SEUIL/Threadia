# 프로젝트 관리자 시나리오

## 1단계. 프로젝트 생성 및 팀 구성

```
프로젝트 생성
│
├─ 프로젝트 생성
│   ├─ 프로젝트 정보 입력
│   ├─ 프로젝트 생성 완료
│   └─ 프로젝트 대시보드 이동
│
└─ 팀원 관리
    ├─ 팀원 초대
    ├─ 권한 지정
    ├─ 팀원 승인
    ├─ 권한 변경
    └─ 팀원 제거
```

## 추가적으로 고려해볼 기능

현재 설계만으로도 프로젝트 관리 기능 구현은 가능하지만, 실제 협업 환경을 고려했을 때 몇 가지 기능을 추가하면 활용도를 높일 수 있다.

| 기능        | 추가 이유                                     |
| --------- | ----------------------------------------- |
| 공지사항      | 프로젝트 관련 공지사항을 팀원들에게 전달하기 위해 필요            |
| 알림        | 업무 할당, 댓글 작성, 상태 변경 등의 내용을 빠르게 확인하기 위해 필요 |
| 활동 로그     | 프로젝트 내 변경 사항을 기록하고 확인하기 위해 필요             |
| 프로젝트 대시보드 | 프로젝트 진행 상황을 한눈에 확인하기 위해 필요                |
| 통합 검색     | 업무, 문서, 회의록 등을 빠르게 찾기 위해 필요               |
| 마일스톤      | 프로젝트 주요 일정과 목표를 관리하기 위해 필요                |
| 멘션(@)     | 특정 팀원에게 빠르게 피드백을 전달하기 위해 필요               |
| 파일 첨부     | 업무 관련 자료를 공유하기 위해 필요                      |

---

## 보완이 필요한 부분

### 프로젝트 생성

* 프로젝트 상태(진행 예정, 진행 중, 완료) 설정 기능 추가 검토
* 프로젝트 생성 시 팀원 초대 기능 포함 여부 검토

### WBS 관리

* 작업 진행률(%) 표시 기능 추가
* 작업 간 관계 표현 기능 검토

### Sprint 관리

* Sprint 목표 설정 기능 추가
* Sprint 종료 후 결과 요약 기능 추가

### 업무 / 이슈 관리

* 첨부파일 기능 추가
* 우선순위 및 마감일 관리 기능 강화
* 지연 업무 표시 기능 추가

### 문서 및 회의록 관리

* 문서 버전 관리 기능 검토
* 회의록 작성 후 업무로 연결하는 기능 검토

---

## 차별화 기능으로 고려할 수 있는 항목

* 문서와 업무를 연결하여 관련 작업을 쉽게 확인할 수 있는 기능
* 회의록 작성 후 후속 업무를 바로 생성하는 기능
* 댓글 작성 시 멘션을 통해 특정 사용자에게 알림을 보내는 기능
* 업무 변경 이력을 확인할 수 있는 기능
* Sprint 종료 시 완료율과 잔여 업무를 자동으로 계산하는 기능

---

## 프로젝트 관리 기능 강화를 위한 제안

현재 설계는 프로젝트 생성부터 업무 관리까지의 기본적인 기능을 포함하고 있다.

추가로 프로젝트 대시보드, 활동 로그, 알림 기능 등을 적용한다면 프로젝트 진행 상황을 보다 효율적으로 관리할 수 있을 것으로 예상된다.

특히 진행률 확인, 지연 업무 조회, 활동 이력 관리 기능은 관리자가 프로젝트 상태를 파악하는 데 도움이 될 것으로 보인다.
