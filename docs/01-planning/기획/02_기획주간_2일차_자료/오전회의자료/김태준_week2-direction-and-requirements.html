2주차 과제 + 3가지 프로그램 단점 정리 반영본

맥락 단절을 줄이는 경량 애자일 협업 플랫폼

Notion 과제 파일과 단점 정리 파일을 기준으로, 팀이 이번 주에 확정해야 할 항목과 제품 방향성을 한 화면에서 볼 수 있도록 재구성했습니다.

현재 과제의 핵심

J
Jira 역할이슈/태스크, 칸반, 스프린트, 백로그
C
Confluence 역할회의록, 기술 문서, 스펙, 지식 베이스
S
Slack 역할채널 채팅, 스레드, 멘션, 파일 공유
Core Direction
대화 → 태스크 → 문서가 단일 맥락으로 연결되는 경량 플랫폼

기능을 다 합치는 것이 아니라, 세 도구 사이의 빈틈인 “맥락 단절”을 줄이는 것이 제품의 핵심입니다.

1. 2주차에 먼저 확정할 것

회의에서 우선 결정해야 이후 ERD, API, 화면정의서 범위가 흔들리지 않습니다.

결정 항목기준다음 작업 영향
사용자 유형일반 사용자 / 관리자 / 비로그인 사용자권한과 화면 흐름 결정
필수 기능6주 안에 구현 가능한 기능만 포함ERD/API 범위 결정
선택 기능시간이 남으면 구현할 기능Sprint 후반 작업 후보
보류 기능실시간 고도화, 복잡한 결재 등 리스크 큰 기능 제외범위 폭주 방지
시연 흐름발표에서 보여줄 핵심 흐름화면/API 우선순위 결정
Repositoryrepo 생성, 팀원 초대, clone 가능개발 착수 기반

2. 사용자 유형 초안

문서 기준으로 비로그인 기능은 일반 사용자 기능 확정 이후 세부화합니다.

A

일반 사용자

소속 프로젝트에서 업무 수행, 문서 작성, 채팅 참여, 이슈 처리.

P

프로젝트 관리자

특정 프로젝트의 PM 역할. 업무/일정/멤버/진행 현황 관리.

C / F

회사·플랫폼 관리자

회사 단위 사용자 관리와 전체 플랫폼 운영 관리. MVP에서는 범위를 축소하는 것이 안전.

3. 기존 3개 도구의 단점

우리 플랫폼이 해결해야 할 명확한 근거입니다.

Jira

강력하지만 무거움

  • 프로젝트/대시보드 설정 시간이 큼
  • 전문 지식 있는 PM 필요
  • 비개발 직군 접근 어려움
  • 데이터가 많아지면 퍼포먼스 저하
Confluence

문서는 쌓이나 찾기 어려움

  • 트리 구조가 커질수록 탐색 어려움
  • 에디터 UX 불만
  • 동시 수정 충돌과 버전 관리 한계
  • Jira와 별도 비용 부담
Slack

빠르지만 맥락이 사라짐

  • 프로젝트 관리 기능 부족
  • 제3자 도구 의존
  • 알림 피로로 업무 흐름 단절
  • 히스토리 파편화와 무료 플랜 보관 제한

4. 핵심 문제 정의

문제의 본질은 단순한 탭 전환이 아니라, 작업 중인 사고 흐름이 끊기는 Context Switching입니다.

맥락 단절

Slack, Jira, Confluence를 오가며 뇌가 계속 리셋됨.

5. 가져올 기능과 버릴 기능

판단 기준은 “이 기능이 맥락 단절을 줄이는가?”입니다.

가져올 기능

검증된 핵심만 선택

  • Jira: 칸반, 이슈 CRUD, 담당자, 우선순위, 스프린트/백로그
  • Confluence: Space → Page, 공동 편집, 버전 히스토리, 템플릿
  • Slack: 채널 채팅, 스레드, 멘션, 파일 첨부
버릴 기능

경량성을 해치는 기능 제외

  • 복잡한 커스텀 워크플로/커스텀 필드
  • 세분화된 권한 관리
  • 화이트보드, 매크로, Jira 전용 위젯
  • 외부 앱 2,600개 연동, 허들, 워크플로 빌더

6. 핵심 차별 기능

단순 통합이 아니라, 기존 도구 조합으로 해결되지 않는 흐름을 새로 설계합니다.

MVP 핵심

메시지 → 이슈 원클릭 전환

채팅 메시지를 이슈로 만들고, 원본 메시지 링크를 이슈에 저장합니다.

Phase 2

이슈 ↔ 문서 양방향 연결

문서 변경이 이슈에 반영되고, 이슈에서 관련 문서를 바로 확인합니다.

Phase 2

문서 내 /task 커맨드

회의록 작성 중 액션 아이템을 바로 칸반 이슈로 생성합니다.

Phase 2

통합 활동 피드

채팅, 이슈, 문서 변경을 하나의 타임라인으로 보여줍니다.

Phase 3

통합 검색

검색어 하나로 채팅 메시지, 이슈 카드, 문서 페이지를 함께 찾습니다.

경량 전략

기본값 중심 UX

프로젝트 생성은 이름 입력 후 즉시 생성, 권한은 관리자/멤버 2단계부터 시작합니다.

7. 개발 우선순위

2주차 회의 이후 화면정의서, 기능목록, Entity/API 후보로 이어질 수 있는 순서입니다.

Phase 1

MVP 필수

채널 채팅 + 스레드, 칸반 보드 + 이슈 CRUD, 문서 페이지 + 에디터, 메시지 → 이슈 전환

Phase 2

포트폴리오 완성도

이슈 ↔ 문서 양방향 연결, 문서 내 /task 커맨드, 통합 활동 피드

Phase 3

여유 기능

통합 검색, 리포트, 고급 알림, 외부 연동

회의용 결론

이번 과제의 방향은 “3개 툴을 합친 그룹웨어”가 아니라, 대화·태스크·문서 사이의 맥락 단절을 줄이는 경량 애자일 플랫폼으로 잡는 것이 가장 설득력 있습니다.

문제: 도구 전환으로 맥락이 끊김
해결: Task 중심으로 대화와 문서 연결
MVP: 채팅 + 칸반 + 문서 + 메시지→이슈
범위관리: 있으면 좋은 기능은 과감히 보류
