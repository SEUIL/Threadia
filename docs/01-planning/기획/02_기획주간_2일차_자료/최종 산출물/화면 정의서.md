# 화면 정의서

## 1. 문서 목적

이 문서는 1차 화면정의서를 최종 결정사항에 맞게 정리한 Day 2 최종 화면 정의서다. 화면별 목적, 접근 사용자, 주요 데이터, 액션, 연결 기능을 정리해 Day 3의 API와 Architecture 설계 입력값으로 사용한다.

관련 문서:

- [[사용자 시나리오]]
- [[기능 분해표]]

## 2. 화면 정의 기준

| 항목 | 기준 |
|---|---|
| MVP 역할 | A/P/C 중심 |
| 보류 역할 | F 플랫폼 관리자 |
| 칸반 컬럼 | 백로그/할일/진행중/검토중/완료 |
| 채팅 | 프로젝트 채팅은 MVP, 1:1 DM은 선택 |
| 알림 | MySQL 기반 알림함 기준 |
| S13 | 회사 조회 + 회사 정보 생성/수정 form 포함 |
| 프로젝트 생성 | 진입 화면은 정의하되 생성 필드는 확정하지 않음 |

## 3. 전체 화면 흐름

```text
서비스 진입
└── S01 로그인
    ├── S02 회원가입
    └── S03 3D 사무실 메인 허브
        ├── S04 프로젝트 목록
        │   ├── S05 칸반 보드
        │   │   └── S10 쓰레드
        │   ├── S06 백로그 / 스프린트
        │   ├── S07 문서·회의록 목록
        │   │   └── S08 문서 편집기
        │   └── S12 프로젝트 설정
        ├── S09 프로젝트 채팅 / 1:1 DM 선택
        │   └── S10 쓰레드
        ├── S11 알림
        └── S13 회사 관리
            └── S14 구성원·권한 관리

MVP 보류
└── S15 플랫폼 관리자 대시보드
```


상태 의미:

| 컬럼 | 의미 |

| 진행중 | 담당자가 작업 중인 이슈 |
| 검토중 | PM 리뷰를 기다리는 이슈 |
| 완료 | 리뷰가 끝난 이슈 |

| 주요 데이터 | 알림 유형, 제목, 본문, 발신자, 대상 화면, 읽음 여부 |
| 주요 액션 | 알림 목록 조회, 읽음 처리, 모두 읽음, 알림 항목 클릭 이동, 기본 on/off 설정 |
| 연결 기능 | NOTI-01, NOTI-02, NOTI-03(선택) |
| 연결 화면 | S05, S06, S08, S09, S10, S12 |

MySQL 1차 구현 기준:

| 저장 단위 | 역할 |
|---|---|
| notification_event | 어떤 일이 발생했는지 저장 |
| notification_recipient | 누가 받았고 읽었는지 저장 |
| notification_preference | 사용자/역할/범위별 on/off 설정 저장 |

설계 메모:

- Redis는 unread count 캐시나 WebSocket/SSE 신호가 필요해진 뒤 검토한다.
- NoSQL은 활동 피드나 대량 이벤트 저장이 필요해진 뒤 검토한다.

#### S13 회사 정보 form

| 필드 | 설명 | 필수 여부 |
|---|---|---|
| 회사명 | workspace에 표시될 회사 이름 | 필수 |
| 대표자 | 기본값은 현재 C 사용자, 필요 시 표시명 수정 | 필수 |
| 회사 소개 | 회사 설명 또는 내부 메모 | 선택 |
| 업종/카테고리 | 회사 분류 | 선택 |
| 회사 로고 | 이미지 업로드 또는 기본 로고 사용 | 선택 |

주요 버튼:

| 버튼 | 동작 |
|---|---|
| 저장 | 회사 정보 생성/수정 |
| 취소 | 변경사항 폐기 후 조회 카드로 복귀 |
| 구성원 관리 | S14로 이동 |
| 부서 추가 | 부서 생성 모달 열기 |

설계 메모:

- 최초 회사 생성 전에는 form을 우선 노출한다.
- 생성 이후에는 회사 정보 카드와 `수정` 버튼을 노출한다.
- 부서 추가는 선택 기능으로 두고, MVP에서는 회사 정보와 구성원 관리가 우선이다.
- 로고 저장 방식은 AWS S3 연동 여부와 함께 Day 3 이후 결정한다.
