# 기획주간 2일차 Repository 세팅과 사용자 흐름 기능 분해

## 목적

2일차는 1일차에서 못 끝내고 넘긴 **주요 사용자 정의, 사용자 시나리오, 화면 목록/흐름, 기능 목록 분해**를 먼저 정리하고, 이후 ERD/API 설계가 가능하도록 기능의 경계를 명확히 하는 날이다.

2026-06-11 기준으로 사용자 시나리오, 기능 분해표, 화면 정의서는 최종 산출물로 정리되었다. 단, **기획서 초안, 보류 기능 최종 정리, repository 이름/owner와 GitHub repository 초기 세팅, README 한 줄 설명 초안은 3일차로 이월**한다.

## 전회차 입력값

| 입력값 | 없을 때 처리 |
|---|---|
| 프로젝트 한 줄 목표 | Jira + Confluence + Slack을 합쳐놓은 경량 애자일 협업 플랫폼 방향 재확인 |
| 기획서 초안 입력값 | 3일차로 이월. 최종 사용자 시나리오/기능 분해표/화면 정의서를 입력값으로 사용 |
| 주요 사용자 | A 일반 사용자, P 프로젝트 관리자, C 회사 관리자 중심으로 정리 완료. F/S15는 MVP 보류 |
| MVP 후보 기능 | 기능 분해표 초안 완료. 보류 기능 최종표는 3일차로 이월 |
| 보류 기능 원칙 | 3일차로 이월. 2일차 최종 산출물의 `MVP / 선택 / 보류` 구분을 기준으로 확정 |
| repository 이름/owner | 3일차로 이월. 값은 확정 필요 |
| README 한 줄 설명 초안 | 3일차로 이월. repo 초기 세팅과 함께 반영 |
| 확정 기술 스택 | MySQL 8.4, Spring Boot, React + Next, AWS EC2/RDS/S3 기준으로 기능 분해 |

### 작업 묶음 1. GitHub repository 초기 세팅

> [!note]
> 이 작업 묶음은 3일차로 이월한다. 2일차에는 사용자 흐름, 기능 분해, 화면정의서 최종 산출물 정리를 우선 완료했다.

| 항목 | 2일차에 할 것 | 4일차로 미룰 것 |
|---|---|---|
| repository | 생성, 팀원 초대, clone 확인 | branch protection 강제 |
| README | 프로젝트 한 줄 설명, 기술 후보, 실행 방법 TBD 표시 | 확정 실행 방법 |
| branch | `main` 직접 push 금지 원칙, branch naming 초안 | 세부 보호 규칙 |
| Issue | 기능 분해 결과를 Issue 후보로 정리 | label/milestone 세부 운영 |
| 협업 문서 | 임시 규칙 메모 | `AGENTS.md`, PR Template, CI |

3일차 repository는 협업 공간을 여는 것이 목적이다. 실행 가능한 Spring Boot 프로젝트, CI, PR Template까지 한 번에 끝내려고 하지 않는다.

### 작업 묶음 2. 사용자 시나리오

| 선택 | 일정 목록/등록 | 일정 관리 |
| 필수 | 관리자 메인 | 관리 기능 진입 |
| 선택 | 사용자 관리 | 관리자 기능 확장 |

### 작업 묶음 4. 기능 분해

| 기능 | 세부 기능 | 우선순위 | 비고 |
|---|---|---:|---|
| 인증 | 로그인, 로그아웃, 권한 확인 | 필수 | Spring Security 여부 검토 |
| 업무/이슈 | 목록, 상세, 등록, 수정, 상태 변경 | 필수 | Jira 역할의 핵심 기능 |
| 문서/회의록 | 목록, 상세, 작성, 수정 | 필수 | Confluence 역할의 핵심 기능 |
| 공지/알림 | 공지 목록, 상세, 작성 | 필수 | Slack 역할은 우선 알림/공지 중심 |
| 관리자 | 팀원 관리, 프로젝트 관리 | 필수/선택 | 사용자 관리는 선택 가능 |
| 일정 | 목록, 등록, 수정, 삭제 | 선택 | 개인/전체 일정 범위 결정 |
| 파일 | 업로드, 다운로드 | 선택 | S3 연동 리스크 있음 |
| 검색 | 업무/문서 검색 | 선택 | 후순위 |
| 채팅 | 실시간 메시지 | 보류 | WebSocket 리스크 큼 |
| 전자결재 | 결재선, 승인/반려 | 보류 | MVP 범위 초과 가능성 큼 |
