# 기획주간 4일차 협업 하네스와 문서 운영

## 목적

4일차는 팀원이 같은 방식으로 개발하고 검증할 수 있도록 **문서 구조, AGENTS.md, PR Template, CI, AI 사용 규칙**을 정하는 날이다.

3일차 산출물로 **ERD 초안 v1.4**, **API 명세서 초안 v1.4**, **권한 정책 초안**, **기획서 초안**, **v2 기획 산출물**이 준비되었으므로, 4일차에는 이를 repository 운영 규칙과 개발 협업 기준으로 연결한다.

기획주간을 다시 6일 구조로 운영하므로 4일차는 협업 하네스에 집중하고, Sprint 1 Backlog/검증 기준은 5일차, 발표/리스크/Week 2 진입 점검은 6일차로 넘긴다.

| API 목록 초안 | 완료: `API 명세서 초안_v1.4.md` | API 변경 PR 체크 항목과 화면-API 매핑 작업에 반영 |

### 작업 묶음 2. AGENTS.md / CLAUDE.md / CONTRIBUTING.md 최소 규칙

2026-06-12 기준으로 아래 파일은 repository root에 생성 완료했다.

| 파일 | 상태 | 역할 |
|---|---|---|
| `AGENTS.md` | 완료 | OpenCode, Codex 계열 AI와 팀원이 읽는 공통 작업 규칙 |
| `CLAUDE.md` | 완료 | Claude Code 사용자가 `AGENTS.md`와 `CONTRIBUTING.md`를 따르도록 연결 |
| `CONTRIBUTING.md` | 완료 | commit message 규칙과 GitHub 표시 원칙 |

현재 반영된 핵심 규칙:

```md
## Git Commit Message

- commit message 형식은 `type(scope): summary`를 따른다.
- summary는 한국어를 허용한다.
- 한 commit에는 한 가지 논리적 변경만 담는다.
- `WIP`, `수정`, `작업중`처럼 의미가 모호한 message는 PR merge 전에 정리한다.

## GitHub 표시 원칙

- GitHub collaborator, reviewer, assignee에는 실제 팀원 계정만 사용한다.
- AI 도구나 agent 이름을 collaborator, commit author/co-author, PR author로 남기지 않는다.
- AI를 사용했다면 PR 설명의 AI 사용 여부/범위로만 기록한다.
```

### 작업 묶음 3. PR Template 체크 항목

```md
## 작업 내용

-

## 검증

- [ ] 관련 기능을 직접 실행했다.
- [ ] `./gradlew test` 또는 `./gradlew build`를 실행했다.
- [ ] 실패한 test/build가 없다.

## AI 사용 여부

- [ ] 이번 PR에서 AI를 사용했다.
- [ ] AI 사용 범위를 아래에 적었다.
- [ ] AI가 만든 코드를 직접 이해했다.

## 보안/승인 체크

- [ ] `.env`, API key, token, password, 개인정보가 포함되지 않았다.
- [ ] DB, 배포, 인증/인가, 보안, 대규모 구조 변경이면 승인자 검토를 요청했다.
```

### 작업 묶음 4. CI 기준

| 입력값 | 처리 기준 |
|---|---|
