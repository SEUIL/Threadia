# 문서 작성 규칙

> Threadia 프로젝트의 모든 문서 작성 기준이다.  
> AI 도구(Claude Code 등)가 문서를 생성·수정할 때도 이 규칙을 따른다.

---

## 1. 폴더 구조 및 용도

```
docs/
├── 00-project/        공통 규칙, 팀 구성 등 프로젝트 메타 문서
├── 01-planning/       기획 기간 원본 자료 — 수정 금지, 참조 전용
├── 02-requirements/   기능 분해표, 사용자 시나리오 최종본
├── 03-design/         화면정의서, ERD 최종본
├── 04-api/            API 명세서 최종본
├── 05-architecture/   아키텍처 결정 문서, 기술 연구 보고서
├── 06-meetings/       개발 기간 회의록
├── 07-decisions/      주요 기술 결정 기록 (ADR)
├── 08-members/        팀원별 개인 작업 공간 (아래 별도 설명)
└── assets/            공용 이미지, 다이어그램
```

### 08-members 구조

```
08-members/
└── member-XX/                  각 팀원 전용 폴더
    ├── 개발-진행사항.md          스프린트별 작업 기록
    ├── 기술-연구/                기술 조사·연구 문서
    └── 포트폴리오/               포트폴리오 정리 문서
        ├── 기여-내역.md
        └── 트러블슈팅.md
```

- `member-01` ~ `member-06` 총 6개 폴더
- 본인 폴더 외 타인 폴더는 수정하지 않는다
- AI가 멤버 문서를 작성할 때는 **반드시 해당 멤버 본인의 요청**이 있어야 한다

---

## 2. 파일명 규칙

- **형식**: `kebab-case` 사용 (예: `화면정의서-최종본.md`, `실시간-아키텍처-연구.md`)
- **언어**: 한국어 허용. 단, 기술 용어는 영어 그대로 사용 (예: `API-명세서.md`)
- **버전 표기**: 파일명에 버전을 붙이지 않는다. 버전은 문서 내 메타정보에 기록한다
- **확장자**: 문서는 `.md`, 이미지는 `assets/` 폴더에 `.png` / `.jpg`

---

## 3. 문서 상단 필수 메타정보

모든 문서는 최상단에 아래 항목을 포함한다.

```markdown
> **작성자**: member-XX  
> **작성일**: YYYY-MM-DD  
> **최종 수정**: YYYY-MM-DD  
> **버전**: v1.0  
> **상태**: 작성 중 | 검토 중 | 확정
```

- `상태`가 **확정**인 문서는 내용을 함부로 수정하지 않는다
- 내용을 수정할 경우 `최종 수정` 날짜와 `버전`을 갱신한다

---

## 4. 문체 규칙

| 항목 | 규칙 |
|---|---|
| 기본 언어 | 한국어 |
| 종결 어미 | `~다` 체 통일 (예: "처리한다", "반환한다") |
| 기술 용어 | 영어 원문 유지 (예: WebSocket, Redis, STOMP) |
| 영어 약어 | 첫 등장 시 풀어서 병기 (예: `SSE(Server-Sent Events)`) |
| 코드·명령어 | 인라인 코드 블록 사용 (예: `` `notification_events` ``) |
| 단위 표기 | ms, KB, Mbps 등 국제 표준 단위 사용 |

## 5. 문서 종류별 작성 기준

### 기술 연구 문서 (`05-architecture/`, `member-XX/기술-연구/`)
- **구조**: 문제 제기 → 조사 → 비교 → 결론 순으로 작성
- 정량적 수치를 포함한다 (지연 시간, 처리량, 비율 등)
- 참고 자료는 문서 하단에 출처 링크와 함께 기재한다

### 회의록 (`06-meetings/`)
- **파일명**: `YYYY-MM-DD-회의-제목.md`
- **구조**: 참석자 → 안건 → 결정 사항 → 다음 Action Item 순으로 작성

### ADR 기술 결정 기록 (`07-decisions/`)
- **파일명**: `ADR-NNN-제목.md` (예: `ADR-001-실시간-아키텍처-선택.md`)
- **구조**: 배경 → 결정 → 이유 → 결과 → 대안 검토

### 개발 진행 사항 (`member-XX/개발-진행사항.md`)
- 스프린트 단위로 섹션을 나눈다
- 완료 항목, 진행 중 항목, 블로커를 구분하여 기록한다

### 포트폴리오 문서 (`member-XX/포트폴리오/`)
- **기여 내역**: 담당 기능, 설계 결정, 코드 구현 범위를 구체적으로 기술한다
- **트러블슈팅**: 문제 상황 → 원인 분석 → 해결 과정 → 결과 구조로 작성한다
- 정량 지표(응답 시간, 오류율, 개선 수치 등)를 포함하면 좋다

---

## 6. AI 작업 규칙

AI 도구가 이 프로젝트에서 문서를 작성·수정할 때 따르는 규칙이다.

### 반드시 지킬 것
- 파일 저장 경로는 위 폴더 구조를 따른다
- `01-planning/` 폴더의 기존 기획 자료는 **읽기만 한다. 수정하지 않는다**
- 상태가 **확정**인 문서는 수정 전 사용자에게 확인한다
- 타인의 `member-XX/` 폴더 문서는 해당 멤버 본인의 요청 없이 수정하지 않는다
- 문서 생성 전 동일한 이름의 파일이 이미 존재하는지 확인한다

### 하지 말 것
- 파일명에 날짜·버전 숫자를 임의로 붙이지 않는다 (`화면정의서-v2-final.md` 금지)
- 문서 내용 없이 폴더만 생성하지 않는다 (`.gitkeep` 제외)
- 규칙에 없는 폴더를 임의로 생성하지 않는다
- 한 문서에 여러 주제를 혼합하지 않는다. 주제당 파일 하나를 원칙으로 한다
