# 기획주간 1일차 OT 킥오프와 Repository 준비

## 목적

1일차는 약 2시간만 주어지는 OT 성격의 회차다. 세부 설계나 실제 구현보다 **팀 운영 방식 설명, 프로젝트 목표 공유, MVP 후보 방향, GitHub repository 생성 전 결정사항**을 맞추는 데 집중한다.

오늘은 repository를 완성하는 날이 아니라, 2일차에 바로 생성할 수 있도록 이름, owner, branch 원칙, 협업 흐름을 합의하는 날로 본다.

## 회의에서 먼저 정해야 할 것

아래 항목은 회의 중 합의하고 넘어간다. 이 결정이 없으면 2일차 기능 분해가 흔들린다.

| 결정 항목 | 결정 방식 | 확정 수준 |
|---|---|---|
| 프로젝트 한 줄 목표 | 후보 문장 1~2개 작성 후 선택 | 기능 집중형 협업 플랫폼 방향으로 결정 |
| 주요 사용자 | 일반 사용자/관리자 기준으로 단순화 | 2일차로 이월 |
| MVP 후보 | 필수/선택/보류로 나누기 | 2일차로 이월 |
| 보류 기능 원칙 | 실시간 채팅, 복잡한 전자결재 등 범위 초과 기능 분리 | 확정 |
| 기술 스택 | 팀 구현 가능성과 배포 범위 기준으로 확정 | MySQL 8.4, Spring Boot, React + Next, AWS EC2/RDS/S3 |
| repository 이름/owner | 팀장이 생성할지, 조직/개인 계정에 둘지 결정 | 팀장이 결정 후 2일차 생성 |
| Git 기본 원칙 | `main` 직접 push 금지, Issue→branch→PR 흐름 설명 | 팀장이 기준 확정 |

## 분업 가이드라인

| 작업 크기 | 배정 기준 | 예시 |
|---|---|---|
| 작음 | 1명 | 자료 검색, 후보 기능 조사 |
| 보통 | 2명 | 사용자 유형 정리, 기술 스택 후보 비교 |
| 큼 | 3명 | MVP 후보 기능 도출, 보류 기능 판단 |
| 중요/복합 | 3~4명 | 프로젝트 목표 합의, 발표에 들어갈 핵심 방향 정리 |

정철진은 Frontend 후보 스택, 화면 흐름, 발표에서 보이는 결과물과 연결되는 업무에 우선 배치한다. 여도현은 기술 판단, 기능 우선순위, 검토 업무처럼 난도가 높은 보조 업무에 우선 배치한다. 그 외 업무는 특정 이름 대신 필요한 인원수로 배정한다.

## 시작 회의 운영안

1일차는 실제 작업 시간이 짧으므로 시작 회의를 OT와 kickoff로 운영한다. 논의가 길어지면 세부 설계는 2일차로 넘긴다.

| 안건 | 진행 방식 | 결과 |
|---|---|---|
| 팀 운영 방식 설명 | 황스일이 기획주간 흐름 설명 | 회의-작업-공유-마무리 구조 이해 |
| 프로젝트 목표 논의 | 전체 의견 수렴 후 문장화 | 목표 초안 |
| MVP 후보 논의 | 기능을 필수/선택/보류 후보로 나눔 | MVP 후보 방향 |
| GitHub 흐름 설명 | Issue, branch, PR, review, merge 흐름 설명 | 협업 방식 이해 |
| repository 결정 | 이름, owner, 기본 branch, 직접 push 금지 원칙 합의 | 2일차 생성 준비 |
| 준비 과제 배정 | 작업 크기에 따라 1~4명 배정 | 2일차 준비 과제 |

## 팀원 작업 시간 운영

회의 후 남은 시간이 있으면 팀원들이 각자 배정된 조사/정리 작업을 진행한다. 시간이 부족하면 작업 착수보다 2일차 준비 항목을 명확히 남기는 것을 우선한다.

| 작업 묶음 | 내용 | 권장 인원 | 우선 배치 |
|---|---|---:|---|
| 그룹웨어 기능 사례 조사 | 공지, 일정, 업무, 관리자 기능 사례 수집 | 2~3명 | 여도현 포함 가능 |
| Frontend 기준 조사 | React + Next 기준 화면 구성, Three.js/TypeScript 적용 가능성 | 1~2명 | 정철진 우선 |
| MySQL/AWS 제약 조사 | MySQL 8.4, EC2/RDS/S3 범위, 배포 제약 | 2명 | 기술 이해도 높은 인원 |
| repository 준비 항목 정리 | repo 이름, README 한 줄 설명, branch naming 후보 | 1~2명 | 황스일 확인 |
| 발표 배경 자료 정리 | 왜 그룹웨어인지, 어떤 문제를 해결하는지 정리 | 1명 | 미배정 |

## 결과 공유 양식

팀원은 작업 후 Notion 또는 공용 채널에 아래 형식으로 공유한다.

```text
작업명:
참여 인원:
정리한 내용:
결정이 필요한 부분:
다음 회차에서 이어갈 일:
참고 링크 또는 자료:
```

## 황스일 종합 항목

황스일은 팀원 공유 내용을 바탕으로 아래를 정리한다.

- 프로젝트 한 줄 목표 후보
- 주요 사용자와 MVP 후보 이월 항목
- GitHub repository 이름, owner, 기본 branch 원칙 결정 필요 사항
- 확정 기술 스택: MySQL 8.4, Spring Boot, React + Next, AWS EC2/RDS/S3
- 2일차에서 먼저 확정해야 할 안건
- 발표에 사용할 배경/목표 문장 후보
- 2일차 기획서 초안 작성에 넘길 배경, 목적, 주요 기능, 기대효과 미정 입력값

## 마무리 회의 운영안

| 안건 | 확인할 내용 | 결과 |
|---|---|---|
| 작업 결과 공유 | 각 그룹이 3분 이내로 핵심만 공유 | 조사 결과 확인 |
| 결정사항 확정 | 목표 후보, 기술 스택, repo 결정 주체 | 2일차 입력값 확정 |
| 미정사항 정리 | 주요 사용자, MVP 후보, repo 이름/owner | 2일차 첫 안건으로 이월 |
| 다음날 브리핑 | 2일차 repo 생성, 사용자 흐름, 기능 분해 방식 안내 | 다음 회차 준비 완료 |
