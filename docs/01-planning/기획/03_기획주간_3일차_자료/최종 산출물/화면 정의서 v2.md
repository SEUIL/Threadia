# 화면 정의서 v2

## 1. 문서 목적

이 문서는 Day 3 확정 결정사항에 맞춰 화면별 목적, 접근 사용자, 주요 데이터, 액션, 연결 기능을 재정리한 v2 화면 정의서다. Day 3의 API와 Architecture 설계 입력값으로 사용한다.

관련 문서:

- [[사용자 시나리오 v2]]
- [[기능 분해표 v2]]

## 2. 화면 정의 기준 v2

| 항목 | 기준 |
|---|---|
| MVP 역할 | A/P/C 중심 |
| 보류 역할 | F 플랫폼 관리자 |
| 칸반 컬럼 | 백로그/할일/진행중/검토중/완료 |
| 프로젝트 채팅 | MVP |
| 1:1 DM | MVP. 같은 회사 구성원 전체 대상 |
| DM 진입점 | S09, S10, S14 |
| DM 제한 | DM 메시지는 이슈로 만들 수 없음. 다자간 DM과 DM 메시지 읽음 처리는 보류 |
| DM unread count | 채팅방별 unread count는 MVP |
| 쓰레드 | 이슈, 문서, 메시지 대상 논의 기능. 문서 단독 논의 UI는 두지 않음 |
| 알림 | MySQL 기반 알림함 + 전체 on/off + 이벤트별 on/off |
| S07/S08 그래프 뷰 | 문서·회의록과 이슈 연결 관계를 시각화하는 MVP 기능 |

| 프로젝트 홈/대시보드 | 선택 기능. MVP에서는 S04에서 S05 칸반으로 진입 |
| 활동 피드/통합 검색 | 선택 기능 |
| 프로젝트 생성 | 진입 화면은 정의하되 생성 필드는 Day 3 설계에서 확정 |

## 3. 전체 화면 흐름

```text
서비스 진입
└── S01 로그인
    ├── S02 회원가입
    └── S03 3D 사무실 메인 허브
        ├── S04 프로젝트 목록
        │   ├── S05 칸반 보드
        │   │   └── S10 쓰레드
        │   ├── S06 백로그 / 스프린트
        │   ├── S07 문서·회의록 목록 / 그래프 뷰
        │   │   └── S08 문서 편집기 / 그래프 뷰
        │   │       └── S10 쓰레드
        │   └── S12 프로젝트 설정
        ├── S09 프로젝트 채팅 / 1:1 DM
        │   └── S10 쓰레드
        ├── S11 알림
        └── S13 회사 관리
            └── S14 구성원·권한 관리
                └── S09 1:1 DM

MVP 보류
└── S15 플랫폼 관리자 대시보드

MVP 이후 선택
├── 프로젝트 홈/대시보드
├── 활동 피드
└── 통합 검색
```

| 항목 | 내용 |
|---|---|
| 접근 사용자 | A/P/C |
| 화면 목적 | 프로젝트 이슈 상태를 칸반으로 관리 |
| 주요 데이터 | 이슈, 담당자, 상태, 우선순위, 마감일, 연결 쓰레드, 연결 문서 |
| 주요 액션 | 이슈 생성, 카드 이동, 이슈 상세 열기, 쓰레드 진입, 관련 문서 연결/조회, 이슈 휴지통 처리 |
| 연결 기능 | ISSUE-01, ISSUE-02, ISSUE-04, KANBAN-01, KANBAN-02, THREAD-01, LINK-02 |
| 연결 화면 | S06, S08, S10, S11, S12 |

칸반 컬럼은 다음 5개로 고정한다.

```text
백로그 → 할일 → 진행중 → 검토중 → 완료
```

상태 의미:

| 컬럼 | 의미 |
|---|---|
| 백로그 | 아직 Sprint나 담당자 확정 전인 후보 이슈 |
| 할일 | 담당자가 정해졌지만 아직 착수하지 않은 이슈 |
| 진행중 | 담당자가 작업 중인 이슈 |
| 검토중 | PM 리뷰를 기다리는 이슈 |
| 완료 | 리뷰가 끝난 이슈 |

설계 메모:

- 이슈 상세 패널에서 연결된 문서, 회의록, 쓰레드를 함께 조회할 수 있다.
- 이슈와 문서가 연결되면 `S07/S08 그래프 뷰`에 이슈-문서 연결선으로 반영된다.
- 이슈 삭제는 즉시 삭제가 아니라 휴지통 보관으로 처리하고, 휴지통에서 복원 또는 영구 삭제할 수 있다.

### S07 · 문서·회의록 목록 / 그래프 뷰

| 항목 | 내용 |
|---|---|
| 접근 사용자 | A/P/C |
| 화면 목적 | 프로젝트 내 `.md` 문서와 회의록 목록 조회, 문서·회의록과 이슈의 연결 관계 확인 |
| 주요 데이터 | 문서명, 유형, 작성자, 수정일, 연결 이슈 수, 그래프 노드, 그래프 엣지 |
| 주요 액션 | 문서 열기, 새 문서 작성, 목록 뷰/그래프 뷰 전환, 그래프 노드 선택, 문서 휴지통 처리 |
| 연결 기능 | DOC-01, DOC-02, DOC-03, DOC-04, GRAPH-01, GRAPH-02 |
| 연결 화면 | S08, S05 |

설계 메모:

- 상단 탭을 통해 `목록 뷰`와 `지식 네트워크 그래프 뷰`를 전환한다.
- 그래프 뷰는 문서 간 링크만 보여주는 기능이 아니라 프로젝트 내 문서·회의록과 이슈의 연결 관계를 시각화한다.
- 연결되지 않은 문서와 이슈는 노드로만 표시하고, 문서-이슈 연결이 생성되면 그래프에 엣지로 반영한다.
- 노드 클릭 시 화면 이동 없이 우측 서랍 패널에서 미리보기와 연결 정보 조회가 가능하다.
- 탭 전환 시 그래프 캔버스 재로딩을 방지하기 위해 프론트엔드 상태 보존 규칙을 적용한다.

### S08 · 문서 편집기 / 그래프 뷰

| 항목 | 내용 |
|---|---|
| 접근 사용자 | A/P/C |
| 화면 목적 | Markdown 문서와 회의록 작성/수정, 관련 이슈 연결, 문서 맥락 쓰레드 열기 |
| 주요 데이터 | 제목, 본문 Markdown, 문서 유형, 관련 이슈, 작성자, 연결 쓰레드, 그래프 연결 상태 |
| 주요 액션 | 저장, 미리보기, 관련 이슈 연결, 문서에서 이슈 이동, 문서 쓰레드 열기, 그래프 뷰 확인, 문서 휴지통 처리 |
| 연결 기능 | DOC-02, DOC-03, DOC-04, LINK-02, LINK-03, THREAD-01, GRAPH-01, GRAPH-02 |
| 연결 화면 | S07, S05, S10, S11 |

설계 메모:

- 모든 문서는 `.md` 형식으로 저장한다.
- 문서와 이슈는 양방향 연결을 제공한다.
- 별도의 문서 단독 논의 기능은 두지 않는다. 문서 맥락의 논의는 `S10 쓰레드`로 연다.
- 문서 저장 자체는 노드 정보를 최신화하고, 문서-이슈 연결이 발생할 때 그래프에 엣지가 반영된다.
- 문서 수정 또는 문서 쓰레드 @멘션 이벤트는 S11 알림으로 연결한다.
- 문서 삭제는 즉시 삭제가 아니라 휴지통 보관으로 처리하고, 휴지통에서 복원 또는 영구 삭제할 수 있다.

### S09 · 프로젝트 채팅 / 1:1 DM

| 항목 | 내용 |
|---|---|
| 접근 사용자 | A/P/C |
| 화면 목적 | 프로젝트 단위 빠른 소통과 회사 구성원 간 1:1 DM 제공 |
| 주요 데이터 | 프로젝트 채널, 프로젝트 메시지, DM 방, DM 메시지, 작성자, unread count |
| 주요 액션 | 프로젝트 메시지 작성, 프로젝트 메시지에서 이슈 생성, 쓰레드 보기, 1:1 DM 시작/전송, 채팅방 unread count 확인 |
| 연결 기능 | CHAT-01, CHAT-02, CHAT-03, LINK-01, THREAD-01 |
| 연결 화면 | S05, S10, S11, S14 |

설계 메모:

- 프로젝트 채팅은 MVP 협업 흐름에 포함한다.
- `1:1 DM`도 MVP에 포함한다.
- DM 대상은 같은 회사 구성원 전체다.
- `S09` 안에서 프로젝트 채팅과 1:1 DM을 탭 또는 목록으로 분리한다.
- `S10`의 사용자 프로필/작성자 영역에서 특정 사용자와 DM을 시작할 수 있다.
- `S14` 구성원 목록에서 특정 구성원과 DM을 시작할 수 있다.
- 프로젝트 채팅 메시지는 이슈로 만들 수 있다.
- DM 메시지는 이슈로 만들 수 없다.
- 다자간 DM과 DM 메시지 읽음 처리는 MVP에서 제외한다.
- 채팅방별 unread count는 MVP에 포함한다.
- 채팅/DM 메시지는 삭제할 수 없다.

설계 메모:

- 하나의 대상에는 대표 쓰레드 하나만 둔다.
- 상위 컨텍스트 배너는 연결 이슈/문서/메시지를 항상 보여준다.
- 문서 맥락의 논의도 이 화면의 쓰레드로 처리한다.
- 쓰레드에서 나온 주제는 이슈와 연결할 수 있다.
- 쓰레드 댓글은 삭제할 수 없다.
- 쓰레드 댓글 전체가 알림을 만들지는 않는다. 자신이 @멘션된 경우에만 알림을 생성한다.
- 댓글 작성자 또는 멘션된 사용자 프로필에서 `S09 1:1 DM`으로 이동할 수 있다.

### S11 · 알림

| 항목 | 내용 |
|---|---|
| 접근 사용자 | A/P/C |
| 화면 목적 | 업무, 문서, 쓰레드 멘션, 채팅/DM, 권한 변경 알림을 한 화면에서 확인하고 이벤트별 수신 여부를 설정 |
| 주요 데이터 | 알림 유형, 제목, 본문, 발신자, 대상 화면, 읽음 여부, 전체 on/off, 이벤트별 on/off |
| 주요 액션 | 알림 목록 조회, 읽음 처리, 모두 읽음, 알림 항목 클릭 이동, 전체 알림 on/off, 이벤트별 알림 on/off |
| 연결 기능 | NOTI-01, NOTI-02, NOTI-03 |
| 연결 화면 | S05, S06, S08, S09, S10, S12, S14 |

MySQL 1차 구현 기준:

| 저장 단위 | 역할 |
|---|---|
| notification_event | 어떤 일이 발생했는지 저장 |
| notification_recipient | 누가 받았고 읽었는지 저장 |
| notification_preference | 사용자/역할/범위별 전체 및 이벤트별 on/off 설정 저장 |

알림 이벤트 MVP 범위:

| 이벤트 | 알림 기준 |
|---|---|
| 이슈 할당 | 담당자에게 알림 |
| 이슈 상태 변경 | 관련자에게 알림 |
| 쓰레드 댓글 | 자신이 @멘션된 경우만 알림 |
| 문서 수정 | 연결된 이슈 담당자/관련자 기준 알림 |
| 문서에서 열린 쓰레드 | 쓰레드 @멘션 규칙 적용 |
| 프로젝트 채팅 메시지 | 사용자 설정에 따라 알림 |
| 1:1 DM 메시지 | 사용자 설정에 따라 알림 |
| 구성원 초대/권한 변경 | 대상 사용자에게 알림 |

설계 메모:

- 사용자는 알림 피로도를 이벤트별 on/off로 조절할 수 있다.
- 채널별, 시간대별, 조건별 자동화 설정은 MVP 이후 고도화다.
- Redis는 unread count 캐시나 WebSocket/SSE 신호가 필요해진 뒤 검토한다.
- NoSQL은 활동 피드나 대량 이벤트 저장이 필요해진 뒤 검토한다.
