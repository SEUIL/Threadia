## 1. 문서 목적

이 문서는 사용자 시나리오 v2와 화면 정의서 v2를 연결하는 최종 기능 범위표다. Day 3의 ERD, API, Architecture 설계에서 기능 누락과 범위 충돌을 막기 위한 기준으로 사용한다.

## 2. 기능 분류 기준

| 우선순위 | 기준 |
|---|---|
| MVP | 없으면 핵심 시연 흐름이 성립하지 않는 기능 |
| 선택 | 시간이 남으면 붙일 수 있으나 핵심 흐름에는 필수는 아닌 기능 |
| 보류 | 구현 리스크가 크거나 MVP 범위를 넓히는 기능 |

## 6. 문서-이슈-메시지-쓰레드 연결 기능

Threadia의 차별점은 채팅, DM, 업무, 문서, 쓰레드가 분리되지 않고 연결되는 것이다. 단, DM은 사적 보조 소통이므로 메시지를 이슈로 만들 수 없다.

```mermaid
flowchart LR
    MSG[S09 프로젝트 채팅 메시지] -->|이슈로 만들기| ISSUE[S05 이슈]
    DM[S09 1:1 DM] -. 이슈 전환 불가 .-> ISSUE
    ISSUE -->|논의| THREAD[S10 쓰레드]
    DOC[S08 문서·회의록] -->|문서에서 쓰레드 열기| THREAD
    THREAD -->|주제 연결| ISSUE
    ISSUE <-->|양방향 연결| DOC
    DOC <-->|관계 시각화| GRAPH[S07/S08 그래프 뷰]
    ISSUE <-->|관계 시각화| GRAPH
    THREAD -->|@멘션 알림| NOTI[S11 알림]
    DOC -->|수정 알림| NOTI
```

| 연결 | MVP 동작 |
|---|---|
| 프로젝트 채팅 → 이슈 | 프로젝트 채팅 메시지를 이슈로 만들고 원본 메시지 링크를 보존 |
| DM → 이슈 | 불가. DM은 이슈 생성 대상에서 제외 |
| 이슈 → 쓰레드 | 이슈별 대표 쓰레드에서 논의 |
| 문서 → 쓰레드 | 문서에서 쓰레드를 열어 문서 맥락의 논의를 보존 |
| 쓰레드 → 이슈 | 쓰레드에서 나온 주제를 이슈와 연결 가능 |
| 이슈 ↔ 문서 | 이슈에서 관련 문서를 열고, 문서에서 관련 이슈 상태 확인 |
| 그래프 뷰 | 문서·회의록과 이슈의 연결 관계를 노드/엣지로 표시 |
| 문서/쓰레드 → 알림 | 문서 수정, 쓰레드 @멘션 이벤트가 MySQL 알림으로 저장 |

| 기능 | MVP 범위 | 이후 확장 |
|---|---|---|
| 알림 원본 저장 | MySQL `notification_event` | 대량 이벤트 분석 시 Document DB 검토 |
| 사용자별 수신/읽음 | MySQL `notification_recipient` | unread count 캐시 필요 시 Redis 검토 |
| 전체 알림 설정 | MySQL `notification_preference`의 master on/off | 채널별/시간대별 설정은 제외 |
| 이벤트별 알림 설정 | 이슈, 쓰레드 멘션, 문서, 채팅/DM, 초대/권한 이벤트별 on/off | 조건별 자동화 규칙은 제외 |
| 실시간 신호 | 1차 구현에서는 인앱 조회 중심 | WebSocket/SSE + Redis는 추후 검토 |

### 7.1 알림 이벤트 MVP 포함 범위

| 이벤트 | MVP 포함 | 비고 |
|---|---|---|
| 이슈 할당 | 포함 | 담당자에게 알림 |
| 이슈 상태 변경 | 포함 | 관련자에게 알림 |
| 쓰레드 댓글 | 조건부 포함 | 자신이 @멘션된 경우만 알림 |
| 멘션 | 포함 | 쓰레드 @멘션 기준 |
| 문서 수정 | 포함 | 연결된 이슈 담당자/관련자 기준 |
| 문서에서 열린 쓰레드 | 포함 | 쓰레드 @멘션 규칙 적용 |
| 프로젝트 채팅 메시지 | 포함 | 사용자가 on/off 가능 |
| 1:1 DM 메시지 | 포함 | 사용자가 on/off 가능 |
| 구성원 추가/권한 변경 | 포함 | 추가 대상, 권한 변경 대상에게 알림 |
