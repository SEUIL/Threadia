## 2. 인증 (Authentication)

### 2.1 MVP 범위

| 기능 | 구현 여부 | 비고 |
|---|---|---|
| 이메일 + 비밀번호 로그인 | MVP | AUTH-02 |
| 회원가입 | MVP | AUTH-01 |
| 로그아웃 | MVP | 클라이언트 토큰 제거 |
| JWT 기반 세션 관리 | MVP | Access Token + Refresh Token 구조 권장 |
| 소셜 로그인 | 보류 | MVP 이후 검토 |
| 비밀번호 찾기 / 재설정 | 보류 | MVP 이후 검토 |

### 2.2 인증 흐름

```text
S01 로그인
  → 이메일/비밀번호 검증
  → JWT 발급 (Access Token + Refresh Token)
  → S03 3D 사무실 메인 허브 진입

비로그인 사용자
  → S01, S02 이외 모든 화면 접근 차단
  → S01 로그인 화면으로 리다이렉트
```

### 2.3 연결 화면 및 API

| 화면 | API 후보 |
|---|---|
| S01 로그인 | `POST /auth/login` |
| S02 회원가입 | `POST /auth/signup` |
| 로그아웃 | `POST /auth/logout` |
| 토큰 갱신 | `POST /auth/refresh` |

## 3. 인가 모델 (Authorization)

### 3.1 핵심 원칙

권한은 사용자 계정 자체에 고정하지 않는다.  
**회사 소속(CompanyMember)** 과 **프로젝트 소속(ProjectMember)** 관계에 역할을 부여한다.

> 같은 사용자가 A 회사에서는 C(회사 관리자)이고, B 프로젝트에서는 A(일반 사용자)일 수 있다.

### 3.2 역할 정의

| 코드 | 역할명 | 관리 범위 |
|---|---|---|
| A | 일반 사용자 | 소속 프로젝트 내 업무 수행 |
| P | 프로젝트 관리자 | 특정 프로젝트 운영 전반 |
| C | 회사 관리자 | 특정 회사 전체 (구성원, 프로젝트 조망) |

### 3.3 역할 부여 구조

```text
User (계정)
  └── CompanyMember (회사 소속)
        └── role: A / P / C
  └── ProjectMember (프로젝트 소속)
        └── role: A / P
```

- C(회사 관리자)는 CompanyMember.role로 부여한다.
- P(프로젝트 관리자)는 ProjectMember.role로 부여한다.
- A(일반 사용자)는 별도의 역할 지정 없이 ProjectMember에 속하는 것으로 간주한다.
- C는 P 권한을 포함한 모든 화면에 접근 가능하다.

## 6. API 인가 처리 기준

### 6.1 인가 검사 순서

```text
1. JWT 유효성 검사 → 실패 시 401 Unauthorized
2. 요청 리소스의 회사/프로젝트 소속 확인
3. CompanyMember.role 또는 ProjectMember.role 확인
4. 역할에 따른 허용/차단 → 차단 시 403 Forbidden
```

### 6.2 주요 API별 인가 기준

| API | 허용 역할 | 비고 |
|---|---|---|
| `GET /projects` | A/P/C | 소속 프로젝트만 조회 |
| `POST /projects` | P/C | |
| `PUT /projects/:id` | P/C | 해당 프로젝트의 P/C만 |
| `GET /issues` | A/P/C | 소속 프로젝트 이슈만 |
| `POST /issues` | A/P/C | |
| `PUT /issues/:id/assignee` | P/C | |
| `PUT /issues/:id/status` (완료) | P/C | |
| `POST /sprints` | P/C | |
| `PUT /sprints/:id/start` | P/C | |
| `GET /companies/:id` | C | 소속 회사만 |
| `PUT /companies/:id` | C | |
| `GET /company-members` | C | |
| `POST /company-members/invite` | C | |
| `PUT /company-members/:id/role` | C | |

## 9. Day 3 ERD/API 입력값

| 영역 | 후보 |
|---|---|
| Entity | User, CompanyMember, ProjectMember |
| 주요 필드 | `CompanyMember.role` (A/P/C), `ProjectMember.role` (A/P) |
