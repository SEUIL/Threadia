# QAO 재검토 - MVP 범위 변경 반영 메모 QA

## 0. 최종 판정

판정: 조건부 승인 유지

`사용자시나리오_재검토_MVP범위변경_반영메모.md`는 회의 결정에 따라 기존 UXD/QAO의 “MVP 제외/선택/보류 권고”를 “MVP 포함 + 최소 구현 기준 명세 필요”로 재해석한다. 이 방향 자체는 수용 가능하다. 다만 원문 `사용자 시나리오.md`, `화면 정의서.md`, `기능 분해표.md`에는 아직 1:1 DM, 문서 댓글, 알림 세부 설정, 활동 피드/통합 검색, S13 부서/로고/통계가 선택/보류 또는 미확정으로 남아 있으므로 무조건 승인으로 바꾸면 Day 3 API/ERD/QA 범위가 다시 충돌한다.

따라서 기존 QAO 판정은 `조건부 승인`으로 유지하되, 조건의 성격을 다음처럼 변경한다.

- 기존 조건: 범위 과대 항목을 MVP처럼 보이지 않게 분리한다.
- 변경 조건: 회의에서 MVP 포함으로 결정된 항목을 `최소 MVP 기준`과 `MVP 이후 고도화 기준`으로 명확히 나누고, 원문 3종의 MVP/선택/보류 표현을 일괄 정정한다.

## 3. 새로 생긴 QA 이슈

### NEW-QA-01. 선택/보류 기능을 MVP로 되돌리면서 원문 3종과 충돌

MVP 범위 변경 메모는 1:1 DM, DOC-04, 알림 세부 설정, 활동 피드/통합 검색, S13 부서/로고/통계, 공통 컨텍스트 배너를 MVP 포함으로 재해석한다. 그러나 기존 원문은 아직 다음처럼 남아 있다.

- `사용자 시나리오.md`: 1:1 DM 선택, 알림 세부 설정 선택, 통합 검색 후순위.
- `화면 정의서.md`: S09가 MVP/선택 혼합 표기, NOTI-03 선택, 활동 피드 분리 여부 미확정.
- `기능 분해표.md`: CHAT-02, DOC-04, NOTI-03, FEED-01, SEARCH-01이 선택 또는 후순위.

조치: 메모만 추가하지 말고 원문 3종의 우선순위 표기와 Day 3 입력값을 함께 수정해야 한다.

### NEW-QA-02. 1:1 DM MVP 포함 기준이 아직 테스트 가능한 수준이 아님

메모는 1:1 DM을 “프로젝트 업무 맥락을 해치지 않는 최소 DM”으로 정의하라고 한다. 하지만 최소 DM의 범위가 아직 모호하다.

반드시 정해야 할 QA 기준:

- DM은 프로젝트 소속 멤버끼리만 가능한가, 회사 구성원 전체가 가능한가.
- DM 메시지를 이슈로 만들 수 있는가, 아니면 프로젝트 채팅만 이슈 생성이 가능한가.
- DM 알림은 S11에 들어오는가.
- DM의 읽음 여부는 MVP에 포함되는가.
- 업무 결정사항을 DM에만 남기지 않게 하는 UX 문구 또는 연결 CTA가 있는가.

### NEW-QA-03. 문서 댓글 MVP 포함 시 S10 쓰레드와 중복 구현 위험이 커짐

기존 QAO는 DOC-04를 선택 기능으로 분리하라고 했으나, 새 메모는 문서 댓글도 MVP에 포함한다. 이 경우 “문서 댓글”과 “S10 문서/이슈/메시지 대상 쓰레드”가 모두 MVP가 되어 댓글 시스템이 이중화될 수 있다.

반드시 정해야 할 QA 기준:

- 문서 댓글은 문서 단위인가, 블록/문단 단위인가.
- 문서 댓글이 S10 쓰레드와 같은 Thread/ThreadComment 모델을 공유하는가, 별도 DocumentComment인가.
- 문서 댓글 알림은 `LINK-03`인지 `NOTI-01` 이벤트인지.
- 결정사항/이슈 상태 논의는 S10으로 남기고, 문서 문맥 피드백만 DOC-04로 제한한다는 문구가 있는가.

### NEW-QA-04. 알림 세부 설정을 MVP 포함으로 바꾸면 NOTI-02/NOTI-03 경계가 깨짐

기능 분해표는 NOTI-02를 기본 on/off MVP, NOTI-03을 세부 설정 선택으로 두고 있다. 메모는 “최소 유형별 on/off”까지 MVP에 포함하라고 한다. 그러면 NOTI-03 전체를 MVP로 승격할지, NOTI-02의 세부 설명을 넓힐지 결정해야 한다.

권장 QA 기준:

- MVP 알림 설정은 `전체 on/off + 최소 유형별 on/off`로 제한.
- 최소 유형 후보: 이슈 배정/상태 변경, 쓰레드 멘션·댓글, 문서 수정·댓글, 채팅·DM 메시지, 초대·권한 변경.
- 제외: 채널별, 시간대별, 조건별, 자동화 규칙, 사용자별 예외.

### NEW-QA-05. 활동 피드와 통합 검색이 MVP에 포함되지만 화면/기능 ID 위치가 불명확

메모는 활동 피드/통합 검색을 MVP 포함으로 바꾸되 “프로젝트/업무 맥락 회수용 최소 검색·피드”로 제한하라고 한다. 그러나 기존 문서에는 SEARCH-01 연결 화면이 `미정`이고, FEED-01도 S04/S11 선택이다.

반드시 정해야 할 QA 기준:

- 통합 검색 진입 위치: S03 전역 검색인지, S04 프로젝트 검색인지, S05/S07/S09 내부 검색인지.
- 검색 대상: 이슈, 문서, 메시지, 댓글 중 어디까지인지.
- 검색 필터: 프로젝트 범위, 작성자, 날짜, 타입 정도만 MVP인지.
- 활동 피드 위치: S11 알림 안의 탭인지, S04 프로젝트 상세 영역인지, 별도 화면인지.

### NEW-QA-06. S13 부서/로고/통계가 MVP 포함으로 바뀌면서 C 초기 세팅 흐름이 과밀해질 수 있음

메모는 S13 부서/로고/통계를 MVP 포함으로 바꾸되 회사 초기 세팅을 방해하지 않는 보조 정보로 배치하라고 한다. 기존 화면 정의서는 회사 로고, 구성원 수, 부서 수, 프로젝트 수를 S13 주요 데이터로 포함하고, 부서 추가는 선택으로 둔다.

반드시 정해야 할 QA 기준:

- 로고: 업로드 필수인지 기본 로고 허용인지.
- 부서: 부서명 표시만 MVP인지, 부서 생성/수정까지 MVP인지.
- 통계: 구성원 수/부서 수/프로젝트 수 같은 단순 count만 MVP인지.
- 제외: 조직도, 부서별 성과, 프로젝트별 분석 대시보드.

## 5. 최종 QA 체크리스트

### 5.3 A/P/C 권한

### 5.4 범위 과대 방지

- [ ] 1:1 DM은 다자간 DM, 고급 읽음, 고급 검색, 무한 스크롤까지 확장되지 않는가.
- [ ] 문서 댓글은 실시간 공동 편집, 버전별 댓글, 복잡한 권한 댓글로 확장되지 않는가.
- [ ] 알림 설정은 채널별/시간대별/조건별 자동화로 확장되지 않는가.
- [ ] 통합 검색은 전체 회사 검색/고급 검색 제품으로 확장되지 않는가.
- [ ] 활동 피드는 별도 대형 SNS형 타임라인으로 확장되지 않는가.
- [ ] S13 통계는 성과 분석 대시보드로 확장되지 않는가.
- [ ] 공통 컨텍스트 배너는 전 화면 공통 대형 UI 컴포넌트 개발로 해석되지 않는가.

## 6. 최종 QAO 의견

MVP 범위 변경 메모는 기존 QAO의 “제외/분리” 권고를 회의 결정에 맞게 “최소 기준 명세”로 바꾸는 문서로는 타당하다. 그러나 이 메모만으로 기존 7개 조건이 해소되지는 않는다. 특히 원문 3종의 우선순위 표기와 기능 ID가 아직 이전 기준을 유지하고 있어 Day 3 설계자가 서로 다른 범위표를 읽을 위험이 있다.

따라서 최종 판정은 `조건부 승인 유지`다. 승인 조건은 다음 3개로 압축한다.

1. 원문 3종에서 선택/보류로 남은 항목을 회의 결정에 맞게 `MVP 최소 기준`으로 재분류한다.
2. 새로 MVP에 들어온 DM, 문서 댓글, 알림 세부 설정, 활동 피드/검색, S13 부가 정보의 고도화 제외 범위를 명시한다.
3. 기존 미해소 항목인 CoWork 명칭, 기능 ID 누락, A/P/C 권한, 프로젝트 생성/상태/초대/알림 미확정 항목을 Day 3 입력값으로 빠짐없이 넘긴다.
