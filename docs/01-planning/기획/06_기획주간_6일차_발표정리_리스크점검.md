# 기획주간 6일차 보고 정리와 리스크 점검

## 목적

6일차 문서는 기획주간을 닫고 Week 2 개발 착수 여부를 확인하기 위한 최종 보고 메모다. 새 정책을 만드는 문서가 아니라, `06_기획주간_6일차_자료/최종 산출물/README.md` 기준으로 **보고 순서, Sprint 범위, 리스크, Week 2 진입 조건**을 압축한다.

2026-06-17 기준 최종 산출물은 `06_기획주간_6일차_자료/최종 산출물/` 아래에 정리되었다. 발표와 Week 2 진입 판단에서는 Sprint 1을 Auth-only 개발 착수 범위로 설명하고, invitation은 Sprint 1.5, 회사/프로젝트/이슈/문서/채팅/알림 등 broader MVP 기능은 Sprint 2 이후로 분리한다.

## 개발 진입 리스크 메모

| 리스크 | 영향 | 대응 |
|---|---|---|
| Sprint 1 범위 과확장 | Auth 품질과 통합 검증이 흔들림 | Sprint 1은 Auth-only로 고정하고 broader MVP는 Sprint 2 이후로 분리 |
| invitation 범위 혼선 | 초대 기능이 Auth 구현에 섞임 | Sprint 1.5 registered-user app-internal invitation으로 별도 관리 |
| Java/Gradle 환경 불일치 | Backend local 실행 실패 | Java 17 기준을 고정하고 kickoff에서 실행 환경 확인 |
| MySQL 8.4 실행 방식 불일치 | DB 연결과 migration 검증 지연 | Sprint 1은 local MySQL 8.4 연결과 Auth table migration만 우선 |
| Google OAuth 설정 지연 | 소셜 로그인 구현 지연 | Client ID/Secret, callback URL, secret 비노출 관리 기준을 먼저 확인 |
| Google SMTP 설정 지연 | password reset 검증 지연 | SMTP credential 관리 방식과 실제 수신 email 확인 기준을 준비 |
| JWT 정책 누락 | login/logout/refresh/me 동작 불일치 | access 30분, refresh 14일, hash 저장, rotation/logout invalidation 기준 유지 |
| CI 설정 지연 | PR 품질 관리 실패 | skeleton 이후 GitHub Actions에서 test/build check를 연결 |
| 문서와 코드 불일치 | 개발 중 기준 혼선 | PR Template에 문서 변경 여부와 검증 기록을 남김 |
