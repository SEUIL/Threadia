# 기획주간 6일차 보고 정리와 리스크 점검

## 목적

6일차는 1~5일차 기획 산출물을 보고 가능한 형태로 묶어 **보고 순서, 핵심 흐름 요약, 리스크 메모, Week 2 진입 조건 checklist, 제출 문서 상태표, PPT 제작 입력값**을 정리하는 날이다.

2026-06-17 기준 5일차 최종 산출물은 `05_기획주간_5일차_자료/최종 산출물/README.md` 기준으로 정리되었다. 따라서 6일차 보고에서는 Sprint 1을 Auth-only 개발 착수 범위로 설명하고, 전체 MVP 기능은 후속 sprint reference contract로 분리해서 설명한다. invitation은 Sprint 1에 포함하지 않고 Sprint 1.5 registered-user app-internal invitation으로 보고한다.

## 5일차 최종 산출물 반영 기준

| 항목 | 6일차 반영 기준 |
|---|---|
| 최종 산출물 위치 | `05_기획주간_5일차_자료/최종 산출물/` |
| 최종 확인용 본문 | 17개 Markdown 본문. Phase B invitation 반영본 13개, Phase A 기준본/보정본 4개 |
| README 양식 | 상단 문서 링크 목록 → `---` → `# README` → 구성/위치/기준/목록 순서 유지 |
| Sprint 1 구현 범위 | Auth-only, Spring Boot/MySQL/Frontend skeleton, CI/PR baseline, Auth flows |
| Sprint 1 제외 범위 | 회사, 프로젝트, 이슈, 문서, 채팅, DM, 쓰레드, 알림, 프로필 수정, invitation 구현 |
| Sprint 1.5 범위 | 등록 사용자 대상 app-internal invitation |
| Sprint 2 이후 후보 | actual invitee email sending, token link acceptance, unregistered onboarding, resend, email template, delivery failure handling, batch cleanup/operations |

## 전회차 입력값

| 입력값 | 현재 상태 | 6일차 처리 |
|---|---|---|
| 최종 MVP 범위 후보 | 기능 분해표/보류표/추적표 최종본에 정리됨 | Sprint 1 구현 범위와 전체 MVP reference를 분리해 보고 |
| Sprint 1 목표 | Auth-only 목표 문장 확정 | Week 2 개발 착수 방향으로 보고 |
| Sprint 1 Backlog | `Sprint1_Backlog 정합도-v1 invitation-v1.md` 확정 | Day 1~5 Auth 작업 흐름으로 요약 |
| 작업별 담당 그룹/역할 | `Sprint1_담당그룹_역할분담 v1.1 정합도-v1.md` 확정 | 지원 담당, Owner, Reviewer 구조로 보고 |
| Definition of Done | 최종 산출물에 포함 | 품질 기준 요약에 반영 |

| AWS 사용 범위 | EC2/RDS/S3 사용 방향 확정, 실제 배포와 S3 파일 저장은 Sprint 1 이후 | 범위 과확장 방지 리스크로 보고 |
| GitHub repository와 clone 확인 결과 | Week 2 시작 전 확인 항목 | 진입 조건 checklist에 유지 |

5일차 산출물은 더 이상 빈 입력값이 아니라 6일차 보고의 기준 자료다. 6일차 작업은 새 정책을 만드는 것이 아니라, 확정된 산출물을 발표와 Week 2 착수 판단 형식으로 압축하는 일이다.
