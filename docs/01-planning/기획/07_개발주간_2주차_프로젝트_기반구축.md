# 개발주간 2주차 프로젝트 기반 구축

## 목적

2주차는 기획주간에서 정한 방향을 실제 개발 가능한 상태로 바꾸는 주차다. 목표는 기능 완성보다 **repository, Backend/Frontend 기본 구조, MySQL 연결, PR/CI 검증 흐름**을 먼저 안정화하는 것이다.

프로젝트 방향은 **Jira + Confluence + Slack을 합쳐놓은 경량 애자일 협업 플랫폼**으로 본다. 2주차에는 이 방향을 기준으로 업무/이슈, 문서/회의록, 공지/알림의 기반을 만든다.

## 2주차 핵심 목표

| 목표 | 완료 기준 |
|---|---|
| repository 협업 기반 구축 | 팀원이 clone하고 branch/PR 흐름으로 작업 가능 |
| Spring Boot 기본 구조 생성 | local에서 서버 실행 가능 |
| MySQL 8.4 연결 확인 | test DB 연결 또는 간단 query 성공 |
| React + Next 기본 구조 생성 | 브라우저에서 기본 화면과 routing 확인 가능 |
| 핵심 domain 초안 작성 | User, Project, Issue, Document, Notice 후보 정리 |
| CI/PR 검증 흐름 시작 | PR에서 test 또는 build 확인 가능 |

## 확정 기술 스택

| 영역 | 결정 |
|---|---|
| Backend | Spring Boot |
| DB | MySQL 8.4 |
| Frontend | React + Next |
| Frontend 후보 확장 | Three.js, TypeScript는 필요할 때만 적용 |
| AWS | EC2, RDS, S3. 사용은 확정하되 실제 배포와 S3 파일 저장 구현은 Sprint 1 이후 |
| 협업 | GitHub Issue, branch, PR, review, merge |

## 2주차 해야될 목록

| 번호 | 해야될 일 | 산출물 | 권장 담당 그룹 |
|---:|---|---|---|
| 1 | GitHub repository 생성/정리 | repo URL, 팀원 초대, clone 확인 | 황스일 주도, 1~2명 |
| 2 | branch/PR 기본 흐름 적용 | branch naming, PR 규칙 초안 | 1~2명 |
| 3 | Spring Boot 프로젝트 생성 | backend 기본 실행 | Backend 1~2명 |
| 4 | MySQL 8.4 local 연결 확인 | DB 연결 결과, 설정 문서 | Backend/DB 2명 |
| 5 | React + Next 프로젝트 생성 | frontend 기본 실행 | 정철진 중심, 1~2명 |
| 6 | 핵심 domain/entity 후보 작성 | User, Project, Issue, Document, Notice 초안 | 여도현 포함, 2~3명 |
| 7 | 기본 API 후보 작성 | 인증, 업무/이슈, 문서, 공지 API 초안 | Backend 2명 |
| 8 | 기본 화면/라우팅 후보 작성 | 로그인, 대시보드, 업무, 문서, 공지 화면 초안 | Frontend 2명 |
| 9 | README 초안 작성 | local 실행 방법, 기술 스택, 협업 규칙 | 1명 |
| 10 | CI 초안 적용 | PR test/build check | 1~2명 |
| 11 | 개발 명세서 초안 갱신 | 기능, 경로/파일, 완료 조건, 검증 방법 | 황스일/여도현 중심, 2명 |

## 2주차에 하지 않을 것

- AWS 배포 완성 및 S3 파일 저장 구현
- 실시간 채팅 구현
- 복잡한 전자결재 구현
- Three.js 기반 3D 기능을 핵심 기능으로 고정
- 전체 기능을 한 번에 완성하려는 작업
- 검증 없이 `main`에 직접 push

## Sprint 1 Backlog 초안

| 작업 | 완료 조건 | 검증 방법 | 의존성 |
|---|---|---|---|
| repository 생성 | 팀원 clone 가능 | 팀원 1명 이상 clone 확인 | repo 이름/owner 결정 |
| Spring Boot 초기화 | 서버 local 실행 | `./gradlew bootRun` | repository |
| MySQL 연결 | test DB 연결 성공 | 연결 test 또는 query | MySQL 실행 환경 |
| React + Next 초기화 | 기본 페이지 실행 | 브라우저 확인 | repository |
| domain 초안 | 핵심 entity 후보 정리 | ERD/API 회의 확인 | MVP 범위 |
| PR Template 초안 | PR 작성 기준 존재 | 첫 PR에서 확인 | Git 규칙 |
| CI 초안 | PR에서 test/build 실행 | GitHub Actions check | Backend 구조 |
| 개발 명세서 초안 | 기능별 구현 기준과 검증 기준 정리 | 팀원이 보고 작업 가능 여부 확인 | Backlog, API/화면 후보 |

## Week 2 종료 조건

- [ ] 팀원이 repository를 clone할 수 있다.
- [ ] `main` 직접 push 금지 원칙이 공유되었다.
- [ ] Spring Boot 서버가 local에서 실행된다.
- [ ] React + Next 기본 화면이 브라우저에서 열린다.
- [ ] MySQL 8.4 연결 기준이 정해졌다.
- [ ] 핵심 domain/entity 후보가 있다.
- [ ] 주요 API 후보가 있다.
- [ ] README에 local 실행 방법 초안이 있다.
- [ ] PR에서 최소 test 또는 build를 확인할 수 있다.
- [ ] 개발 명세서 초안이 Sprint 1 Backlog와 맞게 갱신되었다.
