# AWS SES 이메일 인증 기본 개념

## 1. AWS SES란?

AWS SES는 **Amazon Simple Email Service**의 약자이며, AWS에서 제공하는 이메일 발송 서비스다.

웹 프로젝트에서는 다음과 같은 메일을 보낼 때 사용할 수 있다.

- 회원가입 이메일 인증 메일
- 비밀번호 재설정 메일
- 로그인 알림 메일
- 주문/결제 안내 메일
- 서비스 공지 메일

즉, AWS SES는 웹 서비스에서 필요한 이메일을 실제 사용자에게 발송해주는 역할을 한다.

## 2. 웹 프로젝트에서 말하는 이메일 인증이란?

웹 프로젝트에서 이메일 인증은 보통 **회원가입한 사용자가 실제로 해당 이메일 주소를 소유하고 있는지 확인하는 기능**을 의미한다.

예를 들어 사용자가 아래 이메일로 회원가입했다고 가정한다.

```text
user@example.com
```

서비스는 이 이메일이 실제 사용자의 이메일인지 확인해야 한다.

이를 위해 서버는 인증 링크가 포함된 이메일을 보내고, 사용자가 그 링크를 클릭하면 이메일 인증을 완료 처리한다.

## 3. AWS SES가 담당하는 역할

이메일 인증 기능 전체를 AWS SES가 처리하는 것은 아니다.

AWS SES는 그중에서 **인증 메일을 발송하는 역할**만 담당한다.

| 구분 | 담당 |
| --- | --- |
| 회원가입 처리 | 우리 백엔드 |
| 인증 토큰 생성 | 우리 백엔드 |
| 인증 메일 발송 | AWS SES |
| 인증 링크 클릭 처리 | 우리 백엔드 |
| 이메일 인증 완료 저장 | DB |
| 성공/실패 화면 표시 | 프론트엔드 |

즉, AWS SES는 "이 사용자가 인증되었는지"를 판단하지 않는다.

사용자 인증 여부는 우리 서비스의 백엔드와 DB가 관리하고, SES는 인증 링크가 들어간 메일을 사용자에게 보내는 발송 수단으로 사용된다.

## 4. 전체 동작 흐름

웹 프로젝트에서 이메일 인증은 보통 다음 순서로 동작한다.

```text
1. 사용자가 회원가입을 한다.
2. 백엔드 서버가 사용자 계정을 생성한다.
3. 백엔드 서버가 이메일 인증용 토큰을 생성한다.
4. 백엔드 서버가 인증 링크를 만든다.
5. 백엔드 서버가 AWS SES를 호출해 인증 메일을 발송한다.
6. 사용자가 이메일에서 인증 링크를 클릭한다.
7. 백엔드 서버가 토큰을 검증한다.
8. 검증에 성공하면 DB에 이메일 인증 완료 상태를 저장한다.
```

예시 인증 링크:

```text
https://example.com/verify-email?token=abc123
```

이 흐름에서 AWS SES가 담당하는 부분은 **5번, 인증 메일 발송**이다.

## 5. SES를 사용하기 전에 필요한 설정

AWS SES에서 메일을 보내려면 먼저 발신자로 사용할 이메일 주소 또는 도메인을 인증해야 한다.

### 이메일 주소 인증

특정 이메일 주소 하나만 발신자로 사용할 때 사용한다.

예:

```text
noreply@example.com
```

이 경우 `noreply@example.com` 주소로만 메일을 보낼 수 있다.

### 도메인 인증

운영 환경에서는 보통 도메인 인증을 사용한다.

예:

```text
example.com
```

도메인을 인증하면 같은 도메인의 여러 발신 주소를 사용할 수 있다.

```text
noreply@example.com
support@example.com
auth@example.com
```

그래서 실제 서비스에서는 개별 이메일 주소 인증보다 도메인 인증이 더 일반적이다.

## 6. DKIM이란?

DKIM은 이메일이 해당 도메인에서 정상적으로 발송된 것이 맞는지 확인하는 이메일 인증 방식이다.

AWS SES에서 도메인을 인증하면 SES가 DNS에 추가할 DKIM 레코드를 제공한다.

개발자는 이 값을 도메인의 DNS 설정에 추가해야 한다.

DKIM을 설정하면 다음과 같은 장점이 있다.

- 수신 메일 서버가 발신 도메인을 신뢰하기 쉬워진다.
- 메일이 스팸으로 분류될 가능성을 줄일 수 있다.
- 운영 환경에서 이메일 발송 신뢰도를 높일 수 있다.

## 7. Sandbox란?

AWS SES를 처음 사용할 때 계정은 기본적으로 **Sandbox** 상태다.

Sandbox는 테스트용 제한 환경이다.

Sandbox 상태에서는 다음 제한이 있다.

| 항목 | 제한 |
| --- | --- |
| 수신자 | 인증된 이메일 주소 또는 도메인에만 발송 가능 |
| 발송량 | 24시간당 최대 200건 |
| 발송 속도 | 초당 최대 1건 |

실제 서비스 사용자에게 이메일 인증 메일을 보내려면 AWS SES의 **Production access**를 요청해야 한다.

Production access가 승인되면 인증되지 않은 일반 사용자 이메일 주소에도 메일을 보낼 수 있다.

단, 발신자로 사용하는 이메일 주소나 도메인은 여전히 SES에서 인증되어 있어야 한다.

## 8. 백엔드에서 SES를 사용하는 방식

백엔드 서버는 AWS SDK 또는 SES API를 사용해 이메일을 발송한다.

백엔드가 SES에 전달하는 주요 정보는 다음과 같다.

| 항목 | 예시 |
| --- | --- |
| 발신자 | `noreply@example.com` |
| 수신자 | `user@example.com` |
| 제목 | `이메일 주소를 인증해주세요` |
| 본문 | 인증 링크가 포함된 HTML 또는 텍스트 |

예시 메일:

```text
제목: 이메일 주소를 인증해주세요

안녕하세요.

회원가입을 완료하려면 아래 링크를 클릭해 이메일 주소를 인증해주세요.

https://example.com/verify-email?token=abc123

이 링크는 일정 시간 동안만 유효합니다.
본인이 요청하지 않았다면 이 메일을 무시해주세요.
```

## 9. SES가 하지 않는 일

AWS SES는 이메일 발송 서비스이므로 다음 작업은 직접 처리하지 않는다.

- 회원가입 처리
- 사용자 계정 생성
- 인증 토큰 생성
- 인증 링크 검증
- 이메일 인증 완료 상태 저장
- 인증 링크 만료 처리
- 인증 성공/실패 화면 제공

이 작업들은 모두 우리 웹 프로젝트의 백엔드, DB, 프론트엔드에서 구현해야 한다.

## 10. 웹 프로젝트에서 필요한 구성

이메일 인증 기능을 구현하려면 보통 다음 구성이 필요하다.

```text
AWS SES
- 발신 이메일 또는 도메인 인증
- DKIM 설정
- Production access 승인

Backend
- 회원가입 API
- 인증 토큰 생성
- 인증 메일 발송 로직
- 인증 링크 검증 API
- 인증 메일 재발송 API

Database
- 사용자 이메일
- 이메일 인증 여부
- 인증 토큰 또는 토큰 해시
- 토큰 만료 시간

Frontend
- 회원가입 완료 후 이메일 확인 안내 화면
- 이메일 인증 성공 화면
- 이메일 인증 실패 또는 만료 화면
```

## 11. 정리

웹 프로젝트에서 이메일 인증을 위해 AWS SES를 사용한다는 것은, **사용자에게 인증 메일을 보내기 위해 SES를 메일 발송 서비스로 사용한다**는 의미다.

AWS SES는 인증 메일을 발송하는 역할만 담당한다.

사용자의 이메일 인증 상태를 판단하고 저장하는 일은 우리 서비스의 백엔드와 DB에서 처리한다.

운영 환경에서는 다음 설정이 중요하다.

- SES 발신 도메인 인증
- DKIM DNS 설정
- Sandbox 해제
- Production access 승인
- 백엔드의 인증 토큰 생성 및 검증 로직
