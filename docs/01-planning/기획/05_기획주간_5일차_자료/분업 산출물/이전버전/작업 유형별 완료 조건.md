# 작업 유형별 완료 조건

## 1. 목적

이 문서는 Backend, Frontend, DB, 문서, PR 작업의 Definition of Done을 정의한다.

완료 기준은 담당자와 리뷰어가 동일하게 판단할 수 있도록 검증 가능한 조건으로 작성한다. 작업자는 완료 선언 전 해당 작업 유형의 기준을 확인하고, 테스트 결과나 화면 캡처 등 필요한 증빙을 남긴다.

## 2. 공통 완료 기준

모든 작업은 다음 조건을 기본으로 충족해야 한다.

- 요구사항 또는 이슈에 명시된 작업 범위가 반영되었다.
- 정상 케이스와 주요 예외 케이스를 확인했다.
- 관련 테스트, 빌드, 린트 등 프로젝트의 기본 검증을 통과했다.
- 변경 사항이 기존 기능에 미치는 영향을 확인했다.
- 불필요한 디버그 코드, 임시 로그, 주석 처리된 코드가 제거되었다.
- 보안, 권한, 개인정보, 데이터 정합성에 영향을 주는 부분을 검토했다.
- 완료 여부를 재확인할 수 있는 증빙이 PR 또는 작업 기록에 남아 있다.

## 3. Backend 완료 기준

Backend 작업은 API, 서버 로직, 인증, 권한, 배치, 외부 연동 변경을 포함한다.

- API 요청과 응답이 정의된 스펙과 일치한다.
- 정상 응답과 실패 응답의 상태 코드, 메시지, 응답 형식이 적절하다.
- 필수값 누락, 잘못된 입력값, 존재하지 않는 리소스, 권한 부족 케이스를 확인했다.
- 인증 또는 권한이 필요한 기능은 접근 제어가 올바르게 동작한다.
- 핵심 비즈니스 로직에 대한 단위 테스트 또는 통합 테스트가 작성되었고 통과했다.
- DB 저장, 수정, 삭제가 있는 경우 트랜잭션과 데이터 정합성이 검토되었다.
- 외부 API, 메시지 큐, 캐시 등 외부 의존성이 있는 경우 실패 시나리오를 확인했다.
- 로그는 장애 분석에 필요한 정보를 포함하되 민감 정보를 노출하지 않는다.
- 환경 변수, 설정값, 배포 순서, 운영 영향이 필요한 경우 문서화되었다.

## 4. Frontend 완료 기준

Frontend 작업은 화면, 컴포넌트, 사용자 플로우, 상태 관리, API 연동 변경을 포함한다.

- 요구사항에 맞는 화면과 기능이 구현되었다.
- 주요 사용자 플로우가 브라우저에서 끝까지 정상 동작한다.
- API 성공, 실패, 로딩, 빈 상태가 화면에서 적절히 처리된다.
- 입력 폼이 있는 경우 필수값, 형식, 길이, 오류 메시지를 확인했다.
- 저장, 수정, 삭제 등 주요 액션 후 화면 상태가 최신 데이터로 갱신된다.
- 중복 클릭, 새로고침, 뒤로 가기 등 일반적인 사용 상황에서 문제가 없다.
- 모바일, 태블릿, 데스크톱 등 필요한 화면 크기에서 레이아웃이 깨지지 않는다.
- 버튼, 링크, 입력 요소의 접근성과 키보드 조작 가능성을 확인했다.
- 화면 변경이 있는 경우 스크린샷 또는 녹화 자료가 남아 있다.

## 5. DB 완료 기준

DB 작업은 스키마 변경, 마이그레이션, 데이터 보정, 인덱스, 쿼리 변경을 포함한다.

- 스키마 변경이 데이터 모델과 요구사항에 맞게 반영되었다.
- 마이그레이션 스크립트가 작성되었고 로컬 또는 테스트 환경에서 적용을 확인했다.
- 컬럼 타입, 기본값, null 허용 여부, unique 조건, foreign key 등 제약 조건을 검토했다.
- 기존 데이터에 영향을 주는 경우 데이터 보정 기준과 검증 쿼리가 준비되었다.
- 데이터 삭제 또는 대량 수정이 있는 경우 대상 범위와 실행 전후 확인 방법이 명확하다.
- 성능 영향이 있는 쿼리는 인덱스와 실행 계획을 검토했다.
- 애플리케이션 코드와 DB 변경의 배포 순서가 정리되었다.
- 롤백 또는 복구가 필요한 경우 방법이 기록되어 있다.

## 6. 문서 완료 기준

문서 작업은 기술 문서, API 문서, 운영 가이드, 사용자 가이드, 정책 문서를 포함한다.

- 문서의 목적, 대상 독자, 적용 범위가 명확하다.
- 실제 구현, 운영 절차, 정책과 문서 내용이 일치한다.
- 사용자가 문서만 보고 필요한 작업을 수행하거나 검증할 수 있다.
- 명령어, URL, 설정값, 예시가 실제로 유효한지 확인했다.
- 링크, 이미지, 표, 코드 블록이 정상적으로 표시된다.
- 오래된 정보, 중복 내용, 모호한 표현이 제거되었다.
- 미확정 항목이 있는 경우 담당자와 후속 조치가 표시되어 있다.
- 관련 문서가 있는 경우 함께 갱신되었다.

## 7. PR 완료 기준

PR은 변경 내용뿐 아니라 검증 결과와 영향 범위까지 리뷰어가 이해할 수 있어야 완료로 본다.

- PR 제목과 설명이 변경 목적을 명확히 설명한다.
- 주요 변경 사항, 변경 범위, 제외 범위가 정리되어 있다.
- 관련 이슈, 요구사항, 디자인, 문서 링크가 연결되어 있다.
- 테스트 방법과 실행 결과가 PR에 기록되어 있다.
- 화면 변경이 있는 경우 스크린샷 또는 녹화 자료가 첨부되어 있다.
- API 변경이 있는 경우 요청과 응답 예시 또는 문서 링크가 포함되어 있다.
- DB 변경이 있는 경우 마이그레이션 결과와 롤백 또는 복구 방법이 포함되어 있다.
- CI, lint, test, build 등 필수 검증이 모두 통과했다.
- 리뷰 코멘트가 반영되었거나 반영하지 않은 사유가 답변되어 있다.

## 8. 필수 증빙 요약

| 작업 유형 | 필수 증빙 |
| --- | --- |
| Backend | 테스트 결과, API 요청/응답 예시, 서버 로그 또는 검증 결과 |
| Frontend | 화면 스크린샷 또는 녹화, 확인한 브라우저와 화면 크기, 테스트 결과 |
| DB | 마이그레이션 결과, 검증 쿼리, 데이터 변경 전후 확인 결과 |
| 문서 | 문서 링크, 리뷰 결과, 확인한 절차 또는 명령어 |
| PR | 변경 요약, 테스트 결과, 영향 범위, 리뷰 반영 내역 |

## 9. 완료 판정 기준

작업은 다음 조건을 모두 만족할 때 완료로 판정한다.

- 작업 유형별 완료 기준을 확인했다.
- 관련 테스트 또는 수동 검증을 수행했다.
- 검증 결과가 재확인 가능한 형태로 남아 있다.
- 미충족 항목이 있는 경우 사유와 후속 조치가 명확하다.
- 리뷰어가 동일한 기준으로 완료 여부를 판단할 수 있다.

## 10. 완료로 보지 않는 경우

다음 중 하나라도 해당하면 완료로 보지 않는다.

- 구현은 되었지만 검증 결과가 없다.
- 정상 케이스만 확인하고 주요 예외 케이스를 확인하지 않았다.
- 테스트 또는 빌드 실패가 남아 있고 사유가 설명되지 않았다.
- 화면 변경이 있는데 화면 증빙이 없다.
- DB 변경이 있는데 마이그레이션 결과나 복구 방법이 없다.
- PR 설명만으로 변경 이유와 영향 범위를 이해하기 어렵다.
- 미완료 항목이 후속 작업으로 추적되지 않는다.
